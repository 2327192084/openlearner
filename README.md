# Open Learner

> 把教材、课件、课堂笔记变成**能复习的题、能讲清的骨架、能刷的错题本** ——
> 而且每一条内容都能点回原文那一页。

一个纯本地的备考工作台。数据全部存在你自己的电脑里，AI 用你自己接的模型，
不需要注册账号，也不上传任何东西到别人的服务器。
Windows 桌面版（Electron）与浏览器版共用同一份代码。

**当前版本 0.40.0** · [⬇️ 下载 Windows 安装包](https://github.com/2327192084/openlearner/releases/download/v0.40/OpenLeaner-0.40.0-setup.exe) · [全部 Release](https://github.com/2327192084/openlearner/releases) · [开发文档](DEVELOPMENT.md)

**安装**：双击安装包即可 —— 装到你自己的用户目录（`%LOCALAPPDATA%\Programs\OpenLeaner`），
全程不弹 UAC、不写系统目录；卸载不会删除学习库（数据在 `%APPDATA%\OpenLeaner`）。
不需要注册任何账号；AI 功能在「设置」里填入你自己的模型接口（任何 OpenAI 兼容服务均可）。

## 它能做什么（功能总览）

| 模块 | 你能做的事 |
|---|---|
| 📚 **资料库** | 导入 PDF / Word / PPT / Markdown / 图片；扫描件接 MinerU 转正文；分片解析大书；逐页看 PPT 原件 |
| 🔍 **全文搜索** | 一次搜遍全部资料，命中按书汇总、同页归并，点击跳到原文那句话 |
| 🧠 **知识骨架** | AI 从资料提取知识点（带原文页码角标），整理成章节树，自检「能不能讲清楚」 |
| 📝 **出题刷题** | 单选/多选/判断/填空/问答六种题型，草稿先审后发，错题自动进错题本 |
| 🃏 **闪卡** | 三大类 + 自定义文件夹 + 标签 + `==挖空==` 翻面；与 Obsidian 双向导入导出 |
| 📅 **复习计划** | 记忆曲线排复习、每日安排、模拟考试限时整卷、专注计时 |
| 📊 **学习地图** | 题库按资料与章节摊开，看清哪块练得少、哪块最容易错 |
| 🖥️ **AI 演示文稿** | 从资料原文生成可编辑 .pptx（六套配色，预览导出同一主题） |
| 🔌 **AI 接入** | 任何 OpenAI 兼容接口；8 家预设；一键拉取可用模型列表；用量按天记账 |

## 适合谁用

- **备考的人**：教材 + 课件 + 真题散落各处，需要一个地方把它们串成「资料 → 知识点 → 题 → 错题本 → 复习计划」的闭环
- **不想把学习数据交出去的人**：全部数据存本机 IndexedDB，不注册账号、不上传内容；AI 走你自己接的模型接口
- **用 Obsidian 做笔记的人**：闪卡可以导出成 Obsidian Callout 版式，装上 Spaced Repetition 插件直接在库里翻卡复习；写好的卡也能导回来

## 它解决什么问题

备考最耗时的不是「看不懂」，是**把一堆资料整理成能复习的东西**：

- 六百页的教材，考前要过一遍 → 得自己做提纲
- 看懂了不等于记住了 → 得自己出题、自己批改
- 做错的题过两周又错一遍 → 没有错题本，也不知道自己弱在哪
- 做的笔记过两周就找不到出处 → 想回头翻原文，忘了在哪页

Open Learner 把这条链路串起来，但守住一件事：**AI 生成的内容必须能追溯回原文**。

## 核心特性

### 跨资料全文搜索：一次翻遍全部书

真实场景是「我记得在哪本书看过这个概念」——而单本搜索帮不上忙。

侧栏「课程准备与管理 → 搜索」是独立一页：
- 顶部大搜索框，回车即搜（全库 1000+ 段落、几十万字，输入即搜会卡）
- **命中概览**：先给「共 N 处，分布在 M 份资料」，再给每本书一条分布条
- **同页归并**：一页里出现多处只占一行（标「本页 N 处」），
  否则目录页会把正文结果全压到下面；可一键切回「按处列出」
- **搜索历史**：一排胶囊标签，存本地（不是学习数据，不进备份）
- 点任意一条 → 跳到原文**那句话**并标橙光（临时，翻页即消失）

截断如实告知：搜「的」这类高频词时全库可能几千处，
列表只列前 500 处，界面会明说「共 2365 处，列表只列前 500 处」
——宁可承认没全列出来，也不能让用户以为搜遍了全库。

### 每条内容都能点回原文

这不是装饰性功能，是整个设计的支点。

知识点、题目、复习卡片都带原文定位。点角标直接跳到教材那一页、那一句。
导出成 .pptx 时，末尾会生成一页「资料来源」逐条列出（可关闭）。

实现上有一条硬规则：**AI 只负责说「讲什么」，绝不让它给页码**。
模型看到的是文本，它看不到分页，让它说页码只会得到编造的结果。所以链路是：

```
要点 → 角标序号 → 引用记录 → 原文段落 id → 段落的真实页码
```

页码在解析器切分时确定，全程继承，不做二次推算。

### 标注偏移不是 DOM 偏移 —— 这两套坐标系已经统一

用户标注锚在**原文偏移**（`SourceSegment.text` 的字符位置），
但正文渲染成 DOM 之后字符数会变：标题的 `## ` 被吃掉、`$v_{s}$` 经 KaTeX 变成 `vs`、
插图把一整段切成多段。

实测第 1 页：原文 1048 字，渲染后 `.reader-md` 的 DOM 文本只有 606 字，**差 442 字**。
把原文偏移直接当 DOM 偏移用，标注必然画偏。

修法是渲染时把每个片段的原文坐标写进 DOM（`data-raw` / `data-raw-len`），
换算按片段自带坐标做，不做全局累加。见 `src/v2/ui/dom-text-map.ts`。

参考 [W3C Web Annotation TextPositionSelector](https://www.w3.org/TR/annotation-model/#text-position-selector)
与 [`dom-anchor-text-position`](https://www.npmjs.com/package/dom-anchor-text-position) ——
本项目的关键差别在于 DOM 文本被 Markdown / KaTeX 改写过，
所以偏移必须**标注**在 DOM 上，不能运行时累计。

### PDF 解析：完整解析 / 分片解析

扫描版或文字层损坏的 PDF，接本机 [MinerU](https://github.com/opendatalab/MinerU) 转成正文。

- **完整解析**：整本一次转完（大书要几十分钟）
- **分片解析**：只转指定页范围，几十秒就能先看某一章
- **按页合并**：写回时新页覆盖同页、**没写到的页原样保留**，可以分几次凑齐整本

MinerU 服务没在跑时由程序自动启动，不需要用户敲命令。

⚠️ 两条踩过的坑，写在代码注释里也写在这里：

- **补位空页必须跳过**。分片解析 3-4 页时输出里只有两个页标记，
  但 `page N of 36` 说明整本 36 页 —— 解析器会补出 34 个空页让页码对齐。
  这些占位在合并时**绝不能覆盖**已有正文，否则解析 3-4 页会把之前 1-2 页的正文清空。
- **分片解析不能清掉别的页的插图**。取图那一步原先是「按资料全清再写」，
  于是每次分片解析都把整本的图删一遍，只留这次那几页的。
  现在按 `coveredPages` 只清本次覆盖的页。见 `src/core/mineru/images.ts`。

### 文档格式与解析边界

| 格式 | 处理方式 |
|---|---|
| PDF（有文字层） | pdfjs-dist 直接抽文字，逐页分段 |
| PDF / 图片（扫描件） | MinerU 转正文，可分片、可按页合并 |
| Word / Markdown / HTML / TXT | 直接解析文字，**不送 MinerU** |
| PPTX | 逐页抽文字与备注；同时保存原件，可在阅读器里「看原图」逐页浏览幻灯片 |

Word 这类本来就带文字的格式**不该**当扫描件送去 OCR ——
这个 bug 曾把一份 2 页的 docx 写成 36 段。现在有格式守卫。

### PPTX 看原件：文字用来复习，原件用来对照

PPT 导入后既抽文字（总结知识点、出题用），也把原件字节存进库。
阅读器右上角有「看原图 / 看文字」切换：原图模式用 `pptx-wasm`
（约 1 MB 的纯前端渲染库，中文实测清晰）把幻灯片逐页画出来，
和 PDF 的看原图体验一致。

**注意**：看原件功能只对**新导入**的 PPT 生效 —— 旧资料导入时没存原件字节，
需要删掉重新导入。文字、题目、闪卡链路完全不受影响。

### 阅读器全屏沉浸查看

阅读器右上角「全屏」按钮进入真全屏 + 沉浸布局：侧栏、顶栏、右侧面板、
搜索框全部收起，正文放大；再点按钮或按 `Esc` 退出。
「看原图」模式下同样能全屏，幻灯片铺满整屏。

### 闪卡：三大类 + 文件夹 + 标签，可导入导出到 Obsidian

闪卡不是「指向知识点的引用」，而是**独立的一份内容**：从知识点或错题挑出来后，
原件删了、改了，卡片都不受影响。

- 五种建卡方式：从知识点挑 / 从错题挑 / **写闪卡**（空白手写）/ 让 AI 写 / **导入 Obsidian Markdown**
- 写完再定归属：每张卡可归入「知识点 / 错题 / 记忆」三栏，随时能改，不用重写
- **自定义文件夹**：一卡一个文件夹，像目录一样自组织；多选几张卡（组头可整组勾）
  一步归入；删整个文件夹只清归属，卡一张不丢
- **标签筛选**：标签 chip 按卡去重计数；标签被删光后筛选自动解除，
  不会卡死在「没有符合条件的卡」
- **挖空翻面**：正面写 `==答案==`，复习时点一下显形 —— 装了
  [Obsidian Spaced Repetition](https://github.com/st3v3nmw/obsidian-spaced-repetition)
  插件后在 Obsidian 里同样能翻
- **导入/导出双向**：导出按标签分卡组、支持 Callout 与多行问答两种版式、
  可选双向卡；导入认用户 Obsidian 库的两种真实版式（平铺 callout 与嵌套
  `[!answer]`），按正面判重、报告跳过几张
- 批量删除（整组/整个文件夹）进回收站，30 天内可还原

AI 写的卡**先展示，确认后才入库** —— 模型偶尔会写出偏离素材的内容。

### 跳走再回来，活儿还在

做题做到一半去看原文、翻两页资料、再点侧栏回来 —— 题号、已选的选项、
考试的倒计时都还在原处。

实现上是把「有活儿在进行」的页面留在 DOM 里，只把非当前页藏起来
（`display: none` + `inert`），当前页用 `display: contents` 不生成盒子，
保证包一层之后布局与包之前一模一样。哪些页面算「有活儿」由**页面自己上报**，
不是靠一张白名单猜 —— 打开过但什么都没做的页面不会挂上一个假的「继续」入口。

### 模型后端：填入 API Key 后拉到真实模型列表

「模型名」不再是需要自己背下来的死值：点「拉取列表」就真的
`GET <base>/models`，把这把 Key 能用的模型列出来（带上下文长度、是否可看图），
点一个就填进去。手填仍然保留 —— 有的服务商要求填接入点 ID，也有中转站不兼容。

### 出题、刷题与错题本

- 从资料出题：单选 / 多选 / 判断 / 填空 / 问答 / 闪卡
- 出题前能看到大概要花多少 token
- 草稿先审后发：生成的题进草稿区，检查过再发布
- 错题收进「错题与待巩固」：看错几次、错在哪天，能直接去练
- 学习地图：把题库按资料与章节摊开，看清哪一块练得少、哪一块最容易错

### 复习与学习计划

- **每天**：今天的安排、资料进度、最近在练的题
- **复习巩固**：按记忆曲线安排该复习的题
- **模拟考试**：限时整卷，交卷后统一批改，成绩单独记录
- **知识骨架**：对着章节清单自检「这个知识点我能不能讲清楚」
- **专注**：选一段时间只做一件事，记今天专注了多久

### 从资料原文生成 PPT，不是从知识点二次加工

选资料、可选页码范围 → AI 读原文 → 出大纲。

不填额外要求时走**固定版式**（封面 → 章节页 → 要点页 → 总结页），
同样的资料跑两次结构一致。填了要求就让模型自己组织。

六套配色（商务蓝 / 学术论文 / 极简灰 / 墨绿 / 深色 / 暖灰）+ 自定义主色。
**预览与导出共用同一份主题** —— 两边各写一套会导致「预览深蓝、导出黑色」，
而这类缺陷所有自动测试都会通过，只有真打开文件才看得见。

导出用 pptxgenjs 产出真实 OOXML，可编辑，不是图片拼贴。

### 删除有回收站

删掉的资料、知识点、题组先进回收站，30 天后彻底删除，期间可以还原。
快过期时启动会提醒。大二进制（原始 PDF、插图）不进回收站，
并如实标注「还原后需要重新导入」。

### 重名资料自动消歧

同一次导入做了两次会产生两份同名资料，列表里一模一样，已导致过误操作。

现在**只给重名的那几份**加「（1）」「（2）」编号，不重名的保持干净；
编号按 `createdAt` 升序，所以编号稳定 —— 排序一变编号就跟着变的话，那比不加更糟。
三个入口（资料页 / 文档解析页 / 整理知识点）共用同一套。

## 技术栈

| | |
|---|---|
| 前端 | React 19 + TypeScript + Vite（纯前端 SPA） |
| 桌面 | Electron 38（同一份代码，浏览器 / 桌面都能跑） |
| 数据 | IndexedDB —— DB v12 / schema 19 / 27 个分区（22 个进备份） |
| 文档处理 | pdfjs-dist / pptx-wasm / JSZip / fast-xml-parser / MinerU（外部依赖，可外挂） |
| PPT 导出 | pptxgenjs |
| AI | 任何 OpenAI 兼容接口 |

**规模**：源码 104,000+ 行，单元测试 183 个文件 / 3,693 条，验收脚本 95 个。

### AI 接入

不需要特定服务商，任何提供 OpenAI 兼容 `/chat/completions` 的都能填：

```ts
{ baseUrl: 'https://api.deepseek.com', model: 'deepseek-chat', apiKey: 'sk-...' }
```

内置 8 家预设：DeepSeek、月之暗面 Kimi、智谱 GLM、阿里通义千问、
硅基流动、火山方舟（豆包）、OpenAI、自定义 / 中转站 / agent 平台。

**模型发现**：接兼容端点最麻烦的不是填 Key，是填模型名 ——
用户不知道对方叫 `glm-4-flash` 还是 `GLM-4-Flash`，填错的表现是「模型不存在」，
看起来像 Key 有问题。所以表单提供「获取模型列表」，点选即可；拿不到也不拦路。

**用量统计**：按天、按后端、按用途分别记账。
有一处刻意的边界：**服务端没返回 token 就不记，不猜一个数字** ——
残缺的账单比空账单更危险，用户会以为「这就是我花掉的」。

## 快速开始

```bash
npm install
npm run dev              # 浏览器开发模式
npm run electron:dev     # 桌面端开发模式
```

详细命令、验收复跑、打包说明见 [DEVELOPMENT.md](DEVELOPMENT.md)。

### 从源码构建 Windows 安装包

```bash
TMP=E:/openleaner/.tmp/buildtmp TEMP=E:/openleaner/.tmp/buildtmp npm run electron:pack
node scripts/build-innosetup.cjs         # Inno Setup 编出 build/OpenLeaner-<版本>-setup.exe
node scripts/update-desktop.cjs          # 只更新已装的桌面版
```

脚本在 `build/installer.iss`。装到用户目录、不弹 UAC、卸载不删学习库
（数据在 `%APPDATA%\OpenLeaner`）。
（v0.40 之前用 NSIS，脚本保留在 `build/installer.nsi` 作为回退，不再被流程调用。）

## 验证

```bash
npx tsc -b          # 类型检查，0 错误
npx vitest run      # 183 files / 3693 passed（6 跳过）
npx vite build      # 构建
```

端到端验收脚本在 `scripts/` 下，共 95 个。它们有一个共同点：
**验产物，不采信自我报告**。

比如 PPT 验收会把导出文件真的下载到磁盘、解压、检查 XML 里有没有文本 run；
解析验收真跑 MinerU；标注验收读出 CSS Highlight 实际覆盖的文字。

**踩过的教训**：曾经「单元测试全过」但功能是坏的 ——
正文合并逻辑正确，但真实链路上解析器补出的空占位把正文清空了。
还有一次是反向验证才暴露的：验证脚本在异步取图完成前就读库，
修复前后都报「通过」。**只有用修复前的代码反向跑一遍，才能证明脚本真能抓到 bug。**
