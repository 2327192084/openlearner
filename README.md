# OpenLeaner

> ⚠️ **测试版（Pre-release）**
>
> 这个仓库持续在改，接口与数据格式仍可能变。当前状态：
> P0–P6 功能已跑通、886 条测试全绿，但**没有做过完整的用户测试**，
> 也没有稳定版发布。请只当学习参考用，不要拿它存你唯一的备考资料。

> 把教材、课件、课堂笔记变成**可复习的 PPT 和可刷的习题集** ——
> 而且每一条内容都能点回原文那一页。

一个纯本地的学习备考工具。数据全部存在你自己的浏览器里，AI 用你自己接的模型，
不需要注册账号，也不上传任何东西到别人的服务器。

开发命令、验收复跑方式、打包注意事项见 [DEVELOPMENT.md](DEVELOPMENT.md)。

---

## 它解决什么问题

备考时最耗时的不是「看不懂」，是**把一堆资料整理成能复习的东西**：

- 六百页的教材，考前要过一遍 → 得自己做提纲
- 看懂了不等于记住了 → 得自己出题、自己批改
- 做的笔记过两周就找不到出处 → 想回头翻原文，忘了在哪页

OpenLeaner 把这条链路自动化，但守住一件事：**AI 生成的内容必须能追溯回原文**。

## 核心特性

### 每条内容都能点回原文

这不是装饰性功能，是整个设计的支点。

PPT 里每条要点右边都有一个 `[3]` 这样的角标，点它直接跳到教材第 3 页；
导出成 .pptx 时，末尾会生成一页「资料来源」逐条列出（可关闭）。

实现上有一条硬规则：**AI 只负责说「讲什么」，绝不让它给页码**。
模型看到的是文本，它看不到分页，让它说页码只会得到编造的结果。
所以链路是：

```
要点 → 角标序号 → 引用记录 → 原文段落 id → 段落的真实页码
```

页码在解析器切分时确定，全程继承，不做二次推算。

### 从资料原文生成 PPT，不是从知识点二次加工

选资料、可选页码范围 → AI 读原文 → 出大纲。

不填额外要求时走**固定版式**（封面 → 章节页 → 要点页 → 总结页），
同样的资料跑两次结构一致。填了要求就让模型自己组织。

### 六套配色 + 自定义主色

商务蓝 / 学术论文 / 极简灰 / 墨绿 / 深色 / 暖灰。

选色守两条：正文对比度够（投影到教室墙上仍读得清），角标色不与主色撞。
自定义主色时界面会算对比度并提示 —— 但**只警告不拦截**，
因为有人就是要做低对比设计，硬拦只会让人恼火。

**预览与导出共用同一份主题**。这不是洁癖：两边各写一套会导致
「预览深蓝、导出黑色」，而这类缺陷所有自动测试都会通过，只有真打开文件才看得见。

### 拖拽排版

预览下方可以直接在页面上摆图片、加文本框，拖动移动、拉角缩放、方向键微调。

坐标存的是 **0~1 的比例**而不是像素 —— 存像素的话换个屏幕尺寸再打开，图就跑位了。

### 扫描件也能用

扫描版 PDF 没有文字层，通常只能翻看。接上多模态模型后可以逐页识别：

页面渲染成图片 → 交给视觉模型 → 结果写回分段 → 从此能搜索、能出题、能做 PPT。

按页计费，所以提供「只识别第 1 页先试效果」，并且随时可以停。

## 技术栈

| | |
|---|---|
| 前端 | React 19 + TypeScript + Vite（纯前端 SPA） |
| 桌面 | Electron 38（同一份代码，浏览器/桌面都能跑） |
| 数据 | IndexedDB（本地存储，凭据单独分区，永不进备份） |
| 文档处理 | pdfjs-dist / JSZip / fast-xml-parser |
| PPT 导出 | pptxgenjs（产出真实 OOXML，可编辑，不是图片拼贴） |
| AI | 任何 OpenAI 兼容接口（DeepSeek / Kimi / 智谱 / 通义 / 中转站 / 本地代理） |

**规模**：源码 42,000+ 行，单元测试 886 条，端到端验收脚本 14 个。

## AI 接入

不需要特定的服务商。任何提供 OpenAI 兼容 `/chat/completions` 的服务都能填：

```ts
{ baseUrl: 'https://api.deepseek.com', model: 'deepseek-chat', apiKey: 'sk-...' }
```

内置 8 家预设（DeepSeek、Kimi、智谱、通义、硅基流动、火山方舟、OpenAI、本地代理），
也可以用「自定义」接中转站或 agent 平台。

### 模型发现

接任何兼容端点时最难的不是填 Key，是**填模型名** —— 用户不知道对方叫
`glm-4-flash` 还是 `GLM-4-Flash`，填错的表现是「模型不存在」，看起来像 Key 有问题。

所以表单提供「获取模型列表」，问一下端点它有哪些模型，点选即可。
拿不到列表也不拦路：很多自建端点没有 `/models`，直接手填就行。

### 用量统计

按天、按后端、按用途（整理 / 出题 / PPT）分别记账。

有一处刻意的边界：**服务端没返回 token 就不记，不猜一个数字**。
残缺的账单比空账单更危险 —— 用户会以为「这就是我花掉的」。

## 验证

```bash
npx tsc -b          # 类型检查
npx vitest run      # 886 条单元测试
npx vite build      # 构建
```

端到端验收（需要先构建并起 preview）：

```bash
npx vite preview --port 4173 &
node scripts/verify-p4.cjs    # 学习 PPT：真实下载 .pptx 并解压检查
node scripts/verify-p5.cjs    # 多后端：拦截请求验证真的打到对应服务商
node scripts/verify-p6.cjs    # OCR：验证请求体真的带图片、结果写回分段
```

这些脚本有一个共同点：**验产物，不采信自我报告**。
比如 PPT 验收会把导出文件真的下载到磁盘、解压、检查 XML 里有没有文本 run；
OCR 验收会拦截请求体确认里面真的有 `image_url`。

## 一些取舍（写在代码注释里，也写在这里）

- **不做「假开关」**。勾了没反应的能力选项比没有更糟。已经因为这条摘掉了
  三个东西：联网检索勾选框、agent-app 接入类型、本地 OCR 死标签。
- **宁可少给，也不给假角标**。段落缺页码时，要点照常生成但没有角标。
- **失败必须说清下一步**。所有错误对象都带 `hint`，界面不允许只显示「失败」。
- **迁移只做加法**。旧备份缺的字段补默认值，绝不编造数据；判断不了就留空并如实标注。
- **不伪造统计**。缺数据就显示「未配置」，不把未知价格默认当成免费。
