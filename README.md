# OpenLeaner

> 把教材、课件、课堂笔记变成**能复习的题、能讲清的骨架、能刷的错题本** ——
> 而且每一条内容都能点回原文那一页。

一个纯本地的备考工作台。数据全部存在你自己的电脑里，AI 用你自己接的模型，
不需要注册账号，也不上传任何东西到别人的服务器。
Windows 桌面版（Electron）与浏览器版共用同一份代码。

**当前版本 0.2.0** · [下载安装包](https://github.com/2327192084/openlearner/releases/latest) · [开发文档](DEVELOPMENT.md)

---

## 它解决什么问题

备考最耗时的不是「看不懂」，是**把一堆资料整理成能复习的东西**：

- 六百页的教材，考前要过一遍 → 得自己做提纲
- 看懂了不等于记住了 → 得自己出题、自己批改
- 做错的题过两周又错一遍 → 没有错题本，也不知道自己弱在哪
- 做的笔记过两周就找不到出处 → 想回头翻原文，忘了在哪页

OpenLeaner 把这条链路串起来，但守住一件事：**AI 生成的内容必须能追溯回原文**。

## 核心特性

### 每条内容都能点回原文

这不是装饰性功能，是整个设计的支点。

知识点、题目、复习卡片都带原文定位。点角标直接跳到教材那一页、那一句。
导出成 .pptx 时，末尾会生成一页「资料来源」逐条列出（可关闭）。

实现上有一条硬规则：**AI 只负责说「讲什么」，绝不让它给页码**。
模型看到的是文本，它看不到分页，让它说页码只会得到编造的结果。所以链路是：

```
要点 → 角标序号 → 引用记录 → 原文段落 id → 段落的真实页码
```

页码在解析器切分时确定，全程继承，不做二次推算。

### 标注偏移不是 DOM 偏移 —— 这两套坐标系已经统一

用户标注锚在**原文偏移**（`SourceSegment.text` 的字符位置），
但正文渲染成 DOM 之后字符数会变：标题的 `## ` 被吃掉、`$v_{s}$` 经 KaTeX 变成 `vs`、
插图把一整段切成多段。

实测第 1 页：原文 1048 字，渲染后 `.reader-md` 的 DOM 文本只有 606 字，**差 442 字**。
把原文偏移直接当 DOM 偏移用，标注必然画偏。

修法是渲染时把每个片段的原文坐标写进 DOM（`data-raw` / `data-raw-len`），
换算按片段自带坐标做，不做全局累加。见 `src/v2/ui/dom-text-map.ts`。

参考 [W3C Web Annotation TextPositionSelector](https://www.w3.org/TR/annotation-model/#text-position-selector)
与 [`dom-anchor-text-position`](https://www.npmjs.com/package/dom-anchor-text-position) ——
本项目的关键差别在于 DOM 文本被 Markdown / KaTeX 改写过，
所以偏移必须**标注**在 DOM 上，不能运行时累计。

### PDF 解析：完整解析 / 分片解析

扫描版或文字层损坏的 PDF，接本机 [MinerU](https://github.com/opendatalab/MinerU) 转成正文。

- **完整解析**：整本一次转完（大书要几十分钟）
- **分片解析**：只转指定页范围，几十秒就能先看某一章
- **按页合并**：写回时新页覆盖同页、**没写到的页原样保留**，可以分几次凑齐整本

MinerU 服务没在跑时由程序自动启动，不需要用户敲命令。

⚠️ 两条踩过的坑，写在代码注释里也写在这里：

- **补位空页必须跳过**。分片解析 3-4 页时输出里只有两个页标记，
  但 `page N of 36` 说明整本 36 页 —— 解析器会补出 34 个空页让页码对齐。
  这些占位在合并时**绝不能覆盖**已有正文，否则解析 3-4 页会把之前 1-2 页的正文清空。
- **分片解析不能清掉别的页的插图**。取图那一步原先是「按资料全清再写」，
  于是每次分片解析都把整本的图删一遍，只留这次那几页的。
  现在按 `coveredPages` 只清本次覆盖的页。见 `src/core/mineru/images.ts`。

### 文档格式与解析边界

| 格式 | 处理方式 |
|---|---|
| PDF（有文字层） | pdfjs-dist 直接抽文字，逐页分段 |
| PDF / 图片（扫描件） | MinerU 转正文，可分片、可按页合并 |
| Word / Markdown / HTML / TXT | 直接解析文字，**不送 MinerU** |
| PPTX | 逐页抽文字与备注 |

Word 这类本来就带文字的格式**不该**当扫描件送去 OCR ——
这个 bug 曾把一份 2 页的 docx 写成 36 段。现在有格式守卫。

### 出题、刷题与错题本

- 从资料出题：单选 / 多选 / 判断 / 填空 / 问答 / 闪卡
- 出题前能看到大概要花多少 token
- 草稿先审后发：生成的题进草稿区，检查过再发布
- 错题收进「错题与待巩固」：看错几次、错在哪天，能直接去练
- 学习地图：把题库按资料与章节摊开，看清哪一块练得少、哪一块最容易错

### 复习与学习计划

- **每天**：今天的安排、资料进度、最近在练的题
- **复习巩固**：按记忆曲线安排该复习的题
- **模拟考试**：限时整卷，交卷后统一批改，成绩单独记录
- **知识骨架**：对着章节清单自检「这个知识点我能不能讲清楚」
- **专注**：选一段时间只做一件事，记今天专注了多久

### 从资料原文生成 PPT，不是从知识点二次加工

选资料、可选页码范围 → AI 读原文 → 出大纲。

不填额外要求时走**固定版式**（封面 → 章节页 → 要点页 → 总结页），
同样的资料跑两次结构一致。填了要求就让模型自己组织。

六套配色（商务蓝 / 学术论文 / 极简灰 / 墨绿 / 深色 / 暖灰）+ 自定义主色。
**预览与导出共用同一份主题** —— 两边各写一套会导致「预览深蓝、导出黑色」，
而这类缺陷所有自动测试都会通过，只有真打开文件才看得见。

导出用 pptxgenjs 产出真实 OOXML，可编辑，不是图片拼贴。

### 删除有回收站

删掉的资料、知识点、题组先进回收站，30 天后彻底删除，期间可以还原。
快过期时启动会提醒。大二进制（原始 PDF、插图）不进回收站，
并如实标注「还原后需要重新导入」。

### 重名资料自动消歧

同一次导入做了两次会产生两份同名资料，列表里一模一样，已导致过误操作。

现在**只给重名的那几份**加「（1）」「（2）」编号，不重名的保持干净；
编号按 `createdAt` 升序，所以编号稳定 —— 排序一变编号就跟着变的话，那比不加更糟。
三个入口（资料页 / 文档解析页 / 整理知识点）共用同一套。

## 技术栈

| | |
|---|---|
| 前端 | React 19 + TypeScript + Vite（纯前端 SPA） |
| 桌面 | Electron 38（同一份代码，浏览器 / 桌面都能跑） |
| 数据 | IndexedDB —— DB v12 / schema 19 / 27 个分区（22 个进备份） |
| 文档处理 | pdfjs-dist / JSZip / fast-xml-parser / MinerU（外部依赖，可外挂） |
| PPT 导出 | pptxgenjs |
| AI | 任何 OpenAI 兼容接口 |

**规模**：源码 104,000+ 行，单元测试 117 个文件 / 2,185 条，验收脚本 89 个。

### AI 接入

不需要特定服务商，任何提供 OpenAI 兼容 `/chat/completions` 的都能填：

```ts
{ baseUrl: 'https://api.deepseek.com', model: 'deepseek-chat', apiKey: 'sk-...' }
```

内置 8 家预设：DeepSeek、月之暗面 Kimi、智谱 GLM、阿里通义千问、
硅基流动、火山方舟（豆包）、OpenAI、自定义 / 中转站 / agent 平台。

**模型发现**：接兼容端点最麻烦的不是填 Key，是填模型名 ——
用户不知道对方叫 `glm-4-flash` 还是 `GLM-4-Flash`，填错的表现是「模型不存在」，
看起来像 Key 有问题。所以表单提供「获取模型列表」，点选即可；拿不到也不拦路。

**用量统计**：按天、按后端、按用途分别记账。
有一处刻意的边界：**服务端没返回 token 就不记，不猜一个数字** ——
残缺的账单比空账单更危险，用户会以为「这就是我花掉的」。

```bash
npx electron-builder --dir
node scripts/update-desktop.cjs          # 只更新已装的桌面版
```

重新生成安装包见 `build/installer.nsi`。

## 验证

```bash
npx tsc -b          # 类型检查，0 错误
npx vitest run      # 117 files / 2185 passed（6 跳过）
npx vite build      # 构建
```

端到端验收脚本在 `scripts/` 下，共 89 个。它们有一个共同点：
**验产物，不采信自我报告**。

比如 PPT 验收会把导出文件真的下载到磁盘、解压、检查 XML 里有没有文本 run；
解析验收真跑 MinerU；标注验收读出 CSS Highlight 实际覆盖的文字。

**踩过的教训**：曾经「单元测试全过」但功能是坏的 ——
正文合并逻辑正确，但真实链路上解析器补出的空占位把正文清空了。
还有一次是反向验证才暴露的：验证脚本在异步取图完成前就读库，
修复前后都报「通过」。**只有用修复前的代码反向跑一遍，才能证明脚本真能抓到 bug。**

## 一些取舍（写在代码注释里，也写在这里）

- **不做「假开关」**。勾了没反应的能力选项比没有更糟。已经摘掉过几个：
  资料页「未分类 更改」、折叠的「PDF 解析」块、「自动保存」开关。
- **宁可少给，也不给假角标**。段落缺页码时，要点照常生成但没有角标。
- **取不到的图不存空记录**。宁可少一张图，也不要存 `dataUri` 为空、
  渲染出来是破图的记录 —— 那会让用户以为资料坏了。
- **失败必须说清下一步**。所有错误对象都带 `hint`，界面不允许只显示「失败」。
- **迁移只做加法**。旧备份缺的字段补默认值，绝不编造数据；判断不了就留空并如实标注。
- **不伪造统计**。缺数据就显示「未配置」，不把未知价格默认当成免费。
- **界面改完必须在真实应用里看**。tsc 通过、单测通过都不等于功能在。

## 项目结构

```
src/core/       核心逻辑（存储、迁移、解析、AI、出题、复习）
src/v2/ui/      实际在跑的界面（v2）
src/pages/      v1 界面，大部分已废弃但文件还在
electron/       主进程（数据目录、MinerU、窗口、IPC）
scripts/        验收与诊断脚本
docs/           交接文档、事故复盘、设计说明
```

⚠️ **v1 与 v2 并存**。改任何界面代码前先确认 `App.tsx` 实际 import 的是哪一份：

```bash
grep -n "import.*SourcesPage" src/v2/ui/App.tsx
```

`src/pages/sources/SourcesPage.tsx` 与 `src/v2/ui/SourcesPage.tsx` 是同名不同命的两个文件，
改错那份 tsc 照样通过，但界面一动不动。
