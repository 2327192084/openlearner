## 一、三层证据锚点：端到端验证做完了，并抓到一个真 bug

这是 11-19 晚交接文档列的「最重要遗留」。上一轮代码写好了、28 条单测全过，
但**从没被端到端证明过**。

### 为什么旧脚本验不了

`verify-mastery-evidence.cjs` 在页面上下文里 `import('/src/core/...')`，
然后**自己重抄了一遍** `handleOralJudge` 的逻辑。它验的是「四个纯函数串起来
对不对」，不是 `App.tsx` 里那条真实链路。按项目里那句话：
**一条断言如果对坏实现也成立，它就没在验任何东西。**

### 新脚本：只点真实 UI

`scripts/verify-mastery-evidence-ui.cjs`（30 项）：点导航 → 复习巩固 →
提问式复习 → 输入 → 提交，判定由真实 `handleOralJudge` 发起，
脚本只观察界面与数据库。本地假模型按 user prompt 分流
（`## 知识点` = 证据请求，`## 材料（判定依据）` = 旧判定）。

**两个前置条件**（旧脚本就卡在这里）：
- `BookPage` 在 `volumes.length === 0` 时整页 early return，toolbar 不渲染
  → 「提问式复习」按钮**根本不存在**。所以必须种已发布题组 + 题。
- 素材池来自 `pointsToMaterials`，必须种知识点（`statement` 非空）。

### 抓到的真 bug：模型被告知要判的概念是「第一章」

`App.tsx:1575` 把 `m.label` 传给 `buildEvidenceUserPrompt` 的 `statement`，
而 `OralMaterial.label` 的语义是**位置说明**。实测抓到的请求体：

```
## 知识点

第一章 线性表          ← 应该是一句知识点原话
```

模型不知道要判哪个概念，只能从原文里猜。三层证据那套设计（「只填证据、
不下结论」）因此打了折扣。

**为什么两周没被发现**：单测与旧脚本都把 statement 硬编码成
`'线性表是有限序列'`，正好绕过了接线错误。

**修法**（`a7b0e14`）：`OralMaterial` 加可选 `statement`，
`pointsToMaterials` 填知识点原话，`App.tsx` 优先用它、没有才退回 `label`。
不动 `label`（它进 `scopeLabel` 落库、也显示给用户）。

### 反向验证（证明脚本真的在验）

把 `App.tsx` 临时改回 `m.label` 重跑：**29 通过 / 1 失败**，失败项正是
「真实请求体里带了知识点 statement」。改回来 → 30/30。
**绿了不算数，得证明它能红。**

## 二、复习巩固页 + 答疑记录四项（用户截图提）

用户原话：

> 先优化现有功能。建议：复习巩固页的资料加个收起按钮，然后每一题都要有
> 一个定位回原文的功能，单挂一个出处不够。提问式复习按钮按后给用户两个
> 二级选项，一个是从知识库中随机/选定知识点进行提问（知识库的知识点应该
> 能选中进行提问），第二个是告诉用户可以回资料库划选原文进行提问。
> 最后是答疑记录，应该继续分类，一个是提问式复习的记录，一个是错题答疑的记录

| 项 | 原来 | 现在 |
|---|---|---|
| ① 卷收起 | 平铺，长列表一路滚 | 每卷标题左侧「▾收起 / ▸展开」，记**收起的** id |
| ② 每题定位原文 | 一行纯文字「出处：第 16 页」 | 按钮（本轮后期又改成精确定位，见第五节） |
| ③ 提问式复习 | 一个按钮直接进面板 | 两栏：知识库提问（挑/随机）+ 原文划选提问（三步指路） |
| ④ 答疑记录 | 页签只在两个来源**都有**记录时才出现 | 有任何记录就显示三页签，计数 0 的也可点 |

### ④ 为什么用户从没见过分类

条件原来是 `counts.oral > 0 && counts['wrong-explain'] > 0`。
用户真实库 `oralReviews` 是 **0 条** —— 所以他从未见过那排页签，
看到的一直是一份平铺列表。

### ③ 复用知识库挑选模式时修掉三个耦合 bug

「挑知识点提问」复用了 `KnowledgePage` 的挑选模式（原本只服务闪卡）：

1. 确认按钮写死「加入闪卡（N）」→ 加 `pickActionLabel`
2. 顶部说明写死「勾选要加进闪卡的知识点」→ 加 `pickHintText`
3. **已在闪卡里的知识点被无条件置灰** → 加 `pickDisablesPicked`。
   这条最严重：用户库里知识点大多做过闪卡，不改的话这个功能基本用不了。

`pickingForFlashcards` 布尔改成 `pickingFor` 枚举（两个布尔会出现
「都为真」的非法状态）。

### 又修掉一个：挑完知识点后面板显示两套矛盾信息

截图抓到：顶部写「选定的 1 条知识点」、下拉却写「知识点随机（2）」，
而且真去点那个下拉，**刚挑的素材会被覆盖**。
加 `oralScopeLocked`（state 配 `selectionOralRef`，分工：ref 给 effect 守卫、
state 管渲染）。

### 两次靠截图抓到、断言没抓住的

- **CSS 层外规则（老坑重犯）**：定位按钮 `color` 写在 `@layer` 里，
  界面实际是**灰色** —— `base.css` 层外那条 `button { color: inherit }`
  无条件压过层内规则。而我的断言写「颜色不是纯黑」，**亮灰照样通过**。
- **「收起后截图」没滚动**：被收起那卷在首屏之下，截图与收起前**长得一样**，
  等于没拍到证据。

## 五、定位精确到句子 + 橙色临时高亮

用户原话：

> 定位功能不够，现在只能定位到页面，不能具体到句子。现在在修改一下，
> 同时定位到句子时应该和标注的高亮的效果一样，只不过换成橙光来用来与
> 高亮和备注区分开来。（该橙光是临时的，当用户转到其他页面/界面时就会消失）

### 上一版为什么只到页

我把**题干**当 quote 传给阅读器。题干通常不在原文里，阅读器匹配不上
→ 落地只到页首。

### 实测你的库：题目锚点本来就没有句子位置

| 数据 | anchors 实际内容 |
|---|---|
| 题目（39 道全有） | `charStart: 0, charEnd: 1366` —— **整段** |
| 知识点（59 条） | `charStart: 1320, charEnd: 1364` —— 44 字，**真句子** |

而且这 39 道题**全部没有 `knowledgePointId`**（都是「自选 · 改造组卷」生成的），
所以「借知识点句子」这条路对你的现有数据不命中。

你说「自改题可以没有定位功能，给用户个提示就行」—— 所以这是**设计好的
正常分支**，不是失败兜底。

### 三种情况三种界面

| 情况 | 界面 |
|---|---|
| 能到句子 | 「定位回原文（第 16 页的**具体句子**）→」，点了圈那句 + 橙光 |
| 只到整段 | 「跳到原文（第 16 页）→」+ 说明为什么不高亮 |
| 无出处（自改题） | **不摆按钮**，只给一句提示（摆废按钮比没有更糟） |

逻辑抽成纯函数 `src/v2/core/locate-sentence.ts`，14 条单测。

### 橙光

形状完全照抄 `.reader-mark`（同 padding / 圆角 / 描边宽度），**只换颜色**：

| 标记 | 样子 |
|---|---|
| 定位高亮（临时） | 橙 `rgba(255,106,26,.28)` |
| 高亮标注（持久） | 琥珀 `rgba(217,164,65,.45)` |
| 备注 | 红色下划线 |

「临时」不靠 CSS：`Highlight` 加 `transient` 字段，翻页（`goPage` 里原本就有
`setHighlight(null)`）与离开组件即清，**从不写库**，刷新也不残留。

### 又抓到一个自己引入的 bug

整段级题第一版只传 `{sourceId, page}`，没带 `charStart/charEnd`。
阅读器判断「整段所以有意不圈」靠的正是这两个值 —— 拿不到就落进
「什么都没找到」分支，**连解释都不显示**。

抓到它的过程：断言「整段级题不高亮」当时是**绿的** ——
因为不显示提示也等于不高亮。**又是「断言对坏实现也成立」。**
是截图看到页面上一句提示都没有，才回头查的。

## 七、这一轮最贵的三条教训

### 1. 断言写得够宽 = 没在验（犯了四次）

| 断言原文 | 为什么没验到 | 漏掉的问题 |
|---|---|---|
| 「颜色不是纯黑」 | 亮灰也过 | 层外规则压掉 `--accent`，按钮是灰的 |
| 「收起后截图」 | 没滚动，被收起那卷在首屏下 | 截图与收起前长得一样 |
| 「进了知识库挑选模式」 | 没查顶部说明 | 「勾选要加进闪卡」那套错文案 |
| 「整段级题不高亮」 | 不显示提示也等于不高亮 | 阅读器连一句解释都不显示 |

**写断言时先问一句：坏实现能不能通过它？**

### 2. 界面改动必须截图 —— 这四条全是截图抓到的

这轮 CSS 和文案问题，断言一条都没抓住，全靠 `read_image` 看出来的。
用户会亲自截图验收，而截图能看到的比断言多。

### 3. 「验证脚本重抄被测逻辑」= 假验证

旧的三层证据脚本抄了一遍 `handleOralJudge`。它绿了 30 项，
但真实链路里那个 `m.label` 接线错误它永远看不到 ——
因为它根本没用真实接线。

**要验一条链路，就点真实 UI、抓真实请求体、读真实库。**
