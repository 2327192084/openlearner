### 3. 提问式复习：AI 判定不可靠，所以设计成「让它亮出依据」

用户要求 AI 判断「记忆错误 vs 理解偏差」。但这个分类**技术上不稳定**——
同一段错误回答，模型可能这次判记错、下次判理解偏。调 prompt 到不了 100%。

所以设计上不追求「判得更准」，而是：

1. prompt 强制输出 `quotedFromSource`（逐字摘自材料）
2. 解析层用 `quotesMatch()` 校验这段引文**是否真的在材料里**
   - 宽松到忽略空白与全半角差异
   - 但**字的顺序与内容必须一致**（改一个字就判 false）
3. 界面三态：`✓ 找到了` / `⚠ 没找到，判定未必可靠` / `⚠ 没给依据`

这样即使分类错了，用户能看到它凭什么这么判，而不是一个黑箱结论。

真实测试（DeepSeek）跑通了这一整套：它问「偶部和奇部分别称为什么」，
模拟的错误回答「两类信号没区别」被判为**理解偏差**，引文逐字命中。

## 三、一期：知识点标签（这是二三期的地基）

### 为什么先做标签

用户要「知识骨架能在按资料的基础上加分类，便于翻阅」。
查代码后发现一个关键事实：

> 骨架页正在警告「50 条知识点里 49 条没有记下所属章节」——
> 章节名是解析时从标题行猜的（`detectChapter`），经常猜不到。

而 `tags` 是整理时按小节标题写的、还能手改，**比章节可靠得多**。
所以标签才是那个能用的组织维度。

### 三处改动

1. **收紧 prompt**：`"tags": ["可选标签"]` → 要求从材料的**小节标题**取，
   只填 1~2 个，取不到就给 `[]`
2. **解析层清洗** `cleanTags()`：去 Markdown 标记（`## `、`**`、`` ` ``）、
   丢 13 个泛词（「基础概念」「重点」「可选标签」等）、去重、最多 2 个
3. **标签可手改**（`KpTagsEditor.tsx`）：只放行 tags

### 为什么只放行 tags（这条很重要）

`KnowledgePage` 原注释写着「不做编辑」，理由是改 statement 会让锚点失效。
我查证了：**锚点由 `quotes` 定位产生，与 `tags` 完全无关**。

所以「只放行标签编辑」是安全且够用的——用户能纠正 AI 的错误分类，
又不会碰到任何影响定位的字段。这个口子正好补上那条顾虑留下的空白。

### 筛选后数字必须重算

`ChapterGroup` 只存计数不存知识点，没法在页面层过滤。
改成 ready 状态带 `rawBySource` 原表，筛选时重新聚合，
连「章节 · N 条」都跟着重算——否则会出现「上面写 13，下面还写 50」。

### 附带发现

实测用户库 **59 条知识点全部已有标签**。AI 之前就给了，只是没约束。
所以「花 token 补标签」这一步实际不需要跑。

## 四、二期：记忆闪卡

### 数据结构

`flashcards` 分区。**引用知识点而非复制内容**（用户拍板方案 A）：

```
Flashcard {
  id
  knowledgePointId   // 引用
  frontText          // 冗余！见下
  backNote           // 用户可选备注
  origin             // 'ai' | 'user'
  sourceId
}
```

**为什么还要冗余 `frontText`**：只存 id 的话，知识点被删 → 翻开一片空白。
冗余一份并在读取时校验：知识点还在 → 正常；已被删 → 仍显示那句话但标「已过期」。

**两种过期情形**：知识点被删，或**知识点表述改了**（用户在背旧说法，这更隐蔽）。

### 与「今日复习」的分界（这条最容易搞混）

| | 今日复习 | 记忆闪卡 |
|---|---|---|
| 选什么 | 系统按到期排 | 用户自己挑 |
| 写复习记录 | 写（影响间隔） | **不写** |
| 参与 SRS | 是 | 否 |

翻卡写 SRS 会让用户翻几张就发现到期队列变了，完全无法理解。
端到端验证里专门断言了这条（`reviewRecords` 保持 26 不变）。

### AI 挑卡

`ai/pick-flashcards.ts`（纯逻辑，15 条测试）：

- **用编号而非 id**：让模型回传 `kp_8f3a...` 实测会串号，编号能校验范围
- **越界/重复一律丢弃**：挑错卡让用户背错内容，比少挑一条严重得多
- **用户勾选后才入库**：AI 判断可能不合直觉，全自动会让用户面对一堆不想背的卡

## 五、三期：提问式复习

### 一轮的流程

```
选范围 → AI 出题 → 用户作答 → AI 判定 → 显示判定 → 选保存 → 本轮结束
```

### 保存的两个形态（用户拍板）

- **完整原文**：连材料全文一起留（「我以后要回来读原文」）
- **精简**：只留说明与纠正，`fullText` 为 null（「我只想知道错在哪」）

默认**不保存**。用户可能只是随手试试，不想每次问答都往库里塞东西。

### 数据流

```
chatCompletion（复用 core/ai/chat-client）
  ├─ buildAskPrompt → 出题
  └─ buildJudgePrompt → 判定
       └─ parseJudgement + quotesMatch → 校验引文
            └─ OralReviewService.save → oralReviews 分区
```

第一版左右括号各自独立剥离，`(信号)` → `信号`，而 `(a)(b)` 会变成 `a)(b`。
改成只剥**成对**引号，且**不剥圆括号** —— `f(x)`、`(n+1)` 里括号是正文。

### 4. 问答的空答案被判成「错」

`if (!input) return false` 在 essay 判断之前，用户还没写就看到「答错了」。

## 十、调研过的结论（写下来避免重查）

### 1. 复习该怎么做（Anki / Ebbinghaus / cyberquizzer / StudyHub）

核心结论已写进 `review-session.ts` 与 `oral-review.ts` 头部注释。

- **Anki**：复习是有边界的专用会话（一次一张、看正面→回想→翻面→自评四档）
- **Ebbinghaus**：明确把「自由翻看」与「正式复习」分成两个功能，
  并写明前者**不影响**间隔安排 —— 这正是我们之前做错的
- **StudyHub**：复习页 = 题目 + 左侧题号栏 + `DailyRecap`（每日回顾）
  + `CoachDebrief`（收尾）+ `ResultBreakdown`

**为什么没换 FSRS 算法**：StudyHub 用 FSRS-6（`lib/sm2.js`），
但我们已有等价能力（`srs.ts` 的艾宾浩斯阶梯 + `buildTodayQueue`）。
缺的不是算法而是入口。换算法要重验全部间隔行为 + 老数据迁移，是另一件事。

### 2. UI 参考：没找到可复用的

GitHub 搜「flashcard study app UI design system」零结果，
通用搜索多是营销页。

但更有价值的发现是：**本项目设计体系已经完整**
（`tokens.css` 移植自 StudyHub 4.4.3，暖黑书桌 + 米色索引卡 +
朱砂只给主操作，`--text-*` 全部达 WCAG AA）。
所以 UI 那轮不换风格，只修与体系不一致的地方。

### 3. 墨墨开放 API：已全部移除

调研清楚后用户决定不做。留下的事实：
- 38 个操作 / 7 组，官方规范在 `open.maimemo.com/api_bundle.yaml`（已存 `.tmp`）
- **没有创建牌组的接口**（只有 GET），所以「一键把错题建成牌组」做不到
- 学习数据 5 个接口全是 beta
- 改词本是**整段替换**

## 十二、给下一个模型的话

1. **「测试全绿不代表界面正确」今天又验了 5 次**（见下表）。
   改界面必须 CDP 截图；改数据流必须查 IndexedDB；**量几何**也关键。

   | 现象 | 根因 | 为什么测试抓不到 |
   |---|---|---|
   | 整页高光刷屏 | 整段锚点被当普通偏移画 `<mark>` | 数据对，渲染出来才发现 |
   | 批注不显示 | `pageMarks` 只传给侧栏，没传进正文渲染 | 数据存了、列表能显示，缺绘制 |
   | 资料页白块 | v1 遗留 CSS 的 `.dropzone` 同时命中，用了 v2 不存在的变量 | 两条规则分散在不同目录 |
   | 错题页右侧空一大块 | 双重限宽 | 不量几何看不出来 |
   | 闪卡加完停在挑卡页 | `hasCards` 是加入前的快照 | 逻辑看着对，跑一遍才发现 |

2. **删功能要先查数据**。删类型不等于删数据；IndexedDB 里的字符串
   可能是 UTF-16LE，普通 grep 扫不到。

3. **同一个功能有多个入口时要全部改**。改完 grep 确认没有残留旧调用。

4. **改存储三件套后先看 tsc**。数字错了 tsc 抓不到，但类型塌了会一片红。

5. **验证脚本自己也会错**。全等匹配、分组名写错都踩过。

6. **CSS 冲突可能是跨目录的**。v1 的 `sources.css` 已完全孤立，
   但规则仍在构建产物里、仍在运行时生效。用 CDP 的
   `getMatchedStylesForNode` 能看到真正命中的规则。

7. **移动端/窄屏要自己加 media query**。今天给错题页概览、闪卡、
   提问式复习都补了 560px 以下的规则。

8. **不要声称「稳定」**。提问式复习的 AI 判定跑通一次不代表稳定，
   注释里写明了这是模型能力的边界，靠引文校验兜底。
