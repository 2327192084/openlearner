## 一、最重要的三件事

### 1. ⚠️ 我这一轮犯了三次「验证方法本身是错的」

`docs/交接文档-2026-11-16.md` 第五节记了两次，这一轮又添了三种新形态。
**这三条比任何功能都值得看 —— 它们让你少走我的弯路。**

#### （1）判据抓了页面里随便出现的字

验证 AI 组卷时，我用 `body.indexOf('交卷') >= 0` 判断「是否进入了考试」。
但**设置页的说明文字里就有「交卷后统一批改」** —— 于是请求还在跑，
脚本就报了 PASS。

截图抓到那一幕：按钮还写着「AI 组卷中…」，脚本却说成功。

**正确判据**：只用考试界面才有的结构（`.ex-nav` / `.ex-timer`）。

#### （2）用假数据验显示层，验不到接线

第一次验「解析任务记录」，我手写了一条 `generationRuns` 记录进库，
再验任务页怎么显示 —— 那只证明**显示层**对，证明不了
「解析时真的会写记录」。

后来花 5 分钱真跑一次云 OCR，才确认记录会自动出现（0 → 1 条）。
这个项目因「做了没接上」被投诉过多次（OcrService、updateDeck…），
**这一步不能省**。

#### （3）`--user-data-dir` 没生效，读的是错误的库

跑验证脚本时看到 `release/win-unpacked/` 下凭空多出 107 MB 的
`openleaner-data` —— 那是候选 #4（`ensureUserDataDir` 的第 4 个候选：
安装目录旁）抢先生成了。

**我一度拿到假的 8/8 通过**，因为脚本读的根本不是我传入的副本。

**判据**：跑完看 `release/win-unpacked/openleaner-data` 有没有出现。
**正确做法**：把 app 复制到一个**旁边没有 `openleaner-data` 的独立目录**
（我后来用 `$USERPROFILE/ol-xxx-app`），再看路径落在哪 ——
落在传入的副本里才算数。

### 2. ⚠️ 空 `catch` 让问题多花了一整轮

AI 组卷失败时界面只说「AI 这次没给出可用的组卷结果」。
原因是我在 `App.tsx` 里写了：

```js
try { ... } catch { return null; }
```

网络失败、Key 错、被截断、返回不是 JSON、id 全是幻觉 ——
**五种完全不同的原因全变成同一句话**。用户没法判断，
我也只能另写诊断脚本才查出真因（见 3.1）。

**教训：为了让界面「干净」而吞掉错误，是把诊断成本转嫁给下一个人。**

### 3. ⚠️ 这一轮最贵的 bug：推理模型的输出预算

用户报「AI 组卷没使用成功」。实测一次 API，把原始返回打出来：

```
HTTP 200
finish_reason:      "length"     ← 被截断
completion_tokens:  1200         ← 正好等于 maxTokens
reasoning_tokens:   1200         ← 全部花在思考上
content:            ""           ← 正文一个字都没轮到
```

`deepseek-flash` 是**推理模型**：先输出思考，再输出正文。
我设的 `maxTokens: 1200` 全被思考吃光。

**这不是模型的错，是我没给它留输出空间。**

修复后同一份题库、同一个模型：

| | 修复前 | 修复后 |
|---|---|---|
| finish_reason | length | **stop** |
| content | 空 | **20 个真实 id + 组卷说明** |

**⚠️ 以后加任何 AI 功能都要先确认**：这个模型是不是推理模型？
`maxTokens` 给够了吗？现在是 **4000**。

## 三、关键设计（别推翻，理由都在这）

### 3.1 AI 组卷：让它「挑」，不让它「出」

用户原话：「让 ai 出一套题型分布符合考试标准的题目」。

**但实现是「挑」不是「出」**：提示词第一条硬规则就是
「只能从清单里挑，不许编新题」。

**为什么**：新生成的题没有原文出处、点不回原页，而这个项目的支点
就是「每道题都能点回原文」。而且新题没经过用户审核。

`parseCompose` 在本地**再校验一遍 id**：模型幻觉出的 id 直接丢弃。
不做这一步，卷子里会出现取不到题干的空白题 —— 那比少几道糟得多。

**挑少了不自己补**：补的题不受模型判断约束，会破坏它配好的分布。

### 3.2 三条 AI 路径各自独立，别合并

| 路径 | 输入 | 输出 | 代码 |
|---|---|---|---|
| AI 组卷 | 题库 | **原来的题**，只重新挑 | `core/ai/compose-exam.ts` |
| AI 变式 | 错题 / 知识点 | 新题 | `core/questions/variants.ts` |
| 改造组卷 | **用户挑的题** | 新题 | `core/questions/compose-variant.ts` |

改造组卷**复用** `questionToVariantMaterial` 与 `VARIANT_AXES`，
不另写提示词。（交接文档 5.2「反馈只能有一份实现」）

### 3.3 模拟考的三态评分

`ExamAnswer.correct` 现在是三态：

| 值 | 含义 |
|---|---|
| `true` | 判对 |
| `false` | 判错 |
| **`null`** | **还没评**（自评题刚交卷） |

⚠️ **交卷时自评题必须是 `null`，不能是 `false`** —— 记成 false 等于
先扣一笔冤枉分，用户看到「答错」才被要求自评，与事实不符。

派生字段：`ExamAttempt.pendingCount`（还有几题没评）。

**分数口径必须排除待评题**：份 23 题里 4 题没评、答对 19 的卷子，
真实正确率是 100%，不是 83%。三处都改了（成绩页 / 历史列表 / 趋势）。

### 3.4 错题本的唯一入口是 `reviewLogs`

「错题与待巩固」页读的是 `reviewService.wrongCardsDetailed()`，
它扫 `reviewLogs` 里 `kind === 'question'` 且 `grade === 'again'` 的记录。

试卷错题就是往那里写一条（`exam.ts` 的 `recordWrongAnswers`）。
**不新建表** —— 新建的话错题本要同时读两处并去重排序，必然漂移。

幂等靠 id：`exam:<attemptId>:<questionId>`。

### 3.5 `fileStored` 会说谎，别信它

资料删进回收站时原件字节被清掉；从回收站恢复时资料行回来了、
字节回不来，但 `restore()` 原来**没有把 `fileStored` 设回 false**。

用户库实测：高等数学 442 页 `fileStored=true`，`sourceFiles` 里
**没有**这条记录。信了它就会去取、取不到、回落到「请用户重新选文件」。

**已于 11-17 修**：`trash.ts` 的 `restore()` 按实际有没有记录写对；
`ConvertPanel` 也不再用这个字段提前返回，改成**以能否真的取到为准**。

### 3.6 组卷进行中的提示：为什么是转圈不是进度条

组卷是一次请求，拿不到中间进度。**画一个假百分比比不画更糟** ——
用户会盯着一个不动的条等。转圈只说「在跑」，不假装知道跑了多少。

`prefers-reduced-motion` 下停掉旋转。

## 六、⚠️ 硬约束（这一轮又踩到的，加粗）

1. **验证破坏性操作必须在真正隔离的副本上做。**
   不要把卸载器复制到别处跑 —— NSIS 的 `$INSTDIR` 编译时写死。
2. **要动用户真实库，必须用桌面安装版且不带任何目录参数启动**，
   并用 leveldb 的 mtime + 字节数证明写进去了。
3. **做安装器实验前先记录 `%LOCALAPPDATA%\Programs\OpenLeaner` 的
   app.asar 与 exe 的 MD5 + mtime**，实验后再比。
4. **⚠️ 验证脚本用 `--user-data-dir` 时，必须确认真的生效**（见一节 3）。
5. **⚠️ 判据要贴真实状态，不能贴页面里随便出现的字**（见一节 1）。
6. **⚠️ 提交消息里有反引号/反斜杠，必须写进文件用 `git commit -F`。**
   这一轮我又犯了：`git commit -m "...双反引号..."` 被 shell 当命令替换执行，
   消息里那段变成空白，只能 amend。
7. **CSS 层级**：`base.css` 有不在任何 `@layer` 内的 `button`/`input` 规则。
   原生控件样式一律写层外，包括 `appearance: none`。
8. **token 分两套**：`src/styles/tokens.css` 是 v1（`--c-`，已废弃）；
   `src/v2/ui/tokens.css` 是 v2（`--bg-` / `--text*` / `--accent*`）。
   危险色是 `--bad`，不是 `--danger`。**没有 `--bg`**，画布色是 `--bg-canvas`。
9. **大文件里不要插代码**：`App.tsx`(2600+)、`ReaderPage.tsx`(2100+)、
   `ExamPage.tsx`(1500+)、`SettingsPage.tsx`(1440+)。新增 UI 一律独立文件。
10. **改界面必须 CDP 截图肉眼复核。** 断言全过不代表界面对。
    这一轮截图抓到 4 次断言抓不到的问题（假成功 1 次、显示 `__all__`
    1 次、按钮看起来像禁用 1 次、判据抓错字 1 次）。
11. **一条断言如果对「坏的实现」也成立，它就没在验任何东西。**
    反向验证（用修复前的代码跑）是唯一能证明脚本抓到 bug 的办法。
12. **大文件用 sed 按行号删代码前先 `cp` 备份**，删完立刻 `wc -l` + `tsc`。

## 九、给下一个接手的人

### 这个项目的三个特点，会决定你怎么工作

**1. 用户的界面敏感度很高。** 他会指出「按钮太淡像禁用」「多一个按钮界面臃肿」
「这个提示一直存在」。**截图肉眼复核不是形式主义**，是主要发现手段。

**2. 「做了没接上」是这个项目的老毛病。** OcrService、updateDeck、
mistake 闪卡都出过。所以每做完一个服务层功能，都要 grep 一遍
「服务层有方法但零界面调用」。

**3. 前任的交接文档写得很细，那是因为踩的坑很贵。**
第一节那三条（判据错、假数据、`--user-data-dir` 没生效）
这一轮我全踩了一遍。**看文档能省你半天。**

### 这一轮我做得不好的地方

- **空 catch**：为了界面干净吞掉错误，让用户和我都多花了一轮。
- **判据抓错字**：`body.indexOf('交卷')` 这种判据等于没判。
- **提交消息用 `-m` 带反引号**：硬约束里写着不能用，我又犯了。
- **测试 mock 用 `as unknown as Question` 绕过类型检查**，
  漏了运行时必需字段，6 条测试一起崩。
  **类型断言不等于不用填字段。**
