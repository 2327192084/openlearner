## 二、最重要的一件事：MinerU 图片到底会不会失效

交接文档第三节留了一个风险没验：**locator 依赖 MinerU 自己的缓存，清缓存后还能不能取图？**
这个结论决定架构（「存 locator 现取」还是「首次解析时立刻存图」）。

**做成对照实验，没有只看文档**：

1. 复制 MinerU home 到 `.tmp` 副本（遇到 ACL 保护，用 icacls 收紧后才起得来）
2. 基线：取 `page:1/block:7` → 成功，7117 字节，渲染出 416×216 的电路图
3. 删掉副本里的 `doclib/parsed/87`（该文档的解析缓存），**原 PDF 仍在**
4. 重启服务再读同一 locator → `Error: Requested parsed content is not cached.`

源码佐证（`mineru/doclib/services/content_read_svc.py`）：`_render_image_response` 先找页，
取不到抛 `page_not_cached`；`_render_source_image_asset` 还要靠原文件路径按 bbox 裁图。

**结论：locator 不是永久地址，会失效。必须在转换时立刻取图。**

### 顺带查清了文档说错的地方

交接文档第七节说「图片 locator 被当普通文本存在 `sourceSegments.text` 里，阅读器会渲染成坏链接」。
**查真实库后确认这是错的**：`markdown.ts` 有一条正则把图片行整行丢掉，
`sourceSegments.text` 里 0 个 `![`、0 个 `doc:`。所以不是「抽出来」，而是「现在根本没存，要新加提取」。

### 三个实测发现（写进了注释）

- MinerU 的 blob zip 里 `markdown.md` 用的是 `![](images/page_0_image_6.jpg)`，**没有 doc: 定位符**
  —— 定位符是导出时现生成的，要从 `converted.md` 拿
- `block:N` 是 **1 基**，对应解析 JSON 里 `block.index = N-1`
- doclib 有本地 HTTP API（`/api/v1/content?locator=&format=image`），**比 CLI 快 3.4 倍**（0.43s vs 1.4s/张）

### 关键设计：为什么不把图写进 `seg.text`

知识点靠 `charStart/charEnd` 字符偏移定位，库里 95 个已按当前 text 算好。
插一个字符就整体平移，高亮集体错位且**难以察觉**（只是偏了几个字，用户分不清是数据坏了还是自己记错）。

所以 text 字节不动，图片单独存 `sourceImages` 分区，用 `charOffset` 记位置，渲染时插回。
用真实 `converted.md` 逐页守住「text 与改动前逐字节一致」。

**验证**：真实库补图 88 张全部成功、0 失败、1.05 MB；
点「第 N 页」跳过去，`mark` 文字与知识点引文完全一致，同屏还有 2 张图 —— 偏移没错位。

## 四、用户反馈逐条与根因

### 1. 「知识库没有删除功能」（确认属实）

`KnowledgeService` 早有 `remove()` / `clearBySource()`，但 `KnowledgePage.tsx` **一个删除按钮都没接**。
典型的「底层写好了、界面没接」。现在每条有「删除」，每份资料有「删除全部知识点（N 条）」。

### 2. 「任务栏最近一次任务没统计 token」（不是没统计，是关联不上）

真实数据：11-08 那组题花了 **51,861 token**，记在 `usageRecords`（按天聚合），
但任务页从 `decks.createdAt` 反推，拿不到 → 显示 null。

**根因：出题流程根本不写 `generationRuns`。** 按用户选的方案修（补 run 记录），
顺带让任务页能看到出题耗时与失败原因（原来这些信息全丢了）。

### 3. 「学习库右侧界面太空」

原右侧是一张固定「下一步」卡，显示「10 张没学过 + 去我的题组挑一组」，
而左侧主区**已经在说同一件事**（同样是 10）。改成可自定义小组件，默认放今日学习 / 待办 / 每日一句。

### 4. 「待处理错题点进去没有任何错题」（真实 bug）

实测：`reviewLogs` 18 条 / 16 张卡，其中 15 张答错过；
但那 15 张**全都不在当前的 questions 表里**（旧题组删了、重生成一批新 id）。

根因：`wrongIds` 直接数 `reviewLogs`，不检查题还在不在；错题页有 `if (!card) continue` 正确跳过。
**两边口径不一致**，所以点进去是空的。

修法：角标只算当前仍存在的题。**测试做了反向验证** —— 回退修复后 5 条测试里 3 条立刻变红，
证明断言真能抓住这个 bug，不是凑数。

### 5. 「开始学新题」跳到了题组库

核实：`onLearnNew` 接成了 `onOpenDecks`，而题组库**只有列表和预览、没有练习入口**。
改成去「开始学习」页（三种模式的入口）。这是「不指向不存在的地方」那条规矩的反例。

### 6. 「重新计时」没用（同意删除）

题目已答完、判定已算出，重置计时器既不撤回答作也不重算评分，
唯一效果是把「用时 1.2 秒」清零。纯装饰按钮，按「不做假开关」删掉。

## 五、我自己踩的坑（都记进注释了）

### 1. 熟练度百分比放错了分母

做完「显示本轮正确率」后，答对 1 题只显示「做对 1」，没有百分比。

原因：我用 `done` 当分母，而 `done` 在 `submitGrade`（评完分档）才加，
正确率却要在**提交答案那一刻**就能看到。加了 `done > 0` 判断，结果正确率永远不显示。

修法：新增独立的 `answered` 计数，在 `submitChoice` 里 +1，语义是「已揭晓答案的题数」。

> 截图复核时才发现：数字看着对，少了一半。

### 2. 待做清单只做了一半

第一版只给「今日题组」（到期批次）加了清单，而库里恰好 10 道全是新卡、到期批次为空。
截图时 `.pq__toggle` 是 null 才发现 —— 用户要的是「进去能看到待做哪些题」，
只覆盖到期等于没覆盖。补上新卡批次。

### 3. 验证脚本自己被转义吃掉三次

`shell heredoc → node -e → JS 模板字符串` 三层，把反斜杠吃了三次，写的正则全变成语法错误。
最后改成：用 write 工具直接落盘、脚本内一律用 `indexOf` + `String.fromCharCode(10)`，一次跑通。

> 交接文档那条「验证脚本自己也会错」又加了一个实例。

### 4. 每日一句的取值算法塌陷

首版用 `h * 2654435761 % 30`，32 位整数溢出后分布塌陷，
实测**连续 30 天只取到 7 个不同句子**。肉眼看不出来（每天都有句子，只是反复重复）。

改成「日期串 → 自 1970 起的天数 → 取模」，相邻两天必然不同。
这个 bug 是「连续 30 天不重复」那条测试抓出来的。

### 5. 图注重复显示 + 一张图占满整屏（截图发现）

- MinerU 把图注当正文文字留着，`figcaption` 又渲染一遍，同一句出现两次。
  修法选保守的：**渲染时去重，不改 text**（改了偏移就废）
- 接近正方形的插图算出来 660px 高，而可用高度才 675px。加 `max-height: 72vh`
- 第二张小组件卡的字被米色蒙层盖住：`.today-stack` 的叠纸伪元素原来只垫一张纸，
  多卡时盖到了上面。多卡时不显示衬纸

## 六、学会了「看视频」

用户给了一个 B 站视频（StudyHub 4.5.1 介绍）。我最初误判「看不了」，
后来找到两条路，都不需要下载整个视频：

- **B 站公开的「视频快照雪碧图」接口**：`x/player/videoshot?aid=&cid=`
  → 一张 10×10 网格、一帧 480×270、覆盖全片；PIL 切片即可逐帧读
  → 163 KB、几秒拿到 100 帧
- 备选：`yt-dlp` + `ffmpeg` 抽关键帧（[claude-video](https://github.com/bradautomates/claude-video) 那类项目的做法）

从帧里读到的三个可参考点：
- 答错解析是**逐选项讲**（你的选择标红、正确答案标绿）
- 排期有「**为什么是 1 天？**」可展开
- 首页数字是**拆开的**（「3 题待学 · 1 题到期 2 题薄弱」）

这三条都做了。
