## 三、本轮做了什么（按用户提出的顺序）

### 1. 计时评分系统（用户要求「内置计时器 + 可自定义标准」）

```
src/v2/core/grading.ts       判分：按「题型+题目长度」算基准时长，再用倍率判档
src/v2/ui/use-card-timer.ts  计时器：等两帧起表、切窗口暂停、可手动暂停
src/v2/ui/ReviewPage.tsx     接入：显示实时计时 + 判定面板
```

**默认标准**（用户拍板「参考不背单词 / 艾宾浩斯」）：
倍率 r = 实际耗时 ÷ 基准时长
- r < 0.6 → easy（一眼就会）
- r < 1.2 → good（正常）
- r < 2.5 → hard（想了一会儿）
- 答错一律 again，**不看时间**

**三条硬规则**：
1. 答错永远 again（答错了就是没会，不能因手快放宽）
2. 超过基准 8 倍按 8 倍算（中途离开不被重罚）
3. **不显示「建议时长」** —— 用户明确说过「这个不好估计」，内部用它归一化可以，
   摆到界面上就是误导。有测试锁死这句话不许回来（`grading.test.ts` 的
   「对外文案不暴露建议时长」）。

### 2. 三种做题模式（用户要求「做完一次后面就没题做了」）

```
src/v2/ui/PracticePage.tsx   选题页：今日题组 / 自由练习 / 错题巩固
src/v2/ui/ReviewPage.tsx     做题页（新增 mode / modeLabel props）
```

- **今日题组**：受到期日约束，一批最多 30 张
- **自由练习**：不受到期限制，可选题组或全库随机（Fisher–Yates 洗牌）
- **错题巩固**：只做「最近一次答错」的题

### 3. 评分区分度（用户原话：「只有 5 分才与其他分数做出了区分」）

**根因查证属实**：旧 `FIRST_INTERVAL = { hard: 1, good: 1, easy: 3 }`，
首次复习 3 分和 4 分**都给 1 天**，之后又乘同一个 ease，差距永远拉不开。

**改法**（`src/v2/core/ebbinghaus.ts`）：
- 6 档评分缩到 4 档（Anki / 不背单词都是 4 档）
- 每档独立倍率 + **独立上限**：hard ×1.2/180 天、good ×2/270 天、easy ×3/365 天
- 「忘记」给 0 天（当天内重考，艾宾浩斯要点）

**为什么每档要独立上限**：最初用「共用台阶表 + 按档位走几级」，测试发现走到后期
四档会撞在一起（`[0,365,365,365]`），加密集台阶只能推迟不能消除。改成独立上限后，
实测 8 轮每轮都互不相同，包括顶到上限那轮 `[0,180,270,365]`。

### 4. 错题归集（用户要求「答错了直接记入错题就行」）

**发现一个假功能**：原错题列表读 `answerRecords`，但 v2 做题流程**从不写那张表**
（实测真实库里 0 条），「错题巩固」永远是空的。

**改法**：从 `reviewLogs` 里 `grade === 'again'` 派生（用户拍板方案 A）。
不新增数据表、不双写。见 `ReviewService.wrongCards()` / `wrongCardsDetailed()`。

**答错不弹判定面板**：直接记 again → 显示答案与解析 → 只给「下一题」。

### 6. 出题功能：从「只能选一种」到「五种可勾选」


**五种题型**：单选 / 多选 / **判断题**（新增 `QuestionKind='truefalse'`）/ 填空 / **问答**。

**为什么加问答题**：Anki 社区共识是「选择题适合筛查、不适合记忆」——
4 个选项蒙对概率 25%，蒙对后调度器以为掌握了会拉长间隔，考场上才发现不会。

## 五、⚠️ 硬约束（违反会立刻出问题）

### 1. 迁移必须三件套

新增存储分区时，**三处都要改，漏一处就是线上 bug**：

1. `src/core/storage/types.ts` 的 `STORES`（建分区）与 `BACKUP_STORES`（进备份）
2. `src/core/storage/indexeddb-storage.ts` 的 `DB_VERSION` +
   `src/core/model.ts` 的 `LIBRARY_SCHEMA_VERSION`
3. `src/core/migrations.ts` 加一条 `N: (backup) => ({...backup, schemaVersion: N+1, 新字段: []})`

> **本轮踩过**：`examAttempts` 的分区和备份字段都加了，但 `DB_VERSION` 忘了提
> （补丁被中断），老用户库不会触发 `onupgradeneeded`，**考试记录表根本不会建出来**。
> 后来核对版本常量才发现。**类型检查抓不到这种错** —— 那些是不参与类型检查的数字。

**迁移只做加法**：旧备份缺字段补空数组，**绝不造内容**。
「塞一条示例」会被用户当成自己写的。

### 2. 做题文案不许提「建议时长」

用户明确否决过（「这个不好估计」）。`grading.test.ts` 有测试锁死：
判定文案里不许出现「通常要/通常约/约需/建议/应该花/标准用时」。
内部用基准时长归一化是可以的，但**不能露到界面上**。

### 3. `GeneratePage.tsx` 是 CRLF/LF 混用

```
CRLF 546 行 / bare LF 19 行（每次改动后要核对这两个数）
```

按行号批量替换会错位（历史上把结构改坏过两次）。**优先「纯插入 + 抽独立组件」**。
本轮新增的 `KindPicker` / `ImportPanel` 都是独立文件，GeneratePage 里只插入引用。

**用 `scripts/_patch.py` 改文件**：它能识别文件实际行尾，
替换时自动展开 `\n` → 该文件用的行尾，并在改完后打印 CRLF/bareLF 计数供核对。

### 4. CSS 层级陷阱

`src/styles/base.css` 有个**无层级**的 `button{color:inherit}`。
CSS 级联是「层级先于特异性」，所以**在 `@layer` 里写多少特异性都赢不了它**。
改任何原生控件颜色，先把规则写在 `@layer` 外面。

**本轮又踩一次**：`.btn-fill:disabled` 在 `@layer` 内，禁用按钮的文字色被压掉，
看起来和能点的一模一样。项目已因此踩过四次。

**另一个变体**：v1 的 `src/pages/practice/practice.css` 里 `.wb-item` 也是无层级规则，
把 v2 新建的 `.wb-item` 压成了 `display:flex` 竖条。**新组件的类名要避开 v1 的前缀**
（用 `wbk-` 而不是 `wb-`）。

### 5. 改界面必须截图，改数据流必须查 IndexedDB

本轮有 **8 个 bug 是截图/查库才发现的**，测试全绿：
判定面板文字看不见、错题页被压成竖条、「正确答案」标签换行竖排、
下拉框数量显示两遍、禁用按钮像能点、勾选框 ✓ 污染文本、
两种矛盾提示同时出现、白边。

**所以：测试通过 ≠ 界面正确。**

## 七、⚠️ 已知问题（接手后优先处理）

- `ReviewPage` 有 3 处分支处理它（`submitChoice` / `canSubmit` / 选项区）

**建议**：直接往库里写一道判断题（挂已发布题组），然后从「今日题组」进去看。

### 2. 真实模型不保证按勾选的题型出题

勾了 3 种，可能只给 2 种。这不是 bug 是概率性行为。
现在的处理是**如实告知**：生成结果里显示「实际题型：填空 5 道 · 问答 2 道
（判断题 这次没出成 —— 模型不一定每次都按要求分配题型）」。

提示词里已加「每种至少出 1 道」的强制要求，但不能保证。

### 3. `todayUtc()` 用 UTC 而不是本地日历

StudyHub 的 `lib/sm2.js` 明确偏离了上游库的 UTC 计数，理由是
「北京时间 07:50 和 08:10 跨了 UTC 日期，但用户觉得是同一天」。

我们的 `todayUtc()` 正是 UTC 计数。**这是被上游明确修正过的设计缺陷**，
修它会影响所有 `dueAt` 的语义，需要迁移测试 + 备份。

### 4. `answerRecords` 分区是空的

v2 从不写它（错题已改用 `reviewLogs`）。这个分区留着是因为
`BACKUP_STORES` 里有、旧备份可能带。**不要在它上面做新功能**。
