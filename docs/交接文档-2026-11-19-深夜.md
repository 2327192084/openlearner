## 二、⚠️ 抓到的真 bug：模型被告知要判的概念是「第一章」

### 现象

`App.tsx` 的 `handleOralJudge` 把 `m.label` 传进
`buildEvidenceUserPrompt({ statement: ... })`。
而 `OralMaterial.label` 的语义是**位置说明**：

- 知识点素材：`第一章 线性表`（章节名）
- 段落素材：`信号与系统 · 1.2 · 第 9 页`

实测抓到的请求体：

```
## 知识点

第一章 线性表          ← 应该是一句知识点原话
```

模型不知道要判的概念是什么，只能从原文里猜。
三层证据判定的整套设计（「只填证据、不下结论」）因此打了折扣。

### 为什么两周没被发现

单测与 `verify-mastery-evidence.cjs` 都把 statement **硬编码**成了一句
知识点原话（`'线性表是有限序列'`），绕过了真实接线。

更关键：**旧脚本自己重抄了一份 `handleOralJudge` 的实现**
（`chatCompletion` + `parseEvidence` + `scoreEvidence`），
所以它验的是「四个纯函数串起来对不对」，不是这条链路通不通。

这是项目里那句话的又一次应验：
**一条断言如果对坏实现也成立，它就没在验任何东西。**

### 修法

- `OralMaterial` 加**可选**字段 `statement`：这一条要考的是什么
- `pointsToMaterials` 填知识点原话（`p.statement.trim()`）
- `App.tsx` 优先用它，没有才退回 `label`
  （段落/划选素材没有「提炼句」，退回位置说明，**不编造一句陈述**）
- **不动 `label`** —— 它会进 `scopeLabel` 落库、也显示给用户

## 三、新验证脚本为什么可信（`scripts/verify-mastery-evidence-ui.cjs`）

- 含 `## 知识点` → 证据判定请求

2. **真实代码的兜底**：假模型返回坏 JSON → 不报错，退回旧判定，

3. **落库一致**：`oralReviews.verdict` 与界面一致；
   且如实记 `quotedFromSource: ''` / `quoteVerified: false`（没编造引文）

### 6.1 ③ 复用知识库挑选模式时，修掉三个耦合 bug

「挑知识点提问」复用了 `KnowledgePage` 的挑选模式（原本只服务闪卡）。
复用立刻暴露三处写死：

1. 确认按钮写死「加入闪卡（N）」→ 加 `pickActionLabel`
2. 顶部说明写死「勾选要加进闪卡的知识点」→ 加 `pickHintText`
3. **已在闪卡里的知识点被无条件置灰**（`disabled={inFlashcards}`）→
   加 `pickDisablesPicked`，挑来提问时不再置灰。
   做过闪卡不影响能不能问它 —— 这条不改，用户库里凡是做过闪卡的知识点
   全都勾不动，功能形同废掉。

`App` 里 `pickingForFlashcards` 布尔改成 `pickingFor` 枚举：
两个布尔会出现「都为真」的非法状态，行为取决于判断顺序。

### 6.2 挑完知识点进面板后不给「换范围」下拉

截图抓到矛盾：顶部写「选定的 1 条知识点」、下面下拉写「知识点随机（2）」，
而且用户真去点那个下拉，**刚挑的素材会被覆盖**。

修法：加 `oralScopeLocked`（state）+ 原有的 `selectionOralRef`（ref）成对设置。
两者分工：ref 给 effect 里的守卫用（不能被 setState 时序影响），
state 只负责渲染（ref 变了不触发重渲染，只读 ref 下拉会停在旧状态）。

### 6.3 「划选原文」那条路刻意不做一键跳转

跳过去用户还得自己找书、翻页、拖选，一步没省 —— 那是假开关。
所以做成「指路」：三步行内指引 + 如实写「这条路要你自己划一段，所以没做成一键」。

### 7.3 跨资料全文搜索（2026-11-20，提交 `8097785`）

只能在某一本书里搜。现在顶栏中间加了全局搜索框。

| 要点 | 做法 |

| 点击 | **落到那句话并标橙光**，不是只跳页（与「定位精确到句子」同一条链路） |
| 搜不到 | 如实区分「真没有」与「有 N 份资料还没正文」 |

### 7.4 ⚠️ 顺带修掉的 bug：`ReaderTarget.segmentId` 从来没被读过

`ReaderTarget` 里**根本没有 `segmentId` 字段**，而 `SourceLocation`
与搜索结果里都有。调用方传了也没人读（跨 props 传时多余字段被静默忽略）。

后果：阅读器只能按 `page` 猜段，而 **page 在一份资料里不唯一**
（按章节切分时 page = index；OCR 资料也可能多段共用页码）。
实测现象：搜索结果点进去，页码对了、顶部显示「已定位到第 9 页的原文位置」，
但**正文里没有任何高亮** —— 选中的段不是偏移所在的那段，偏移越界被静默丢弃。

修法：`ReaderTarget` 补 `segmentId?`，阅读器优先按它精确匹配，没有才退回按页码。
**这条对所有带 segmentId 的跳转都生效**（错题、知识点、搜索结果）。

### 7.7 ⚠️ `vite build` 会覆写项目根的 `index.html` —— 别提交它

**这一轮打包后 `git status` 里多了一条 `M index.html`**，diff 是：

```diff
-    <script type="module" src="/src/main.tsx"></script>
+    <script type="module" crossorigin src="./assets/index-BSbk2fdS.js"></script>
+    <link rel="stylesheet" crossorigin href="./assets/index-DDt0ZgFU.css">
```

vite 把开发入口换成了打包产物引用，**直接写回项目根的同名文件**。

- 它是**源码**（开发入口），`.gitignore` 里没有它（也不能加 —— 那会
  让开发入口不受版本管理）
- **一旦提交，`npm run dev` 就废了**（入口指向不存在的 assets）
- 处理：`git checkout index.html` 还原，且**不要 `git add -A`**
  （会把它一起带走 —— 这轮我差点这么干，是 `git status` 里多出的
  那条未暂存改动提醒了我）

每次 `npm run electron:pack` / `vite build` 之后都要检查一遍这条。

### 7.8 关于「AI 组卷题型分布」与「改造组卷维度」（2026-11-21 核实）

交接文档 11-17 的 7.1 把这两条列为「待用户决定」。**实测代码后确认：前者已经实现，后者不是缺陷。**

**① 题型分布：早已支持逐种填数字**

- `GenerateQuestionsOptions.kindCounts`（`backend-types.ts:62`）
- `planKinds()` 按配额展开序列（mock 与真实后端共用同一份推导）
- 界面：`GeneratePage.tsx` 的 `QuotaPicker`（勾题型后可逐种填数量）

所以「要不要强制按比例」这个问题已经不存在 —— 用户填了配额就是强制的，
不填则退回「尽量平均分配」的旧行为。

**② 改造组卷的维度：空数组是**有意的默认**，不是缺失**

`compose-variant.ts:45` 的注释写得很清楚：

> `/** 改造维度；空数组 = 让模型自己选一个等价考法 */`

也就是说「不指定维度」本身是一种设计选择：让模型自己挑一个等价但不同的考法，
而不是逼用户每次都勾维度。要暴露维度选择是**可选增强**，不是补缺陷。

## 九、给下一个接手的人

- **这轮最贵的一条**：验证脚本重抄一遍被测逻辑，等于没验。
  要验一条链路，就点真实 UI、抓真实请求体、读真实库。
  「旧脚本 28 项全绿」和「这个功能是通的」是两件事。
- **绿了要再证明它能红**。反向验证（改回坏实现重跑）是唯一能证明
  脚本抓到 bug 的办法 —— 这轮靠它确认了新增断言不是摆设。
- **断言写得够宽 = 没在验**。这轮四次都是同一类错误：
  - 「颜色不是纯黑」→ 亮灰也过，放过了层外规则压掉 `--accent` 的 bug
  - 「收起后截图」没滚动 → 被收起那卷在首屏下，截图与收起前**长得一样**
  - 「挑知识点进了知识库」→ 没查顶部说明，漏了「勾选要加进闪卡」那套文案
  - 「进面板了」→ 没查下拉，漏了「选定的1条 vs 知识点随机」的矛盾
  写断言时先问一句：**坏实现能不能通过它？**
- **用户真实库的字节数变化，现在有两级排查**：
  ① 只启动再关闭（排除 LevelDB 开销）；
  ② 逐条扫 `updatedAt` 在时段内的记录（定位到具体哪条）；
  ③ 还要加一级：直接扫「有没有我种的那份数据」（id / 标题都对一遍）。
  这轮 +38B 就是靠 ①②③ 全做一遍才敢结论「不是我写的」。
- 桌面版仍落后 HEAD **三个**提交（`5d8fb52` / `a7b0e14` / `377832b`）。
  要让「桌面版 = HEAD」重新成立，需要走一遍 `electron:pack` 三件套替换流程
  （见 `交接文档-2026-11-19-晚.md` 七节 7.2），**但别重新生成安装包**，
  用户的规矩是「只有我让生成安装程序时才生成」。
