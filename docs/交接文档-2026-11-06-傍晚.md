## 三、v2 已完成什么（可运行的四个页面）

入口在 `src/main.tsx` → `src/v2/ui/App.tsx`。
v1 的 `AppRouter` 已不再挂载，但文件保留（其业务逻辑仍被 v2 调用）。

### 1. 间隔复习引擎 `src/v2/core/srs.ts`（42 项测试）

SM-2 改进版。**为什么不用 FSRS**：FSRS 需要大量历史数据才能拟合，
新用户前几十次复习没有意义；SM-2 参数少、行为可解释，
用户问「为什么今天让我复习这个」时能说清楚。

三处相对原始 SM-2 的改进：
- 间隔上限 365 天（备考场景不该推到十年后）
- 答错时 ease 只降 0.2 而不是打回原点
- 刚答错过又答对给较小跳跃（2~5 天），不当成全新卡片

评分用四级（`again/hard/good/easy`）而非原版六档：
六档实际使用中没人分得清 3 和 4。

**关键函数**：`schedule()` / `isDue()` / `mastery()` / `buildTodayQueue()`

### 2. 复习服务 `src/v2/core/review-service.ts`（14 + 18 项测试）

进度与历史分开存：
- `reviewRecords`：每张卡一条，只留最终状态
- `reviewLogs`：每次评分一条，用于统计「今天刷了几张」

**两者都进备份** —— 丢了等于让用户白学几个月。

概览数字必须来自**同一时刻的快照**，否则会互相矛盾
（v1 出现过「显示到期 5 张但列表只有 3 张」）。

### 3. 卡片模型 `src/v2/core/cards.ts`（28 项测试）

把 v1 的 `Question` 与 `KnowledgePoint` 统一成 `Card`。

**为什么要统一**：v1 里两者各有独立进度，复习时不知道该按哪个来。
这是 v1 的结构性问题之一。

判分含**宽松匹配**（填空/简答）：忽略空白、标点、全角半角，
阈值 0.6（实测：`顺序存储结构` 含 `顺序存储` 是 0.67，按 0.7 会误判为错）。

## 五、设计系统：从 StudyHub 移植，改动要谨慎

### 来源

设计 token 直接移植自 **StudyHub 4.4.3**（`EricWang1358/dsh-web-studyhub`，MIT）。
子代理把仓库 clone 到了 `.tmp/studyhub`（3731 文件，67MB），
`ui/tokens.css`、`ui/shell.css`、`ui/DESIGN.md`、`ui/review/question.css`
是原始出处。**需要对照时直接读那些文件。**

> ⚠️ `.tmp/studyhub` 是临时 clone，已 gitignore，可能被清理。
> 需要时重新 clone：
> `git clone --depth 1 https://github.com/EricWang1358/dsh-web-studyhub .tmp/studyhub`
> 但**不要依赖它** —— 我们需要的设计值已经落到 `src/v2/ui/tokens.css`
> 与 `shell.css` 里了，那里才是权威。

### 核心设计原话

> "the card is the only physical object; everything else is type on a desk."

暖黑书桌（`#161412`）+ 米色索引卡（`#ece4d6`）+ 单一朱砂红（`#c93d22`）。
朱砂**只用于主操作与进度**。

### 不能改的几条

1. **选中态用中性色，不用朱砂**
   否则页面上同时出现两个红，用户不知道看哪个。

2. **纸张卡片三个细节缺一不可**
   顶部 2px 朱砂横线 + 索引卡横格线（每 32px）+ 圆角 16px。
   少一个就变成「一个米色的 div」。

3. **字重只有 300 / 400 / 550 / 650 四档**
   没有 500 和 700 —— 深色底上相邻两档看不出差别。

4. **一屏只有一个填充主按钮**
   评分档、导航项、次要操作都不带实心底色。

5. **≤560px 时侧栏变抽屉，不收缩成图标条**
   图标条在 420px 下只能挤出 60px，还得让用户记图标含义。

6. **色值不要随意改**
   `--text-*` 全部达 WCAG AA 4.5:1，重调等于把测试重做一遍。

## 七、踩过的坑（都真踩过，别再踩）

### 环境类

| 现象 | 真因 |
|---|---|
| `npx vitest run` 报 `spawn EPERM` | 沙箱禁止 node 创建子进程；vitest 必须启 esbuild |
| `npx vite build` 报 `Access is denied` | esbuild 临时文件被锁，设 `TMPDIR`/`TMP`/`TEMP` 到工作区 |
| 全量测试随机红 1~3 个、单独跑全过 | PDF 用例并行时涨到 4~6s，撞默认 5000ms；已设 `testTimeout: 20000` |
| 验收脚本 `EPERM` | 上次的 headless Edge 没退，先杀进程 |
| 桌面版双击无反应 | Chromium 沙箱崩溃，必须走 `OpenLeaner-Launcher.bat` |
| `electron-builder` 联网必失败 | 改离线手工组装（见附录） |

### 数据类

| 现象 | 真因 |
|---|---|
| **PDF 第 3 页起渲染成纯白** | pdfjs 6 缺 `wasmUrl`，JBIG2 图像被**静默跳过**（不报错） |
| pdfjs 渲染空白但图"存在" | 同时传 `canvas` 与 `canvasContext` 时 pdfjs 忽略后者；须 `canvas: null` |
| OCR 中途停止后 628 页变 2 段 | `isWholeDocument` 用「请求范围」判断而非「实际完成」 |
| 内容存不住（画了刷新就没） | `hasContent()` 漏判类型（先漏 `shapes`，后漏 `textMarks`） |
| 高亮锚点错位 | TreeWalker 把工具栏图标文字算进了正文偏移 |
| 历史统计少一条 | 日志 id 用时间戳，同毫秒冲突覆盖 |
| 概览数字互相矛盾 | 统计时漏了「只算池子里的卡」的范围过滤 |

### 界面类

| 现象 | 真因 |
|---|---|
| 「只能用批注」 | 批注画布始终 `pointer-events: auto`，鼠标落不到文字上 |
| 高亮点了没反应 | 工具条按钮的 `pending` 被「点外部收起」监听器清空 |
| 出题页说「无法出题」 | 默认选中第一份资料，而它恰好没整理过知识点 |
| 提示「去学习库整理知识点」 | 学习库页**没有那个入口**，指向了不存在的地方 |

### 一个反复出现的错误模式

**用 fixed 值承诺动态结果**。例：
界面写死「熟练 → 20 天后复习」，但 SM-2 首次只给 1 天。
用户点了发现第二天又来，会觉得软件在骗人。

现在用 `schedule()` 真实算一遍显示，数字与算法永不脱节。

## 十一、几条不能碰的约束

1. **不要动 `src/core/sources.ts` 里 PDF 原始字节保存的逻辑**
   （pdfjs 会 detach ArrayBuffer，顺序不能倒回去）

2. **凭据、登录态、`secrets` 分区**不进代码、日志、导出或提交

3. **不做「假开关」**
   这个项目已经因此摘掉三个东西（联网检索勾选框、agent-app 类型、
   本地 OCR 死标签）。不做的功能就明说没做，不要摆一个点了没反应的按钮。

4. **不指向不存在的地方**
   提示「去 X 页面做 Y」之前，先确认 X 页面真有 Y 入口。
   （踩过：让用户「去学习库整理知识点」，而那里没有这个入口）

5. **遇到需要用户决定的岔路就停下来问**
   （接口形状、是否摘掉某功能、是否改动数据模型）

6. **保持轻量**：优先精确读文件片段和 grep，不要整库扫描
