## 三、⚠️ 三个「断言没报、截图报了」的 bug（本轮最重要的一节）

这一轮再次印证了那条最高优先级约束：**断言全绿不算交付**。
首轮 CDP **32/32 全绿**，然后看截图发现三个真实问题。

### 1. 三个章各显示「0 / 26」，标题栏「0 / 78」

**根因**：用户库那条 v2 路线是 AI 对**同一章**做的三段细分 ——
三步都是 `chapterNumber: 1`：

```
ch=1 信号的描述与分类      basis=model
ch=1 基本连续信号与运算    basis=model
ch=1 系统的描述与线性时不变性 basis=model
```

`drillSections` 按章号匹配（`byNumber.get(ch.number)`），于是**三步
都命中同一个切分章、都拿到全部 26 个小节** → 26 × 3 = 78。

**为什么断言没抓到**：它们查的是「章数对不对」「分不分叉」，
**没有一条查「小节总数对不对」**。而 78 这个数字只在标题栏和
每章的「几/几」里，断言恰好都没读那两处。

**修法**（`tree-build.ts`）：先把同号的多步认出来，再**分摊**小节
（`shareSections`：均分，余数给前面的份，26 → 9/9/8）。

**为什么用均分而不是按标题对齐**：小节标题是 `1.1`/`1.2`（资料编号），
步骤标题是「基本连续信号与运算」（AI 起的名），字面完全不同，
没有可靠的对齐依据。均分至少保证**不重复、不漏**。
第 3 步做完（AI 给真正的小节结构）后不需要分摊。

**反向验证**：把 `shareSections` 改回 `[...match.sections]` → 3 条测试红。

### 2. 卡片里显示「## 1.0 引言」

**根因**：`section-split.ts` 把**整行**当 title 存，而那行是
MinerU 转出来的 markdown（`## 1.1 连续时间和离散时间信号`）。
两个井号就明晃晃露在卡片上。

**为什么断言没抓到**：断言查「有没有标题」，没人查「标题长什么样」。

**修法**：加 `cleanHeadingText()`，只剥**行首** `#{1,6}\s*`
（正文里的 `C# 入门` 不能动）。**5 条新测试**守着，含一条
「正文里合法的 `#` 不能被剥」的反向验证。

### 3. 点小节后详情面板在屏幕外

**根因**：树有 9–26 个小节、比一屏高，详情面板挂在树**下方**。
用户点一个小节，面板出现在屏幕外 —— 看起来就是「点了没反应」。

**为什么断言没抓到**：只查了 `detail.has`（DOM 里有），
**DOM 里有不等于用户看得见**。

**修法**：`scrollIntoView({ block: 'nearest' })`。
用 `nearest` 而不是 `start`：面板已在视野内时不该把它硬拽到顶部。

**加了断言**：`getBoundingClientRect()` 判断面板是否真在视窗内。

### 顺带修的视觉问题

首版把章→小节的枝画成**朱砂红 + 2px**，9 条枝从同一个点扇出去 →
渲染成**一大团红**，分叉全糊了，比不聚焦更乱。
改成 `line-strong` + 1.75px，朱砂留给主干与选中态。

## 四、设计决定（下一任别推翻）

### 4.1 布局坐标是**算**出来的，不是**量**出来的

`tree-layout.ts` 出坐标，`RouteTree.tsx` 用 inline style 挂
`left/top/width/height`。**CSS 里不许写卡片宽高。**

理由：SVG 连线与卡片必须严丝合缝，差 2px 就像断线。
`getBoundingClientRect()` 的三个问题：首帧量不到（DOM 没布局完）、
缩放要重算、jsdom 里量不到（单测不了）。

代价：尺寸只在 `TREE_METRICS` 一处定义。改尺寸去那里，别改 CSS。

### 4.2 根节点位置**不随展开变化**

根垂直居中于**章那一列**，不是居中于整图。
否则展开一个靠下、小节多的章时，根会突然下移，视线被拽走。
**反向验证过**（改成按整图居中 → 2 条测试红）。

### 4.3 小节居中与不越界**有冲突**，取了后者

第 0 章的章中心只有 34px，3 个小节高 182px。真居中就要 `top = -57`，
负坐标会被 SVG viewBox 裁掉。所以：**能居中就居中，不能就贴顶**。
代价是第一节多时分叉点偏上一点，视觉上反而像「从章往下扇开」。

### 4.4 统计是**三态**，不是数字

`StatCount = { kind:'count', n } | { kind:'unknown' } | { kind:'stale', n }`

用户库「信号与系统」**10 道题的锚点全部失效**
（实测 `anchorMatchedToThisSource: 0`）。照常算会显示「0 道题」，
用户会以为一题没做。所以 `stale` 要带上真实总数并如实说明原因。

**反向验证过**（把 stale 退化成 count 0 → 2 条测试红）。

这与 `RouteBoard` 里已有的 `anchorHealth` 是同一套处理。

### 4.5 同章号多步 → 均分小节

见第三节 1。**这是这一轮最容易被"顺手优化掉"的地方** ——
看起来"每步都拿全部小节"更简单，但那正是这个 bug。

### 4.6 折叠默认 + 点章聚焦

用户原话「点章后局部放大，只专注该章和它的小节」。
折叠默认（一次看 30 个小节看不清结构），点章展开，其余章 `opacity: 0.25`。

**前置提醒只提醒、不锁**：有前置未完成的章显示黄色提醒条，
但按钮**绝不 disabled**（用户明确说"章节可以同时进行"）。
CDP 有一条断言专门守这个（`chapterDisabled === 0`）。

### 4.7 三层动效降级

调研 StudyHub 的 `graph-sketch.css` 学来的，本项目原来一层都没有：

1. `prefers-reduced-motion` —— 前庭功能障碍用户
2. `forced-colors`（Windows 高对比度）—— **系统会忽略 opacity**，
   光靠 0.25 淡出在这里完全失效，改用虚线边框 + `GrayText`
3. 高对比度下 opacity 抬到 0.4 保底
