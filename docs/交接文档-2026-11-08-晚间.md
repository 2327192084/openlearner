## 一、最重要的一件事：公式渲染（本轮起因）

### 用户报的问题

读《信号与系统（第二版）第1章》时，第 1 页及后续页面看到：

```
$\rho v$ 为正比于汽车速度 $v$ 的摩擦力
```

用户判断是「MinerU 转出来的乱码」，要求「换底层渲染、换查看器」。

### 我的核查结论：**不是乱码，是缺渲染器**

把那份 PDF 的全部 36 页文本 dump 出来逐页看：

- MinerU 的输出是**标准 LaTeX**：`$v_{s}$`、`$\rho v$`、`$v_{e}$`、`$\frac{1}{2}$`
- 36 页里 36 页都有公式，写法规范
- **问题在阅读器把它们当纯文本显示**

所以没有按「换底层」做 —— 那会把一个渲染问题当成数据问题来修，
改了 OCR 反而可能把本来正确的东西弄坏。

### 修法：接 KaTeX

选型依据（按项目规矩先检索；对比数据来自
[这篇选型实测](https://m.blog.csdn.net/berry/article/details/154388046)）：

| | KaTeX | MathJax v3 |
| --- | --- | --- |
| 200 个公式首次渲染 | ~120ms | ~850ms |
| 体积 | ~100KB | ~300KB |
| 语法覆盖 | 95% 常用 | ~100% |

桌面应用 + 离线 + 教科书场景，KaTeX 合适。剩下的 5% 语法失败时**退回显示源码**
（`throwOnError: true` 由我们接住），比看到 KaTeX 的红色报错块好。

**新文件**：
- `src/v2/ui/render-math.ts` —— `splitMath` / `renderMath` / `renderTextWithMath`（纯函数）
- `src/v2/ui/MathText.tsx` —— 共享的渲染组件
- 两个都有完整单测（24 + 若干）

**接入范围（7 个页面）**：阅读器、知识库、整理知识点、做题页、我的题组、
考试页、复习全书、练习页错题列表。题干/选项/解析/参考答案/知识点语句/**引用块**全覆盖。

### 三个必须知道的坑（都写在注释里）

1. **`$$` 必须先于 `$` 匹配**。否则 `$$x$$` 会被切成「空 + $x$ + 空」，碎片化。
2. **跨行的 `$...$` 不当公式**（行内公式不跨行）。`价格 $5 到 $10` 这种要能安全跳过。
3. **渲染失败退回原文**，不显示报错块。

### 一个我犯的错（值得记）

第一次验证时知识库显示 `katex=0`，我差点认定「页面里没有公式」。
查下来是两个问题叠加：

- **我的检测正则写错了**：`new RegExp('\\$[^$]+\\$')` 里 `\\$` 变成 `$` 锚点，
  永远匹配不到。正确写法用字符类：`[$][^$]+[$]`。
- **真正漏掉的是引用块**：368 个 `$` 全在 `kb-point__quote` 里，
  我第一遍只改了知识点语句那一处。

> 教训：**验证脚本自己也会错**。`katex=0` 时先确认「页面上到底有没有公式」，
> 再判断渲染有没有生效。

## 二、本轮其它已完成的事

### 1. C1：错题闪卡导出 Obsidian（用户主力笔记软件是 Obsidian）

**方案：导出而不是内置复习。** 用户主力笔记是 Obsidian，考研大量公式。
所以错题闪卡的定位是**把卡片送进 Obsidian 的复习流**（插件负责调度），
本应用负责挑题与转格式。

**语法逐条对照官方文档**（不是猜的）：`st3v3nmw/obsidian-spaced-repetition`
的 `docs/docs/zh/flashcards.md`（raw.githubusercontent 不通，用 GitHub API 取 base64）。

| 插件规则 | 实现 |
| --- | --- |
| 多行卡正面/反面以**单独一行**的 `?` 分隔 | 用这个 |
| 卡片之间必须空行，否则会连成一张 | `join('\n\n')` |
| 需要复习的笔记要有 `#flashcards` 标签 | 文件顶部 |
| 行内 `$...$` / 块级 `$$...$$` | 同 KaTeX 语法 |

入口在**错题与待巩固**页的「导出到 Obsidian」按钮。
文件：`src/core/questions/obsidian-export.ts`（32 个单测）。

**真实导出发现并修掉的 3 个 bug**：
1. `$**A**$` —— Markdown 粗体被裹进公式，两边都不渲染
2. `|x[n]|^{-8126}` —— `²`(U+00B2) 不在 Unicode 上标区，按区间减偏移算成负数
3. `a³`、`1⁰` 根本没被包装 —— 上下标不在「明确符号」判断里

### 2. `dueAt` 改用本地日历（已知问题 3，拖了几轮终于修完）

原来取 UTC 日期。东八区下 **本地 00:00–08:00 算「昨天」**：
早上 7:50 和 8:10 是两个不同的日子；凌晨做的卡到期日按「昨天」推，早一天回来。

**之前一直以为「修它要迁移所有 dueAt」是误判。** 日期串仍是 `YYYY-MM-DD`，
语义没变 —— 变的只是「拿哪个串去比较」。已有复习记录一条都没迁。

新增 `todayLocal()`，7 处「今天」判定切过去。`addDays` **没动**
（它只做纯日期串加减，不涉及「今天是哪天」）。

> **这条 bug 只在凌晨 8 小时内显形**，所以藏了很久。中午验证不了。

### 3. 统计页数字对不上

截图发现：顶部「总卡片 16 张」，分布 0+9+0+1+0 = **10 张**。

根因：`masteryDistribution` 只遍历 `reviewRecords`，而
**从没点过的题在记录里没有条目**（记录只在第一次复习时创建）。
所以它永远数不到那 6 道没练过的题。

修法：接收 `cardPool` 按池子过滤 + 把池子里没记录的卡补进「未学」。
现在保证 `五档之和 == 池子大小`。

### 4. 数据不同步（用户报「删题后仍显示 15 张待复习，必须重启」）

根因：`cardPool` 是 `main.tsx` 在启动时算一次的 **props 快照**，之后永不更新。
`todayOverview(旧池子)` 照样数出 15。

修法三层：
1. `cardPool` 变成 App 内部状态，由 `refreshData()` 从 `loadCards()` 重新派生
2. 所有改题库结构的操作统一调 `refreshData()`
3. 自动刷新：切回学习库时、窗口重新获得焦点时

**用户明确说过不要手动刷新按钮** —— 做过一版太突兀，已删除，只保留自动刷新。

## 三、下一步：B（图片与文字分离）—— 已有调研结论，可直接开工

用户把这件事**分到新窗口做**。以下是本轮已经验证过的关键事实，
**新窗口不用重新验证**。

### 已确认：MinerU 的输出里已经带图片定位符

手动跑了一次 MinerU（`--tier basic -p 1-2`），它的 Markdown 输出长这样：

```markdown
<!-- page 1 of 36 -->

## 第1章 信号与系统
...正文...

![Image block](doc:87731df/tier:basic/page:1/block:7)

图1.1 含有电压源 $\pmb { v } _ { s }$ 和电容器

![Chart block](doc:87731df/tier:basic/page:2/block:3)
```

**关键**：`![Image block](doc:<sha256前7位>/tier:<tier>/page:<N>/block:<M>)`
这个 locator 精确到「第几页第几块」。

### 已确认：能按 locator 取回原图

```bash
mineru read "doc:87731df/tier:basic/page:1/block:7" --format image -o out.png
```

实测成功，拿到原教材的电路图（416×216，清晰完整，带 v_s / R / i / C / v_c 标注）。

`mineru read --help` 显示：`--format <markdown|image>`、支持 `--context N`、
`--locator`、`page/rN/ranges` 等选择器。

### 所以 B 要做的（按依赖顺序）

1. **解析 Markdown 里的图片引用**
   把 `![Image block](doc:...)` / `![Chart block](doc:...)` 从正文里抽出来，
   不当普通文字存。当前代码把它们当文本存了 —— **阅读器里会显示成坏链接**。

2. **新增存储分区存图片**
   `STORE_IMAGES` 之类，存 `{ sourceId, page, block, bytes 或 filePath }`。
   ⚠️ **必须走迁移三件套**（见第五节）。

3. **调 MinerU 取图并落盘**
   需要在 electron 侧加一个 IPC（现有 `electron/mineru.cjs` 已有 parse 通道，照着加）。

4. **阅读器渲染图片**
   - 最小版：「图文按原顺序分块展示」—— 图片插在它原来的位置
   - 完整版：版式还原（绝对定位）—— 工作量大，**建议先做最小版**

### ⚠️ 一个必须实测的风险

`mineru read` 的 locator 依赖 **MinerU 自己的文档库缓存**（`doc:<sha256>` 形式）。
需要验证：**清理缓存 / 换机器之后，这些 locator 还能不能取到图**。

如果不能，那图片必须在**首次解析时就取回来存进我们自己的库**，
不能留到「用户点开时再去取」。

### 一个已经被踩过的坑（先知道能省时间）

`mineru parse -o <目录>` 在**应用进程里会 Permission denied**
（服务以不同权限运行）。现在代码的做法是让它输出到默认位置，
再自己去找 `converted.md`。加取图 IPC 时沿用这个模式，不要指定自定义输出目录。

（和「今日」一样大）+ 浏览器默认灰底。

> **原生控件（button/input/select）的样式一律写层外，一条都不能留层内。**
> 包括 `appearance: none` —— 只写 `background: none` 不够。

按行号批量替换会错位（历史上改坏过两次）。**优先抽独立组件**。
