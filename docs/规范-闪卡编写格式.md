# 闪卡编写格式规范

> 这份文件是**写闪卡时的唯一标准**，也是导出到 Obsidian 的依据。
> 来源：2026-11-23 直接读用户 Obsidian 库里的真实闪卡文件归纳，
> 不是凭空设计；导出语法另外用插件的真实解析器实测过（见 §5）。

更新时间：2026-11-23

---

## 1. 一句话规则

**正面写"问题"，背面按行写"标记 + 内容"，标记只有四种，用哪个写哪个，不适用的直接省略。**

---

## 2. 单张闪卡的结构

```
闪卡 N｜标题                    ← 头部（可选，多行正面才有意义）
**题目**                       ← 正文（题目/条件/公式）
$$公式$$
问题句…

✅答案：…                      ← 必须有（没有答案的卡不能复习）
💡要点：…                      ← 可选，可多条
❌坑：…                        ← 可选
⚠️限制条件：…                  ← 可选
```

### 2.1 头部与标题

- 单行正面**不要写标题** —— 写了会和正文重复。界面上会看到同一句话出现两遍。
- 多行正面：第一行当标题，其余行当正文。这条规则界面（`splitFrontTitle`）与导出（`titleOfFront`）是同一份判据，两边不会打架。
- 标题建议不超过 40 字（导出时超长会截断并加省略号）。

### 2.2 四种标记行

| 标记 | 含义 | 什么时候写 | 界面颜色 |
|---|---|---|---|
| `✅答案：` | 答案 | **必写**。没有它这张卡没法复习 | 绿（`--ok`） |
| `💡要点：` | 解题要点/思路 | 有多步推理时写 | 蓝（`--info`） |
| `❌坑：` | 易错点 | 这题有典型错误时写 | 红（`--bad`），加粗 |
| `⚠️限制条件：` | 前提/适用条件 | 结论有边界时写 | 黄（`--warn`） |

规则细节：

- 标记后面的**冒号用中文全角 `：`**（半角 `:` 也认，但全角与用户库里现有文件一致）。
- 标记必须**在行首**，前面不要有空格或 `>`。
- 不写的标记**直接省略整行**，不要留 `💡要点：` 空着。
- 每条标记的内容可以是一句话，也可以是 `1. 2. 3.` 有序列表（多条要点用列表，不要重复写 `💡要点：`）。

### 2.3 公式

- 行内公式用 `$…$`，独立公式用 `$$…$$`。
- 公式里**不要用 `==`**（那是挖空标记，会打架）。
- 也不要写 `::`（见 §4.3）。

---

## 3. 挖空卡（本应用内的"翻面"）

在正面或背面用 `==…==` 包住要考的内容：

```
导数的定义是 ==差商的极限==。
```

- 界面上显示成 `[…]`，点一下显形 —— 这就是"翻面"。
- 一张卡**最多挖 2 处**，挖太多会变成"猜谜"而不是"回忆"。
- **不要把整个公式挖掉**：`==$x_4(t)=je^{(-2+j100)t}$==` 这种挖了等于什么都没给。
- 挖空内容里**可以有单个 `=`**（`==k=100==` 是合法的，实测确认）。
- `====`（空挖空）不合法，会原样显示。

## 4. 导出到 Obsidian 时的额外规则

### 4.1 版式

导出有两种版式，默认 **callout**（与用户库里现有闪卡文件同款）：

**callout 版式**（默认）：

```markdown
> [!tip] 闪卡 1｜题1.8‑d 复指数取实部格式转换
> **题目**
> $$x_4(t)=je^{(-2+j100)t}$$
> 将 Re 表示为 Ae^{-at}cos(ωt+φ)
> ✅答案：==$e^{-2t}\cos(100t+\frac{\pi}{2})$==
> 💡要点：$j=e^{j\frac{\pi}{2}}$
> ❌坑：不能直接把虚数 $j$ 当作实振幅 $A$
```

**review 版式**（老式多行卡）：

```markdown
题1.8‑d 复指数取实部格式转换
?
✅答案：$e^{-2t}\cos(100t+\frac{\pi}{2})$
```

### 4.2 必须留真空行

插件的断卡规则是"**空行结束一张卡**"。所以：

- 标签行 `#flashcards` 与第一张卡之间**必须有一个空行**；
- 卡与卡之间**必须有一个空行**；
- **绝对不能用 `>` 分隔两张卡** —— 会把它们并成一张，而且后一张的答案会漏进前一张的正面。

这三条都是实测出来的（见 §5），不是猜的。

### 4.3 正文里的危险字符会被自动处理

| 危险写法 | 后果 | 导出时的处理 |
|---|---|---|
| `std::cout`（正文含 `::`） | 被当单行卡分隔符，正面被截断 | 插入零宽空格打断 |
| 正文某行只有一个 `?` | 被当多行卡分隔符 | 改成行内代码 `` `?` `` |

处理过的文件会把处数写在导出提示里，不会静默改字。

### 4.4 标签 → 卡组

- 闪卡的标签写成 `高数`、`信号与系统` 这样的短名（**不要带 `#`**）。
- 导出时每个标签成为一节 `#flashcards/<标签>`。
- **一张卡有多个标签时只进第一个卡组** —— 写进两节会让插件里出现两张同名卡，复习时被排两次。
- 没打标签的卡落在默认卡组 `#flashcards`，导出提示里会报数量。

## 5. 为什么这些规则是这样（取证依据）

2026-11-23 把 Obsidian Spaced Repetition 插件**已发布的** `main.js`
（sha256 `e2af1a34…`，与 Release digest 逐字节一致）切片成可执行 harness，
用它自己的 `parse()` / `CardFrontBackUtil.expand()` 跑了 40+ 个用例。
完整取证在 `.tmp/sr-verify/FINDINGS.md`，复现：
`node .tmp/sr-verify/build_harness.cjs && node .tmp/sr-verify/run_cases.cjs`。

九条关键结论（1.9.0 → 1.15.4 三版一致）：

1. **纯 callout 里没有 `==…==` 或分隔符 → 0 张卡**。callout 写 `> ?` 也是 0 张 —— 多行分隔符要求整行 trim 后**完全等于** `?`，`"> ?"` 不等于 `"?"`。
2. `#flashcards` 标签只决定"扫不扫这个文件 / 归哪个卡组"，**不决定"这段文字是不是卡"**。
3. callout 里某行含 `==…==` → **1 张 Cloze 卡**，整段 callout 合成一张，`> ` 前缀无害。
4. **一个 callout 里 N 个 `==…==` → 展开成 N 张独立卡**。所以导出时只包一处。
5. 裸 `??` 一行 → 自动生成反向卡（正反各一张）。
6. 标签行会被**吸进卡片正面**（`#flashcards / ? / 答案` 实测 front = `"#flashcards"`）。
7. 卡之间用 `>` 分隔 → 两张并成一张，后一张的答案漏进前一张。
8. 行内 `::` 是**子串**匹配，不是整行 —— `std::cout` 会被切。
9. Anki 的 `{{c1:…}}` 不支持，且会被 `::` 静默劈成垃圾卡。

> ⚠️ 任务里提到的 `src/parser/`、`src/regular-expressions.ts`、`SINGLE_LINE_CARD`
> 等常量名在 1.15.4 与 1.9.0 **都不存在**，属于多年前的旧结构（网上博客仍在抄）。
> 真解析器是 `src/parser.ts`，逐行字符串比较，不是大正则。

## 6. "让 Obsidian 的闪卡翻面"——四条路的实话

用户问：「有没有技术方法可以让 obsidian 的闪卡实现翻面」。

| 方案 | 能不能翻面 | 有没有复习排期 | 代价 |
|---|---|---|---|
| **A. 原生折叠 callout** `> [!answer]-` | ✅ 点标题展开 | ❌ 没有 | 折叠时正文被隐藏，用户会以为内容没了；插件完全不解析折叠标记（实测无害） |
| **B. 挖空卡** `==答案==` | ✅ 显示 `[…]`，点开显形 | ✅ **有** | 需要装插件；一张卡只能挖有限处 |
| **C. `??` 双向卡** | ✅ 正反两张自动生成 | ✅ 有 | 只适用 review 版式；会翻倍卡数 |
| **D. 换 Obsidian Decks 插件** | ✅ 原生翻面 UI | ✅ 有 | 换生态，与现有库不兼容 |

**当前实现的选择**：默认 callout 版式 + 答案包成 `==…==`（方案 B）。
理由：这是唯一"既翻面、又有排期、且与用户库里现有格式几乎不带改"的组合 —— 只多 4 个字符。

**必须说清楚的实话**：用户本机**目前没装** Spaced Repetition 插件
（`.obsidian/plugins/` 只有 `nutstore-sync`，`community-plugins.json` 为 `[]`）。
所以现在导出的文件只是普通笔记，**翻不了面也复习不了**，装上插件之后才生效。
界面提示里已经这么写了，不宣称"导出就能复习"。

## 7. 给 AI 的模板（生成闪卡时用）

提示词里已经内置这些规则（`src/core/ai/make-flashcards.ts` 的 `buildCardPrompt`）。

```text
## 背面的写法（必须照这个格式，复习界面按它渲染）

- `✅答案：` 必写，一句话给结论
- `💡要点：` 有多步推理时写，多条用 `1. 2. 3.` 列表
- `⚠️限制条件：` 结论有边界时写
- `❌坑：` 这题有典型错误时写
- 不适用的标记直接省略，不要硬凑
- 单句正面不要硬加标题
```

挖空卡用 `buildClozePrompt`：要求 `==…==`，一张最多 2 处，不许整公式挖掉。

## 8. 检查清单（写完一张卡自查）

- [ ] 有 `✅答案：` 吗？
- [ ] 标记行都在行首、冒号是 `：` 吗？
- [ ] 用不上的标记删掉了吗（没有空标记行）？
- [ ] 单行正面**没有**多余标题吗？
- [ ] 公式里没有 `==` 吗？
- [ ] 正文没有 `::` 吗？
- [ ] 挖空不超过 2 处、没挖整个公式吗？
