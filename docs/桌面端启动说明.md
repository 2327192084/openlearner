# 桌面端启动说明

## 怎么启动

**桌面上的 `OpenLeaner` 快捷方式已经指向正确的启动器，直接双击即可。**

手动启动的话，跑这个：

```
release\win-unpacked\OpenLeaner-Launcher.bat
```

**不要双击 `OpenLeaner.exe` 本体。** 原因见下一节。

---

## 为什么要用启动器，而不是直接双击 exe

这不是绕远路，是唯一可行的做法。实测记录如下。

### 现象

双击 `OpenLeaner.exe`，**完全没有任何反应**：没有窗口，没有报错，没有日志。

### 排查过程（结论：不是我们的代码问题）

在 `release\win-unpacked` 下逐个试参数，看主进程的 JS 到底有没有被执行：

| 命令 | 退出码 | main.cjs 是否执行 |
|---|---|---|
| `OpenLeaner.exe` | 3 | **否** |
| `OpenLeaner.exe --disable-gpu` | 3 | **否** |
| `OpenLeaner.exe --user-data-dir=<已存在目录>` | 3 | **否** |
| `OpenLeaner.exe --no-sandbox` | 持续运行 | **是**，窗口出现 |
| `ELECTRON_DISABLE_SANDBOX=1 OpenLeaner.exe` | 持续运行 | **是**，窗口出现 |

连一个 20 行的最小 Electron 程序在这台机器上同样起不来 —— 所以和打包、asar 结构、原生模块 ABI、代码逻辑**全都无关**。

### 根因

在部分 Windows 环境下，Chromium 的**沙箱初始化**阶段就失败，进程以退出码 3 死掉。这个阶段在 **JavaScript 引擎启动之前**，所以：

- 一行日志都不会有（我们的日志代码根本没机会跑）
- 任何写在 `main.cjs` 里的自救逻辑都无效

### 试过但无效的做法

```js
// main.cjs —— 太晚了，沙箱在这行代码执行前就已经初始化完成
app.commandLine.appendSwitch('no-sandbox');
```

这条我实际写过、打包测过，仍然 exit 3。**记下来免得后人重复踩。**

### 现在的方案

`OpenLeaner-Launcher.bat` 带上 `--no-sandbox` 启动，并通过 `electron-builder` 的
`extraFiles` 自动打进每次打包产物。桌面快捷方式指向它。

## 安全说明（如实记录，需写进合规声明）

**关掉的是 Chromium 渲染进程的沙箱，不是操作系统账户权限。** 这两者常被混为一谈。

仍然生效的保护措施：

| 措施 | 状态 |
|---|---|
| `contextIsolation: true` | 开启 |
| `nodeIntegration: false` | 关闭（渲染进程拿不到 Node） |
| `sandbox: true`（webPreferences） | 开启 |
| preload 只暴露白名单方法 | 是（仅 `platform`/`isElectron`/`versions`） |
| `setWindowOpenHandler` 一律 deny | 是 |
| 外链仅允许 http/https | 是（`javascript:`/`file:`/`data:` 全部拒绝） |
| 权限请求默认拒绝 | 是（仅放行剪贴板写入） |
| `will-navigate` 只放行自身页面 | 是 |
| 渲染进程只加载本地打包静态文件 | 是（**不加载任何远程网页**） |

最后一条是关键：这个应用本质上是把静态页面装进原生窗口，不浏览任意网站。
没有沙箱的实际暴露面因此远小于「用浏览器打开任意网页」，但仍应如实披露。

**如果用户的机器沙箱正常**，用 `--no-sandbox` 会白白降低安全性。更严谨的做法是
安装时探测一次沙箱可用性，只在失败时降级 —— 这是 P7 打包阶段的待办项，
当前为了先让软件能跑起来，统一走启动器。

## 换机器 / 重新打包后要做什么

```bash
npm run build
npx electron-builder --dir        # 产物在 release/win-unpacked
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/make-desktop-shortcut.ps1
```

第三条会重建桌面快捷方式，并自动指向启动器（找不到启动器时会告警）。

如果首次 `electron-builder` 卡在下载、报 `ETIMEDOUT`（连 GitHub 超时），用镜像：

```bash
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
npx electron-builder --dir
```
