> 让用户自己决定。然后我设想的地图应该是和图二的树状图一样的，从资料延伸出

| 问题 | 用户选择 |

## 三、数据模型（零迁移）

### 3.1 路线树存 `settings.sourceTree`

```ts
interface SourceTree {
  subject: string;
  edition: string;
  sourceId: string;
  chapters: ChapterNode[];
  /** 资料外的后续（沿用现有 beyond 语义，如实告知"资料里没有"） */
  beyond: { title: string; note: string }[];
  usedSearch: boolean;
  savedAt: string;
}

interface ChapterNode {
  /** 章号；0 = 认不出章号（pptx 那种） */
  number: number;
  title: string;
  /**
   * 前置章号（AI 给）。
   *
   * ⚠️ 只提醒、不锁 —— 用户明确要求「章节可以同时进行，不用按顺序」。
   */
  prerequisites: number[];
  /** 为什么需要这些前置（给用户看，AI 生成） */
  prereqReason: string;
  /** 难度 1-5。沿用 v2 口径：内容本身有多难，不是掌握度 */
  difficulty: number | null;
  /** 依据来源：目录 / 检索 / 模型推断 */
  basis: 'toc' | 'search' | 'model';
  sections: SectionNode[];
}

interface SectionNode {
  /** `sec_<uuid>`，稳定标识 */
  id: string;
  title: string;
  /** 该小节覆盖的段 id（用于统计与跳转） */
  segmentIds: string[];
  /** 来源：正文标题切出 / AI 拆 / 整章退化 */
  origin: 'heading' | 'ai' | 'whole-chapter';
  tasks: SectionTasks;
}

interface SectionTasks {
  /** 任务一：外部资料（网课/文档），可多条 */
  resources: {
    id: string;
    title: string;
    url: string;
    source: 'search' | 'manual';
  }[];
  /** 任务一是否完成（看过了） */
  resourceDone: boolean;
  /** 任务二：闪卡是否学完 */
  flashcardsDone: boolean;
  /** 任务三：习题是否做完 */
  exerciseDone: boolean;
  /** 用户自定义任务 */
  custom: { id: string; text: string; done: boolean }[];
}
```

**为什么任务状态存路线里而不是新表**：

- 一条路线一次写入天然原子
- 新建表要动迁移四件套（`STORES` / `BACKUP_STORES` / `StoreRecordMap` / `DB_VERSION`）
- 这些状态**只对这一条路线有意义**，重排路线后旧状态本就该失效

**为什么不存闪卡 id 列表**：闪卡与知识点是两条独立数据（`Flashcard` 的注释明确写了"闪卡是独立的，不会因来源消失而消失"）。存 id 列表必然与闪卡表漂移。改成**按知识点反查**（`flashcards.ts:251` 已有这个能力）。

### 3.2 外部资源存 `settings.sourceResources`

```ts
interface SourceResource {
  id: string;              // `res_<uuid>`
  sourceId: string;
  title: string;
  url: string;
  /** 来源标注：与 LogiNote 截图的「LLM 联网收集 / 人工整理」对应 */
  source: 'search' | 'manual';
  addedAt: string;
  note?: string;
}

// settings.sourceResources: Record<sourceId, SourceResource[]>
```

### 3.3 旧数据兼容

读取顺序：

1. `settings.sourceTree` 存在 → 直接用
2. 否则 `settings.sourceRoute`（v2 扁平三块）存在 → **纯函数转成树**：
   - 每个 `block` 的每个 `step` → 一个 `ChapterNode`
   - `sections` 靠正文标题现切（信号那份能切 26 个）
   - 切不出 → 单个 `origin: 'whole-chapter'` 节点
3. 都没有 → 空状态

**转完不删旧数据**（保留回退余地）。

## 四、小节提取：`src/v2/core/section-split.ts`

### 4.1 三种标题写法（实测）

| 写法 | 出现于 | 正则 |
|---|---|---|
| `## 1.1 连续时间和离散时间信号` | 信号与系统（26 个，含 1.1.1） | `^#{1,3}\s*([0-9]{1,2}\.[0-9]{1,2}(?:\.[0-9]{1,2})?)\s*(.+)$` |
| `## 1. 映射概念` | 高等数学（8 个，章内序号） | `^#{1,3}\s*([0-9]{1,2})[.、]\s*(.+)$` |
| `1.1 极限`（无 `#`） | 纯文本资料 | `^([0-9]{1,2}\.[0-9]{1,2}(?:\.[0-9]{1,2})?)\s+(\S.+)$` |

### 4.2 ⚠️ 最容易写错的一条：小节必须落在自己的父章里

高等数学每章都有「1.」「2.」「3.」——**章内序号**。
按编号全局分组会把第 2 章的「1. 导数的定义」错归到第 1 章。

**算法：一遍扫描 + 记住当前章**

```
for 每段:
  for 每行:
    认出章标题  → 开新章，小节清空
    认出小节标题 → 挂到「当前章」
    都不是      → 归到「当前小节」
```

绝不按编号分组。

### 4.3 AI 兜底

以下情况走 AI 拆：

- 该章切出的小节 < 2（0 个或 1 个）
- 整份资料无标题（pptx）

提示词写死两条（沿用 `prompts.ts` 已验证的防护）：

- 只能按**这一章已有的正文**拆，不许引入资料外内容
- 每个小节必须给 `quote`（原文片段），用于本地回填 `segmentIds`
  —— 这样「依据资料」是可验证的，不是口号

### 4.4 退化

既切不出、AI 也拆不出 → `origin: 'whole-chapter'` 单节点，
界面如实写「这一章没有小节结构，按整章学」。

## 五、树状地图 UI：`src/v2/ui/RouteTree.tsx`

### 5.1 视觉（对齐用户给的图二）

- **纵向树**：资料根节点 → 章节点 → 小节节点（层级从左到右展开）
- 节点是**卡片**（圆角 + 边框）
- 连线用 **SVG 贝塞尔**（CSS 画不出分叉）
- 默认**只展开章级**；点章 → 展开它的子树
- **点章后聚焦**：其余章 `opacity: 0.25` 淡出，只显示该章及其小节

### 5.2 为什么用 SVG 而不是纯 CSS

一个章节点连多个小节 → **分叉**。CSS 的 `border` / 伪元素只能画直线段。
SVG overlay 按布局算出的坐标画贝塞尔，且**布局是算出来的不是测出来的**，
所以不依赖 `getBoundingClientRect` 也能准。

### 5.3 章节点显示什么

- `3/5 小节完成`
- 难度角标
- **前置未完成时**：显示提醒条「建议先学第 N 章 —— <AI 理由>」
  - 但**仍然可点**（用户明确要求可并行）

### 5.4 小节已完成判定（界面层）

```
三项任务都勾（resourceDone && flashcardsDone && exerciseDone）
  && 所有自定义任务都勾
  → 显示「完成」
```

**不做任何自动判定**（用户明确要求交给用户）。

## 六、小节详情面板

四块，顺序按用户的任务流：

### 6.1 任务一：外部资料

- 规划时搜好的链接列表（标题 + 域名 + 来源标注「联网收集」）
- 「+ 添加」手工补（标「人工整理」）
- 勾「已看过」

### 6.2 任务二：闪卡

- 显示该小节对应知识点的闪卡数 / 已学数
- 反查方式：该小节段落 → 知识点（`KnowledgePoint.anchors[].segmentId`）→ 闪卡（按 `knowledgePointId`）
- 「去学这些卡 →」跳闪卡页
- 勾「已学完」

### 6.3 任务三：习题

- 该小节段落对应的题目数
- 「去练这些题 →」跳做题页
- 勾「已做完」

### 6.4 自定义任务

`+ 加一条`，可勾可删。

## 七、外部资源栏

### 7.1 位置

`SourceReader` 的**右侧新栏**（左侧 `reader__toc` 已有目录）。

理由：资源是「边看边点开」的东西，与 LogiNote 一致；抽屉塞不下。

### 7.2 形态（照用户截图）

每条：

```
● 资源标题
  域名 · 来源标注（联网收集 / 人工整理）
  相对时间
```

点开 → 系统浏览器（走现有 `openExternalSafely`，**不新增网络通道**）。

### 7.3 用户自建入口（两处）

| 位置 | 归属 |
|---|---|
| 阅读器右栏「+ 添加资源」 | 资料级 |
| 小节详情「+ 添加资源」 | 挂到该小节 |

### 7.4 表单（只有网址必填）

| 字段 | 必填 | 行为 |
|---|---|---|
| 网址 | ✅ | 粘贴后**自动抓标题**；抓不到不阻塞 |
| 标题 | ❌ | 留空时逐级回退：抓到的标题 → 域名 → 完整网址 |
| 备注 | ❌ | 如「第 3 节看这个视频」 |

### 7.5 坏输入处理

| 情况 | 处理 |
|---|---|
| `javascript:alert(1)` | 拒绝，说明「只支持 http/https 网址」 |
| `file:///C:/...` | 拒绝（同上） |
| 无协议头 `www.bilibili.com/x` | **自动补 `https://`** |
| 完全不是 URL | 拒绝，**保留输入框内容**不清空 |
| 重复网址 | 提示「这条已经在列表里了」，不新增 |

### 7.6 删除

- 每条可删（悬停出删除按钮）
- **资料删 → 资源跟着删**（用户确认）
- 小节被删 / 路线重排 → 挂在小节上的资源**回到资料级**，不丢

## 十四、从 LogiNote 学到的两条（调研结论）

调研了 `GlimmerElve/LogiNote-Chinese-version-`，
**主应用不在该仓库**（只有 `apps/community-api`、`apps/community-web`、`apps/android`），
所以用户截图那个「学习资源」栏的源码**拿不到**。

但有两条设计值得吸收：

### 14.1 外部链接先弹确认框（`apps/community-web/src/LinkSafety.tsx`）

LogiNote 打开外链前先弹窗显示**域名 + 完整地址**，并提示
「请核对网址，谨防仿冒网站。不要向不可信网站提供密码、验证码等敏感信息」，
用户点「继续访问」才真的跳。

**对我们的意义**：我们的 `openExternalSafely` 是**直接跳**。
用户自建资源意味着 URL 可能来自任何地方（复制粘贴、别人发来的），
加一个确认框成本很低、价值明确。

**建议**：用户添加的资源在打开时先弹确认（联网搜来的可以直跳，
因为是我们自己查到的）。

### 14.2 资源包校验的严格程度（`apps/community-api/src/resourceFormat.ts`）

它的 `validateResourceManifest` 有几条值得学的思路：

- **白名单式字段校验**：`keys(value, allowed)` —— 出现未允许字段直接拒绝
  「资源包含未允许的字段，请重新导出」
- **正文里禁止本机路径**：`check(!/(?:file:\/\/|(?:^|[\s("'=])[A-Z]:[\\/]|\\\\[^\s\\]+\\)/i.test(value))`
  —— 防止把一个用户的本地路径泄露给别人
- **层级必须无环**：`hierarchy()` 用 `visited` 集合检测循环引用

**对我们的意义**：第 2 条与第 3 条对「用户自建资源」有直接价值 ——
如果以后要支持导出/分享，正文里混入本机路径是真实风险。
