## 四、⚠️ 重大方向变化：扫描件 PDF / OCR（用户已拍板）

**这一节与夜间文档第十节的结论冲突，以本节为准。**

### 用户说了什么

- m02051 原话：「不行，我们项目里的 **ocr 模型完全不能用**，你可以试着用它识别下资源库里的 pdf 文件看它能不能输出文档。所以文档识别这一块**我们参考 studyhub 的方案，采用本地部署开源模型进行识别。开源模型让用户在 Docling、MinerU、OCRmyPDF、Marker 这四个中选择**。」
- m02192：本轮只做删除资料 + 交接文档 → **OCR 四引擎的实现整体留给下一轮 / 下一个模型**。

### 实证：现有 OCR 为什么「完全不能用」

用一次性探针走项目真实依赖链（`pdfjs-dist/legacy` 渲染 → `@napi-rs/canvas` → `tesseract.js` + `public/tesseract/` 本地 chi_sim，等价于 `LocalTesseractBackend` + `OcrService` 的核心）：

| 样本 | 结果 |
| --- | --- |
| `src/test/fixtures/scanned.pdf`（合成扫描件，3 页 / 9 图 / 0 字体） | 3 页共 498+354+308 ms，置信度 92/91/89，内容正确。→ **干净合成件能出字**，但 RAW 满是「第 一 章」「操作 。」「信和号」这类插空格/错字。 |
| 桌面真实 45MB《信号与系统》PDF（43.1MB / **628 页 / 628 图 / 0 字体 / 31 DCTDecode**，纯扫描教材） | 抽 5 页：封面置信度 **36**（乱码）；第 2 页混排英文全错（"Sisnals and Systemis"）且报 `jbig2.wasm` 加载失败；第 5 页错字密集；第 20 页目录页码全乱（OCR **16 秒**）；第 50 页正文公式图表全丢。5 页合计 **46,667ms / 4,388 字符** → **整本 628 页约 5,861 秒 ≈ 1.6 小时**。 |

结论（**写进交接文档的事实，别再争论**）：

1. 封面/混排/图表页置信度 36–75、错字成片；
2. **1.5–16 秒/页，整本 1.6 小时**，不可接受；
3. **只输出纯文本**，不给版面、标题层级、表格、公式、bbox，也不产出「文档」或分页标记 —— 而 StudyHub 路线要的正是这些；
4. `grep -rln "OcrService\|checkOcrReadiness\|LocalTesseractBackend\|本地识别" src/pages/ src/v2/` → **NO MATCH**，v1/v2 界面根本没有 OCR 入口。

→ 用户「完全不能用」成立。**不要再试图修/调 tesseract，方向已改成本地部署开源模型。**

### 下一轮要做的方向（已定，不是待拍板岔路）

- **参考 StudyHub 4.4.3**：MinerU 在**本机**运行、不上传、不需令牌（云端版已在 3.5.5 移除）；一键安装六步 = 下 uv（校验 sha256）→ uv 装 Python 3.12 → pip 装 `mineru>=4.0,<5` → 下模型 → 起本机服务 → 自检；下载约 1.3GB / 占约 4GB / 10–30 分钟，可取消续装，全装在一个文件夹（`MINERU_HOME`），不写 `~/.mineru`。
- **四个引擎让用户选**：`Docling` / `MinerU` / `OCRmyPDF` / `Marker`。
  ⚠️ **不要再自作主张加 PaddleOCR、也不要把 Marker 排除** —— 这是用户点的名。但夜间调研查到的风险要如实摆给用户、由他决定：Marker 代码 Apache-2.0 而**权重是改良 OpenRAIL-M（限制商用）**、2.x 需 Docker；MinerU 是 Apache-2.0 **带附加条款**（月活 1 亿 / 月收 2000 万美元需另授权）且要常驻服务；OCRmyPDF（MPL-2.0）把文字层压回原 PDF、**页数布局不变，对我们的现有解析器零改动**；Docling（MIT）`prov[].page_no` **从 1 开始**、每元素带 bbox、CPU 约 3.1 秒/页。
- **不照抄 StudyHub「转换后另存文档、丢掉原 PDF」**：我们定位是「每条都点回原文」，anchor 是 `{sourceId, page, charStart, charEnd}` 且 `charStart/charEnd` 是**页内偏移**。只要文字**按页写回 `sourceSegments`**，页码映射天然 1:1，不需要「转换页 → 原页」对照表，也不用碰 PDF 原始字节（避开 pdfjs detach ArrayBuffer 的坑）。
- **安装体验**照抄 StudyHub 的 uv 六步（自带 Python、sha256、可取消续装、单文件夹、失败只给一个修复按钮）。

### 已确认的环境事实（下一轮直接用）

- 本机 `Python 3.13.1`、`uv 0.12.13 (2026-09-10)` 可用；**`python3` 命令不存在**。
- `electron/main.cjs` 只有 `ipcMain.handle('openleaner:chat-completion', ...)`（:462）**一个 handler，没有 `child_process/spawn`** → 桌面版调本机 Python 转换器必须新增 IPC + spawn，并把 Python 环境放进 `resources/` 或首次运行时安装。**这是打包链路的新风险点，动手前跟用户确认要不要现在就走。**
- `src/core/parsers/text.ts:128`：导入 MD/TXT 时 `pageCount: 1`、**页码是按段编的，不是真实页** → 接转换器的分页输出必须新增「带分页标记的 Markdown 解析」（`<!-- page: N -->` / MinerU `content_list.json` / Docling JSON）。
- 扫描件 `textStatus: 'no-text-layer'` 与 `'decode-failed'`（有字但缺 cMap）**严格分开**（`src/core/parsers/types.ts:26-44`，有测试断言后者 hint 不能出现「换一份电子版」）。
- `src/core/ocr/service.ts` 的「逐页渲染 → VisionBackend → 写回 segments + textStatus」骨架、`checkOcrReadiness()`、中途停止保留已识别页仍然可用 —— 换引擎时**这套写回逻辑可以复用**，别整个删掉。
- Node 下 pdfjs 6 的三个坑（探针里踩过）：① `CanvasFactory` 要有 `getNoAlphaContext(canvas)`；② `page.render` 必须传 `canvas: null` + `canvasContext` + `canvasFactory`（同时传 canvas 与 canvasContext 会被忽略）；③ `wasmUrl`/`standardFontDataUrl` 必须是**带尾斜杠**的 `file:///.../` URL（否则 `Invalid factory url ... must include trailing slash`）。
- 现有依赖：`pdfjs-dist ^6.5.438`、`tesseract.js ^7.0.0`、`@tesseract.js-data/chi_sim ^1.0.0`、`@napi-rs/canvas`；`public/tesseract/` 资源齐全。`scripts/verify-p7-local-ocr.cjs` 历史上只验过「canvas 上手写 7 个字」，**没测过真 PDF**。

## 八、验证方式（必须遵守，别退回「看 DOM 就下结论」）

- **改界面 → 必须 CDP 截图**（`Page.captureScreenshot`）并肉眼复核。
- **改数据流 → 必须查 IndexedDB** 确认真写进/真删掉（`indexedDB.open('openleaner')`，`DB_VERSION = 4`，每分区 `keyPath: 'id'`）。
- 自动化点击前，目标在折叠分组里要先展开（如「统计」在「阶段性」下）。
