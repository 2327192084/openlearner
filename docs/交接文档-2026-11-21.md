## 二、⚠️ 清理用户库 29 条坏数据（`c7932db`）

**授权**：用户原话「先把坏数据请了」。

### 问题

`question.knowledgePointId` 应指向 `knowledgePoints`，实测 **29 道题指向不存在的 id**：

| 类型 | 条数 | 来源 |
|---|---|---|
| `variant:q_xxx` | 19 | 变式题造出的伪 id（`questions/variants.ts:176`） |
| `seg_xxx` | 10 | 段落 id 被误写成知识点 id |

代码 2026-11-09 已修（`service.ts:532` 只在 `origin === 'knowledge'` 时写），
**但旧数据没迁移** —— `migrations.ts` 只处理**备份文件版本升级**，不清库内坏数据。

### 为什么置 null 而不是回填

先做回填探测，结论：**29 条一条都回填不了**。

- `variant:` 的原题已不在库里
- 锚点位置匹配也对不上：这些题锚点是 `charStart:0 / charEnd:整段`，
  而知识点锚点是真句子偏移（44~144 字），不可能相等

硬凑 id 就是编数据。项目一贯：**如实写 null，不给假 id**。

## 三、跨资料全文搜索（四轮迭代，`8097785` → `091b1ce`）

交接文档 6.3 列为「建议的下一项」，理由是只能在某一本书里搜。

### 迭代 1：基础版（顶栏搜索框）

- 新增 `getAllSegments()` **一次读全表** —— 循环 `getSegments(sourceId)` 是
  O(资料数 × 全表)（它内部每次 `getAll` 再过滤）
- 纯函数 `src/v2/core/global-search.ts`
- **顺带修掉真 bug**：`ReaderTarget` **根本没有 `segmentId` 字段**，
  导致阅读器只能按 page 猜段（page 在一份资料里不唯一）。
  实测现象：点搜索结果进了阅读器、页码对了、**正文没有任何高亮**。

### 迭代 2：打磨（实测发现的三个问题）

| 问题 | 实测证据 | 修法 |
|---|---|---|
| **静默截断**（说假话） | 搜「的」实有 **2365 处**，界面显示「共 500 处」 | 拆 `matchCount`（真实）/ `total`（展示） |
| 第一本书吃光额度 | 高数 515 处占满 500 条，另两本（566/1284）一条不列 | 按 `floor(limit/有命中的资料数)` 保底配额 → 167/167/166 |
| 500 条平铺滚不动 | 面板限高 620px | >80 命中时每组默认列 3 条 + 展开 |

### 迭代 3：独立成页（用户要求改 UI）

用户原话：「新开一个功能栏在课程准备与管理那里，界面参考 Google 或是 bing」。

借三样：居中大搜索框（620px，顶栏的 1.9 倍）、**命中概览分布条**、结果三段式。
不借：输入即搜（会卡）、相关性排序（本地无词频模型，硬造不可解释）。

**坑**：`.page` 是 flex 容器，`.spage` 作为子项默认按内容收缩 →
搜索框实测只有 279px（比顶栏 329px 还窄）。修法：显式 `width: 100%`。

### 迭代 4：搜索历史（用户给参考图）

上限 10 条、归一后去重、**只记搜出结果的词**。

### 迭代 5（B 组）：同页归并

搜「极限」前 6 条全是「第 11 页 目录」→ 同页多处合成一行（标「本页 N 处」），

| 轮次 | 做法 | 结果 |

| 第一轮 | 把题干当 `quote` 传给阅读器 | 题干不在原文里，匹配不上 → 只到页 |

从原文出题只能是整段。用户自己已验证过（`deck_0f24e` 那 2 道题锚点 47/57 字）。

### B2 的意外结论：知识点 → 原文的句级定位**本来就是对的**

## 六、这一轮踩的坑（都是新的，接前几份）

1. **断言与界面的时差**（两次）
   - 点搜索结果后只等 `.reader-page` 就查 mark → 查到 0（高亮是第二步 effect 画的）
   - 搜第二个词后只等「有摘要元素」→ 上一次的摘要还在 DOM 里，假通过
   **断言不能比界面快一步，也不能比它慢一步。**

2. **`.page` 是 flex 容器，子页面会按内容收缩**
   搜索框实测 279px（比顶栏还窄）。别处没暴露是因为内容够宽（表格、卡片把宽度顶开）。

3. **`46ch` 在中文里 ≈ 23 个汉字** —— 说明文字被挤成两行窄条，改 `560px`。

4. **模板字符串里的注释不能带反引号** —— 会提前结束字符串（语法错）。

5. **正则里的双反斜杠**：`/\\d+/` 在 JS 字面量里匹配「字面反斜杠+d」，永远命中不了数字。
   用 `[0-9]+` 更稳。

6. **`ReaderTarget` 缺 `segmentId` 字段** —— 调用方传了没人读（跨 props 传时多余字段被静默忽略）。

## 十二、给下一个接手的人

- **这一轮最贵的一条**：断言全绿之后仍必须看截图。这轮**五次**断言通过但界面是错的
  （搜索框 279px、说明两行窄条、整页标注、搜不到的词进历史、归并开关消失）。
  用户会亲自截图验收，而他看到的优先于你手上的计划。
- **抽样探测不能当全量结论**，尤其当结论是「不存在」时。
- **用户说「退一步」时，先想清楚折中方案长期看是否成立**。
  「整段也高亮」测试全过，但用户一看就说「整页不能叫段落」——
  因为他的资料一页就是一段。**折中方案要能被一眼验证**。
- **AI 功能的通用模式**（这轮多条经验可复用）：
  编号映射替代 uuid（模型抄错 uuid 是实测问题）、越界/重复一律丢弃不猜、
  只接受一个完整 JSON 不修补残片、**理由字段要留**（LogiNote 砍掉它是错的）。
- 桌面版面数据（包/日志）在 `.tmp` 下，不要在仓库里留调研垃圾
  （这轮子代理留下了 13.7MB 的 `repo.tgz`、`tree.json`、`nul`，已清理）。
