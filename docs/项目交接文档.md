## 一、一句话现状

**P0–P2 已完整交付并验收，P5 的 AI 接入已可用。P3（出题）、P4（PPT）尚未开始。**

## 三、已实现的功能清单

### 数据层

- **IndexedDB 存储**，12 个分区；`secrets` 独立存放凭据，**永不进备份文件**
- **存储契约**：`StorageAdapter` 接口，IndexedDB 与内存两套实现，跑同一组 32 条契约测试
- **备份导出/导入**：整库原子替换（单事务，失败回滚）
- **schema 版本迁移**：v1→v2→v3，旧备份仍可导入（只做加法，不伪造数据）

### 资料（P1）

| 能力 | 细节 |
|---|---|
| 导入格式 | PDF / DOCX / PPTX / Markdown / 纯文本 |
| 导入方式 | 多选文件、拖拽、粘贴一大段文字 |
| PDF 切分 | 按页；**已配 cMap，支持 CID 编码中文教材** |
| PPTX 切分 | 按幻灯片，**按 `sldIdLst` 顺序而非文件名**（PowerPoint 调页序只改引用顺序） |

### 三条验收原则（踩过坑总结的）

1. **验收必须在产物真正运行的环境里跑**。只跑浏览器时 29 项全过，但 Electron 生产包一打开就是 404（history 路由在 file:// 下匹配不到）。
2. **断言必须能在功能坏掉时变红**。曾经「定位失败不携带位置」在假后端场景下是零结果也能 PASS 的空断言。
3. **故意破坏功能验证断言不是空转**。已做过：禁用搜索提交 → 只有搜索那条 FAIL；高亮偏移 +1 → 3 个单测 FAIL。

## 六、给后续开发的建议

### 1. 扫描件的两条路：怎么选

界面上已经如实写了两条路的代价。技术上的建议：

**路线① 本地 OCR（Tesseract）**
- 用 `tesseract.js`（WASM，浏览器内跑，无需安装）
- 中文包 `chi_sim` 约 20MB，首次使用下载
- **必须做后处理**：OCR 出来的文本要按段落重组，并且**逐条标注置信度**
- **关键风险**：OCR 错字会跟着进知识点，污染"点回原文"。建议 OCR 结果与被引用的原文**分开存**，界面上标出"这段来自 OCR"
- 适合：字为主的讲义、笔记扫描件
- 不适合：公式密集（这本《信号与系统》就是）

**路线② 视觉模型**
- 每页一次调用（或按需只处理用户选中的章节）
- **必须先给预估**：628 页 × 每页成本，让用户决定要不要跑
- 适合：公式、图表、复杂版面
- 建议做成"按章节按需转换"，不要一次跑全书

**我倾向的顺序**：先做路线②（因为目标用户是备考学生，教材公式多），但**只做按需转换**，且先给预估。路线①作为"字为主资料"的免费备选，明确标注准确率局限。

### 2. P3 出题的关键设计（避免重蹈 P2 覆辙）

**不要让模型输出出处**。应该：
1. 让模型为每道题指定它依据的**知识点 id**
2. 题目的 `anchors` 直接**继承该知识点的 anchors**
3. 这样题目的"点回原文"必然准确，因为它复用了已经验证过的位置

如果让模型重新给一次引用，就会出现"知识点说第 3 页、题目说第 5 页"的矛盾。

**发布前逐题复校验**（计划书 P3 第 2 条要求）建议校验：
- `anchors` 非空且切片能还原
- `answer` 非空
- `explanation` 非空
- 题目依据的知识点仍然存在

### 3. 界面设计的一条教训

**用户误判"AI 总结能力差"，实际是他用了示例后端。** 这类问题的根源是界面没有暴露关键状态。

建议后续所有"生成类功能"都在结果上标明**来源与模式**：
- 哪个后端生成的
- 是草稿还是已发布
- 是否经过人工校对

不要让用户靠猜。

### 4. 建议加入的功能（计划书之外）

| 功能 | 理由 |
|---|---|
| **知识点覆盖率提示** | 整理完告诉用户"这份资料第 5–8 页没有提取出知识点，可能是纯图表页"，帮他判断有没有漏 |
| **一键对比原文** | 校对时高亮当前知识点在原文的位置，同时显示左右各一段上下文，比只高亮命中处更好判断 |
| **导入前体检** | 导入时就告诉用户"这份 PDF 是扫描件/有 628 页/需要 OCR"，而不是导入完点整理才发现 |
| **操作可撤销** | 删除知识点、重新整理会丢手工修改，目前靠 confirm 提示。建议做软删除或 30 秒内撤销 |
| **离线状态检测** | 调用 AI 前先探测网络，避免用户等 2 分钟超时 |
| **提示词可配置** | 高级用户可能想调整 prompt（比如要求更细/更粗的知识点粒度） |

### 5. 技术债

| 项 | 影响 |
|---|---|
| `use-organize-backend.ts` 里 `estimateTokens` 每次 new 一个 DeepSeekBackend 实例 | 轻微浪费，可提取成纯函数 |
| 错误提示文案分散在 `deepseek-client.ts`、`parsers/types.ts`、界面各处 | 建议集中成 i18n 文件，P7 要统一文案 |
| `KnowledgeService` 没有"取最近一次 run"的缓存，每次切资料都查全表 | 数据量大时会慢，可加索引 |
| 验收脚本之间有重复的 CDP 客户端代码（约 200 行 × 10 个文件） | 可抽成共享模块 |

## 八、几个必须知道的坑（都踩过）

| 坑 | 现象 | 解法 |
|---|---|---|
| **Electron 双击无反应** | exit 3、零日志 | 必须用 `OpenLeaner-Launcher.bat`（带 `--no-sandbox`）；`app.commandLine.appendSwitch` 太晚，无效 |
| **file:// 下路由 404** | 生产包打开是错误页 | 用 `createHashRouter`，不是 history 路由 |
| **中文 PDF 读不出字** | 被误报成扫描件 | 配 cMapUrl；`public/cmaps` 不能删 |
| **PDF worker 在浏览器失效** | `No workerSrc specified` | 用 `?url` 导入 worker；Node 里不能用（会解析成文件系统路径） |
| **esbuild 构建失败** | `Access is denied` | 设 TMP 到工作区内 |
| **改了代码但用户没变化** | 「你改的没生效」 | 忘了重新打包；用 `check-packaged-version.cjs` 核对 |
| **PowerShell 脚本乱码** | 变量被吞、报错 | 存成 UTF-8 with BOM；注释用 `#` 不是 `//` |
| **.bat 中文注释被执行** | 报「不是内部或外部命令」 | .bat 用纯 ASCII |
