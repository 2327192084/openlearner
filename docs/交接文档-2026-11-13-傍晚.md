## 一、最重要的三件事

### 1. 用户报的「跳页后回不到原任务」，根因不是「没有返回按钮」

上一轮已经做过返回栈（`nav-history.ts`，2026-11-09）。那个栈只解决
「**回到哪一页**」，不解决「**那一页上的活儿还在不在**」。

`App.tsx` 原来是一条 33 个 `page === '...' ? <XxxPage/> :` 的三元链。
**切页 = 卸载组件 = 组件内 state 全丢**。具体丢的是：

- 做题：题号（回到第 1 题）、已选选项、已提交的揭晓区、读题计时
- 模拟考：整张卷子 + 倒计时
- 整理知识点：出题跑到一半的进度条与已生成的点
- 文档解析：分片解析跑到一半

用户去看一眼原文，回来就从零开始。这不是「回不去」，是「回去了，但活儿没了」。

**这一轮的解法：让页面别卸载**（下面第二节）。

### 2. ⚠️ 保活不是免费的：三个真实副作用，都处理了

这是本轮最容易做错的地方。页面留着不卸载，意味着**它仍然活着**：

| 副作用 | 表现形式 | 处理 |
|---|---|---|
| **读题计时继续走** | `use-card-timer` 只在 `document.hidden` 时暂停；`display:none` 的隐藏层 `document.hidden === false`，所以「切到别的页」不会被当成离开。用户看一眼原文，回来这道题被判「想了好久」，直接拖垮复习间隔 | 给 `useCardTimer` 加 `suspended` 参数，由 `useLayerActive()` 驱动 |
| **键盘双响应** | `ReviewToday`/`FlashcardsPanel`/`BookSelfTest` 都在 `window` 上抢 `1-4`/方向键/空格。两层同挂时按一次「4」会给**隐藏的那页也判档**，写一条用户看不见的复习记录 | 抽 `useLayerKeydown()`：非活动层**不注册**监听 |
| **看到过期数据** | 首页/资料页留在内存里，用户在别处删了资料，回来还看得见 | 白名单只收「有进行中状态」的页，其余照旧卸载 |

**「保活」听起来像纯收益，其实是拿内存和副作用换的。**
白名单（`page-layers.ts` 的 `KEEP_ALIVE_PAGES`）就是这笔交易的边界。

### 3. 检索结论：**不引第三方库**，用 React 自己的机制

用户每轮开工前要求先看 StudyHub、再搜现成库。本轮结论（详见
`src/v2/ui/page-layers.ts` 头注释与下节）：

- **StudyHub 没有页面保活**（v4.8.0 实测：`ui/app/page-views.jsx` 用
  `key={page}`，切页即重挂）。它解决「回来进度不丢」用的是**状态快照**
  （`learning-navigation.js` 的 `captureContext` → `contextTrail`），
  不是保活。所以没有可抄的实现。
- `react-activation` / `keepalive-for-react` 的 README 都**明令禁止 StrictMode**，
  而本项目 `main.tsx:245` 正在用 StrictMode；两者都是给 react-router 生态设计的，
  本项目 v2 没有 router。**都不该引。**
- React **19.3.1** 已内置 `<Activity>`（已实测确认导出存在），
  但它隐藏时会**销毁 effect** —— 对 `ExamPage` 的倒计时是致命的（隐藏即停表）。
  所以本轮没用它。

**结论：自写，约 200 行（含注释与单测），只用 `display:none` + `inert`。**
这个结论也写进了 `page-layers.ts` 头注释，免得下一任再去查一遍。

### 2.1 新增 `src/v2/ui/page-layers.ts`（纯逻辑，24 个单测）

两个概念**必须分开**，这是第一版设计错的地方：

```
retained  留下不卸载的页（白名单里、有进行中状态的）
current   现在这一页 —— 它自己不一定在白名单里（阅读器就不在）
渲染   =  retained ∪ {current}，且 current 永远在最后
```

第一版只有一个数组并把 current 也塞进去，结果是：
进阅读器时要么把阅读器塞进保活（它很重，不该保活），
要么阅读器根本不渲染（**黑屏**）。单测里专门钉了 `layersToRender` 这一条。

其余语义（全部有单测）：

- 白名单外的页不进来，但**也不挤掉**别人（去首页看一眼不该扔掉做题进度）
- 已在里面的页再进去 → 挪到末尾，不重复
- 超上限（3 层）从**最久没访问**的开始丢（丢 = 卸载 = 回到旧行为，不会坏）

上限为什么是 3：保活的是重型页面（每层有队列、卡片、计时器），
3 层够覆盖实际路径（「做题 → 看原文 → 再点一个知识点」已是最长）。

### 2.2 `App.tsx`：33 分支三元链 → `renderPage(page)` + 覆盖层渲染

**这是本轮风险最高的一步**（文件 2130 行，链本身 582 行、几十个闭包变量）。

做法：用脚本 `.tmp/splice-layers.cjs` **整行剪切**链，不重写链内任何一行。
参数故意叫 `page`，让链里 33 处 `page === 'xxx'` 原样生效（参数遮蔽外层 state）。

**可核对性**（这一步务必保持）：搬完之后用脚本逐行比过：

```
head (lines 1-363) identical: true
tail identical after alignment: true    （尾部 217 行）
inserted lines count: 13                （只有我刻意改的做题分支那 13 行）
```

也就是说：**除了做题分支那 13 行，链是逐字节原样搬过去的**。
下一任若要再动这条链，别把它拆成分散的表 —— 那会让这种核对失效。

### 2.3 隐藏层的两条保证

```css
.page-layer     { display: none; }     /* 隐藏：退出布局与无障碍树 */
.page-layer--on { display: contents; } /* 可见：不生成盒子 */
```

`display: contents` 是刻意的：这一层**不生成盒子**，页面根节点仍像原来
一样直接参与 `.page` 的布局。**包一层 div 之后布局必须与包之前一模一样** ——
否则每一页的宽度/内边距都会悄悄变一次（这个项目因此被投诉过）。

隐藏层同时加 `inert`（不拿焦点、不点、读屏不念）。
⚠️ `inert` **挡不住挂在 window 上的 keydown** —— 所以才有 `useLayerKeydown`。

### 2.4 侧栏「继续：xxx」

保活之后用户跳走时那一轮还活着，但**没有入口他就找不到它** ——
「东西没丢，但你拿不回来」。所以侧栏顶部给一行「继续：做题（未完成）」。

**人在任务页上时不显示**（`if (isKeepAlive(page)) return null`）。
这一条是**截图复核才发现的**：第一版人在做题页上、侧栏还写着「继续：做题」。

### 2.5 一轮结束要 `dropLayer`

做题点「完成」/「退出」时把那一层从保活列表里丢掉，
否则侧栏永远挂着「继续」，点进去是上一轮的结果页 —— 一个**永远无法结束的任务**。

另外三处 `bumpLayer()`（强制换一个组件实例）：

- `startPractice()` —— 新一轮练习
- `startTodayReview()` 的两条分支 —— 新一次今日复习
  （`BookPage` 的自动开始用 `autostartedRef` 一次性守卫，
  组件活着就一直是 true，第二次点「开始复习」会**没反应**）

## 五、教训（写给下一个接手的人）

### 1. 「保活」的代价主要在副作用，不在内存

真正会咬人的是**仍然在跑的定时器**和**仍然挂着的 window 监听**。
动手做保活之前，先 grep 一遍要保活的页面：
`setInterval` / `addEventListener('keydown')` / `document.hidden`。
本轮就是靠这三条 grep 找到全部三个坑的。

### 2. 大文件里搬代码，要能**证明**是原样搬的

582 行的渲染链，手抄必然漏。用脚本整行剪切 + 事后逐行比对
（head 363 行 identical / tail 217 行 identical / 插入 13 行），
才能说「除了我改的那 13 行，其他一个字都没动」。
**「我小心的搬了一遍」不是证据。**

### 3. 反向验证会暴露脚本自己的假断言

第一次跑旧构建 9/17，其中三条是空断言（空数组 `every` 恒真、`null === null`）。
**跑旧构建不只是验证功能，也是在验证脚本。**
修完之后旧构建 6/17 —— 那个数字才是脚本真的在工作。

### 4. 截图复核又一次抓到断言抓不到的东西

「人已经在做题页，侧栏还写着继续做题」——17 条断言全过。
这与上一轮「资料库跳页把标题挤成竖排」是同一类问题：**布局与噪音不触发断言**。

### 5. 区分「我引入的」和「本来就有的」

竖排的「退出做题」看着像我新包一层 div 弄坏的。量了盒子才发现
新旧两版都是 `w 53, h 51`，与我无关。
**改布局类代码时，务必对新旧两版量同一个数值** —— 否则很容易把
既有问题当成自己的回归去「修」，改出真 bug。

### 6. flaky 名单（与上午那份一致）

- `src/core/parsers/pdf.test.ts` 的 `parseCourse`
- `src/core/knowledge/service.test.ts` 的 `beforeEach`

本轮全量跑了 3 次，两次全绿、一次未复现上述两条；遇到先单独重跑。
