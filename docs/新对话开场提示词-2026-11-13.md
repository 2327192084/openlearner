【硬约束（完整见两份交接文档，最易踩的）】
1. 验证破坏性操作必须在真正隔离的副本上做。不要把卸载器复制到别处跑 ——
   NSIS 的 $INSTDIR 编译时写死，会删真实的安装目录。前任因此删过用户的库。
2. **要动用户真实库，必须用桌面安装版且不带任何目录参数启动。**
   --user-data-dir 只是 electron/main.cjs 里 ensureUserDataDir() 的候选之一，
   不是决定项（候选 #4 是「安装目录旁的 openleaner-data」，它会抢先）。
   写完必须用 leveldb 的 mtime + 字节数证明真的写进去了 —— 脚本自己
   打印的成功不算证据。这一条前任栽过，向用户误报过一次「已删除」。
3. 迁移四处：STORES + BACKUP_STORES + StoreRecordMap + export type StoreName。
   但**优先考虑加可选字段而不是加分区** —— 可选字段对旧数据天然兼容，
   不触发迁移（见 model.ts 里 NotemarkImage 的注释）。
4. CSS 层级：base.css 有不在任何 @layer 内的 button/input 规则。
   原生控件样式一律写层外，包括 appearance: none。
5. token 分两套：src/styles/tokens.css 是 v1 浅色（--c-*，已废弃）；
   src/v2/ui/tokens.css 是 v2（--bg-* / --text* / --accent*）。v2 组件用 v2 的。
   危险色是 --bad，不是 --danger。
6. fetch 不能丢 this：(url, init) => globalThis.fetch(url, init)。
7. 大文件里不要插代码：App.tsx(2000+)、ReaderPage.tsx(2000+)、
   BookPage.tsx(860+)、SettingsPage.tsx(1440+)。新增 UI 一律独立文件。
   用 sed 按行号删代码前先 cp 备份，删完立刻 wc -l 和 tsc。
8. 改界面必须 CDP 截图肉眼复核。**断言全过不代表界面是对的** ——
   本轮就出现过 21 条断言全过、但截图里标题被挤成竖排的情况。
   截图前先确认「现在这一屏是不是我要拍的那个」（有过截到首页的假复核）。
9. 验证脚本自己也会错。按钮文字匹配用 indexOf 不要用 ===。
   **一条断言如果对「坏的实现」也成立，它就没在验任何东西** ——
