### 1. 修了一个会静默丢数据的缺陷（`a62e085`）

`src/core/library.ts` 的 `validateBackup()` 原本**逐字段手写重建对象**，只搬了 9 个分区，**漏掉 6 个**：`sourceSegments`、`sourceAnnotations`、`reviewRecords`、`reviewLogs`、`slideImages`、`usageRecords`。

因为 `importBackup()` 之后立刻 `storage.replaceAll(snapshot)`（整库原子替换），这 6 个分区会被**静默清空**，用户收不到任何提示。后果是：恢复备份 = 正文锚点全失效（点不回原文）、手写批注全丢、复习进度与历史全丢、PPT 插入图片全丢、用量统计归零。

修法：导出与校验两处都改成**以 `BACKUP_STORES` 为唯一清单**（`Object.fromEntries(BACKUP_STORES.map(...))`），从结构上消除「导出有、导入丢」的漂移。新增 2 条回归测试，**先跑出红再改绿**（改前 2 failed，改后 25 passed），证明测试真能抓到这个 bug。

> 教训写在 `src/core/library.ts` 注释里：**别手写字段清单，永远从唯一权威清单展开。**

- **进度百分比分母用 `estimatedTotal`（估算），不是 `segmentTotal`** —— 后者在「3 段产出 10 条」时会算出 333%。
- 停止后**已产出的条目已经在库里**，所以 catch 分支要**先刷新列表再报错**。
- 页码范围要么两头都填、要么都留空；估算抛错时显示「无法估算」，**不给假数字**。

## 五、已知的「说谎」与隐患（诚实清单，下次开工先看这个）

这些都是**还没修**的，按严重程度排：

1. **`src/core/questions/service.ts:147` / `:156` 文案指向不存在的页面**
   - `'没有可出题的知识点。请先在「知识点」页把资料整理成知识点。'`
   - `'…请先在校对页把至少几条标为「已定位」，再来出题。'`
   - v2 里没有「知识点」页（叫「整理知识点」），**更没有「校对页」**。虽然 `GeneratePage` 在调用前就用 `usablePoints.length === 0` 拦住了（实际很少能看到这两句），但一旦 core 被别的入口调用就会说谎。

2. **复习不写 `AnswerRecord`（做错题页前必须拍板）**
   `review-service.review()` 只写 `reviewRecords`（最终状态）和 `reviewLogs`（每次评分一条）。`answerRecords` 表**在 v2 界面里没有任何写入者** —— `DeckService.submitAnswer()` 有实现、`getWrongQuestions()` / `getHistory()` / `getStats()` 也都写好了，但**没人调**。
   → 做错题页有两条路，**数据模型不同，必须先问用户**：
   - A：复习页判定对错时**同时**调 `submitAnswer()`（双写）。语义最正，`getWrongQuestions()` 直接能用；代价是多一张表要维护、两处记录可能不一致。
   - B：错题页改用 `reviewLogs.grade`（`again`/`hard` 视为答错）。不用双写，但**知识点卡没有「对错」概念**会混进来，要额外过滤。


3. **`Question.kind` 有 `'essay'`，但 `CardKind` 没有**
   `src/v2/ui/cards-loader.ts:48` 是 `kind: (q.kind as CardKind) ?? 'single'` —— 强转。若库里出现 essay 题，ReviewPage 的 `card.kind === 'blank' || 'short'` 都不匹配，会渲染出**一个没有输入框的提交按钮**。目前生成只出 single/multiple/blank，所以打不出来，但这是个定时炸弹。

4. **复习队列有硬上限 30**
   `src/v2/ui/App.tsx:174` `setQueue(due.slice(0, 30))`。到期 80 张时只做 30 张，界面不说「还有 50 张」。要么给提示，要么去掉上限分批。

5. **「学新内容」和「开始复习」走同一个 `navigate('review')`**
   两个按钮文案不同但行为一样（都是取 due 队列），`onStartNew` 语义没实现。

6. **几处死代码/残留**
   - `src/v2/ui/today.css`（169 行）**无任何 import**，类名全不匹配，是死文件。
   - `src/v2/ui/TodayPanel.tsx` **没被任何文件引用**（`grep -rn TodayPanel src/` 只命中它自己）。
   - `AppShell.tsx:301` 的 `export function isReady()` **全库无调用点**。
   - `shell.css:234-258` 的 `.lang-switch*` 样式残留（组件已按用户要求摘掉 EN 按钮时整块删除）。
   - `src/app/`、`src/components/states.tsx` 等 v1 资产仍在，`main.tsx` 还 import 着 v1 的 `base.css` / `components.css`（v2 令牌挂在 `.app` 上，所以不冲突）。

7. **`src/styles/base.css` 的 `button, input, select, textarea { color: inherit }` 是无层级的**
   → **在 `@layer` 里覆盖原生控件样式会静默失效**。本轮踩了两次：`.set-inline .btn-text` 写多少特异性都赢不了。最后只能用**独立类名 + 把规则写在 `@layer` 外面**（见 `settings.css` 末尾 `.set-inline__action`，有长注释）。**下次改按钮/输入框颜色，先确认目标规则有没有层级。**

8. **资料页「PDF 解析」折叠的说明是错的**
   `src/v2/ui/SourcesPage.tsx:285-294`：`<summary>` 写「PDF 解析 / 扫描件、公式多或大文件」，正文却是「讲义和笔记保存为资料，原文件一并保留；JSON 题组存为草稿；字幕和录音在「音频 / 录音」里确认用量后导入。」
   → 标题在讲扫描件（**正是本轮调研、还没做的 OCR**），正文在讲 JSON 题组（`ready: false` 的未做功能）与「音频用量确认」（**根本不存在这个流程**）。标题与正文互不相关，整段要重写。

## 八、踩过的坑（本轮新增，都真踩过）

### 环境

- `npx vite build` 报 **Access is denied** → 必须把 `TMPDIR` / `TMP` / `TEMP` 三个都设到 `$(pwd)/.tmp-esbuild`。
- `electron-builder` 联网必失败 → 用上面的离线 asar 组装。
- 桌面包**双击 exe 无反应** → 必须走 `OpenLeaner-Launcher.bat`（bat 里注释记录了实测矩阵：直接跑 exe / `--disable-gpu` 都是 exit 3，`--no-sandbox` 或 `ELECTRON_DISABLE_SANDBOX=1` 正常）。
- 验收脚本 EPERM → 先杀残留 headless Edge。

### CSS

- **`@layer` 里的规则赢不了无层级规则**，`base.css` 的 `button { color: inherit }` 就是无层级的。详见第五节第 7 条。
- `.btn-fill` 是 `border: none`，`.btn-ghost` 有 `1px solid`。**并排时高度差 2px**。修法：`.set-actions .btn-fill { border: 1px solid transparent }`（`organize-page.css` 里的 `.org-actions` 也照做）。

### 自动化（Cdp）

- **侧栏 `nav-item` 的 textContent 是「图标 + label」拼接**，`textContent.trim() === '资料'` 永远不匹配 → 必须 `(b.querySelector('.nav-item__label')?.textContent ?? '').trim()`。这一条曾让 22 项断言全 FAIL。
- **`HTMLInputElement.prototype` 的 value setter 不能用于 textarea**（`Illegal invocation`）→ 必须按元素类型取 `HTMLTextAreaElement.prototype` 的 setter。
- **模板字符串里写 `/[\s\S]/` 会被吃掉一层反斜杠** → 脚本里一律用 `indexOf` / `slice` / `includes`，不用正则。
- **用 bash heredoc 写含反斜杠的 JS 会被吃掉** → 用 write 工具直接写文件。
- **v2 没有 hash 路由**（v1 才有 `#/settings`）→ 必须点真实侧栏按钮。
- **假服务器必须处理 OPTIONS 预检并回 CORS 头**（`Access-Control-Allow-Origin` 回显、`Allow-Methods: POST, OPTIONS`、`Allow-Headers: Content-Type, Authorization`），否则浏览器判 CORS 失败，前端只看到 `Failed to fetch` —— 那是探针的问题，不是产品的问题。
- **假后端太快**：mock 每条 120ms，3 条约 360ms 就结束，`wait(400)` 抓不到「运行中」状态 → `wait(120)`。

### 数据

- 备份必须**整库往返**（已修，见上）。
- `reviewRecords` 只留最终状态、`reviewLogs` 每次评分一条，**两者都进备份**。
- `charStart/charEnd` 是**页内偏移**，不是全文偏移。
- 导入 TXT/MD 时**页码是按段编的，不是真实页**（`src/core/parsers/text.ts:128`）。

### 一个反复出现的错误模式

**用 fixed 值承诺动态结果。** 例：界面写死「熟练 → 20 天后复习」，但 SM-2 首次 `good` 只给 1 天。
现在的做法：用 `schedule()` 真算一遍再显示（`ReviewPage` 的 `previewIntervals`）。
**同理**：任何「预计要花多少」「大概多久」都要来自真实计算；算不出来就显示「无法估算」，不要给假数字。

## 十、还没答复的两件事（用户换模型前提出，需要接手的人接着问）

用户在最后问了扫描件 PDF 的选型。调研已完成，结论如下，但**两个岔路要用户拍板才能动手**：

### 调研结论（已核实 StudyHub 源码 + 各项目官方文档）

StudyHub 的做法是「转换后另存为文档、**丢掉原 PDF**」，一页存成一份资料，引用指向转换出来的页。它明确推荐两个引擎：**MinerU**（效果最好，但 Apache-2.0 带附加条款、要常驻服务、装 4GB）与 **Docling**（MIT、一条命令、`prov[].page_no` 从 1 开始、CPU 约 3.1 秒/页）。明确不推荐 Marker（权重 OpenRAIL-M 限制商用 + 需要 Docker）与 olmOCR（要 12–20GB 显存 GPU）。

**我们的建议是不要照抄这个路线**：因为我们定位是「每条都点回原文」，anchor 是 `{sourceId, page, charStart, charEnd}` 且 `charStart/charEnd` 是**页内偏移**。只要文字**按页写回 `sourceSegments`**，页码映射就天然 1:1，不需要「转换页 → 原页」对照表，也不用碰 PDF 原始字节（避开 pdfjs detach ArrayBuffer 的坑）。

推荐顺序：**先接 OCRmyPDF 的产物形态（它把文字层压回原 PDF，页数与布局不变，现有解析器零改动）验证整条链 → Docling 做默认引擎 → 中文/公式重时提供 PaddleOCR PP-StructureV3 选项 → 安装体验照抄 StudyHub 的 uv 六步**（自带 Python、sha256 校验、可取消续装、只写一个文件夹、失败给唯一一个修复按钮）。

### 要用户决定的岔路

1. **引擎默认选谁**：先 OCRmyPDF+Docling（许可干净、安装轻），还是直接上 PaddleOCR / MinerU（中文教材质量优先，代价是体积和 Windows 环境坑）。
2. **桌面版要不要起子进程**：调用本机 Python 转换器需要在 `electron/main.cjs` 新增 IPC + `child_process.spawn`，并把 Python 环境放进 `resources/` 或首次运行时安装 —— 这是打包链路的新风险点。要不要现在就走？还是先只做「纯浏览器 + 现有 Tesseract / 看图模型」，把界面入口补齐？

**在这两件事定下来之前，不要动 OCR 相关代码。**
