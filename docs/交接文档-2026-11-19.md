## 一、接手先读这几条（最贵的教训）

### 1. ⚠️ 验证脚本「滚错容器 / 选区构造错」造成三次假阳性，直到用户实测才暴露

这轮右侧工具栏固定返工四次的根因，**不是代码难，是验证脚本在骗自己**：

- 用户滚的是**整个 document**（`.app` 是 `min-height:100vh`，随正文长高），
  而脚本前两次滚的是 `.rside__body` / 内部容器 → 断言全绿，界面照旧滚走。
- 公式批注治本第一次用 JS 构造**跨片段**选区（起终点落在不同 `[data-raw]`），
  15/15 PASS；但用户真实拖选整行公式时起终点都在**同一 math 片段内部**，
  `domPointToRaw` 对 math 片段起终点返回同一个 `rawFrom` → `s===e` → 治本分支没进。
- 教训：**必须按用户真实操作路径验证**——滚 `document.scrollingElement`、
  拖选片段内部；一条断言如果对坏实现也成立，它就没在验任何东西。

相关：`docs/工作日报-2026-11-18.md` 第九节、`scripts/verify-reader-fixes-ui.cjs`、
`scripts/verify-anchor-fix.cjs`。

### 2. ⚠️ KaTeX 与锚点的两个反直觉事实

- `.katex-html`（可见层）整个带 `aria-hidden="true"`；构造选区**不能**按
  aria-hidden 过滤节点，否则把用户实际拖选的文本节点全排除。
- `domPointToRaw` 对 math 片段（`data-raw-math`）起终点都返回片段起点 `rawFrom`。
  治本做法是 `mathSpanAt(node)` 拿片段完整 `{from,to}`，起终点各自吸附，
  让纯公式选区也 `s<e`；**`dom-text-map.ts:232` 是 paint 侧依据，不能改**。

### 3. ⚠️ 用户会用截图反复推翻「已通过」——改界面必须 CDP 截图肉眼复核

断言全过不代表界面对。这一轮截图抓到：顶栏按钮被右栏压住一半（断言全绿时没发现）。
**只要动了 CSS 布局，就一定截图看。**

## 三、关键设计（别推翻，理由都在这）

### 3.1 批注锚点必须同源（这是公式批注治本的核心）

创建批注时 `exact` 原本存 DOM 选区文本；纯文本选区 = 原文源码（能对上），
公式选区 = KaTeX 渲染文本（含零宽字符 U+200B、下标拆成 `x \n 2 \n [n]`），
而 `start/end/prefix/suffix` 取自原始 LaTeX 源码 → 还原时 `resolveTextAnchor` 判 lost。
现在 `ReaderPage.tsx` 的 `handleAddMark` 里：`mathSpanAt()` 命中 math 片段时
`exact = seg.text.slice(s,e)`、`start = s`，用原文源码切片，翻页往返都能还原。
**旧的第36页公式批注是坏数据，读不出来，需用户手动删掉重标**（用户已拍板不救旧数据）。

### 3.2 右栏必须 `position:fixed`，不能用 sticky

sticky 依赖包含块，`.rside` 的包含块 `.reader-split` 高度 = 整页正文，
document 滚到底时 split 底边把 `.rside` 顶出视口（top 变 -48px）。
现在：`.rside{position:fixed;right:0;top:var(--topbar-h,51px);height:calc(100vh - var(--topbar-h,51px));z-index:4}`，
正文 `.reader-page{padding-right:260px}`（**留白在整页，不在 `.reader-split`**，
否则 header/reader-bar 按钮被遮）。窄屏 ≤560px 退回 static + 撤掉留白。
全屏 `.reader-page--fullscreen .rside{display:none}` 且撤留白。
三批注按钮（高亮/下划线/删除线）在 `.rside__sec--sticky` 里贴顶，
滚动区收窄到 `.rside__body`（`flex:1;min-height:0;overflow-y:auto`）。

### 3.3 PPT 看原件走 pptx-wasm，不走 LibreOffice

- `src/core/slides/pptx-page.ts` 的 `renderPptxPage()`：`await import('pptx-wasm')` +
  `import('pptx-wasm/wasm?url')`，`Presentation.open(bytes,{wasm})` → `deck.render()` → `toDataURL`。
  类型用 `import type { Presentation }`（`InstanceType<typeof Presentation>` 会因 private constructor 报 TS2344）。
  正确入口是 `index.js`（底层 `pptx.js` 的 `Presentation` 无静态 `open()`）。
- `sources.ts` 的 `storeOriginalFile` 闸门改为「只挡 docx/markdown/text」，
  PPTX 也存原件字节；`source-ext.ts` 的 `KNOWN` 加 `pptx`。
- ReaderPage 的看原图 effect 放宽到 `pdf || pptx`，按 kind 选渲染器。
- 保护点：看图 OCR 先判 `kind !== 'pdf'` 拒绝，PPTX 不会误入；MinerU 白名单不含 pptx（现状一致）。

### 3.4 全屏 state 不能挂在 Fullscreen API promise 上

首版 `setIsFullscreen` 放在 `await requestFullscreen()` 之后，CDP 非 trusted 点击下
promise 不 settle → 点了没反应。改成**先立即翻转 state，再异步请求全屏，失败保留纯沉浸**。

### 3.5 更名边界（继承，别「顺手统一」）

改了：侧栏品牌、面包屑、窗口标题、README、GitHub 描述等**文案**。
故意没改（改了坏数据/让旧安装失效）：`%APPDATA%\OpenLeaner`（用户学习库）、
IndexedDB 名 `openleaner`、备份/题组格式、`window.openleaner` 桥、
`com.openleaner.app`、安装目录与 `OpenLeaner.exe`、仓库 URL `2327192084/openlearner`。
