## 三、DeepSeek 云 OCR（唯一未推送的功能）

### 官方文档核过，不是照报道抄

`POST https://api.deepseek.com/v1/tools/ocr`
依据 https://api-docs.deepseek.com/zh-cn/guides/ocr

| 项 | 事实 |
|---|---|
| 请求 | `multipart/form-data`：`file`（带文件名）+ `purpose` |
| 响应 | `{ pages:[{index,text,finish_reason}], page_count, usage }` |
| 页码 | `index` **从 0 开始**，全项目用 1 基 |
| 限制 | 100 MiB / 1000 页 / **180 秒总时长** |
| 计费 | 1.5 元 / 1000 页；每账号 15 并发 |

⚠️ **识别失败时 HTTP 仍是 200**，响应体是 `{ error: {...} }`。
只看状态码会把错误当结果（「解析成功但 0 页」）。这条有单测钉住。

### 关键落差：它不出插图

官方 OCR 只返回文字。MinerU 会切图、给位置、写回 `SegmentFigure`；
阅读器有「这一页有哪些插图」、图文页能点开原图。

所以**不能替换** MinerU，只能并列。这个代价**写在选择器上**（选之前就能看到）。

### 与已有 `src/core/ocr/` 不是一回事

那套（2026-11-06）是「PDF 页渲染成图片 → 多模态模型看图」；
DeepSeek 是「直接上传原文件 → 服务端解析」。输入/计费/本地依赖都不同。
所以做成第三条路，不塞进那套里。

顺带发现：那套 `OcrService` **从写完起没有任何界面调用**
（`grep OcrService src/v2 src/pages` 零命中）。又一个「做了没接上」。

### 分片上传：用户选了，但**这一版没做**

按页切 PDF 要「每片重新拼成合法 PDF」，还要定「第二片怎么与第一片合并」——
那要动 `writeSegments` 的 merge 语义与页码范围校验。
界面上明写「超过 180 秒的大文件可能超时，大书建议先分批」。

**没在注释里写「已按 10 页分片」** —— 那会让下一个人以为有合并逻辑，去查半天。

## 五、⚠️ 两次「验证方法本身是错的」

这两条是这一轮最有价值的教训。

### 1. 用错方法验「asar 里有没有某个功能的源码」

我查「安装包是否含 OCR」时跑：
```bash
npx asar list app.asar | grep -c "deepseek-ocr"
# → 0
```
据此在报告里写「asar 里 0 个 OCR 文件，确认不含 OCR」。

**但 asar 里装的是 `dist` 打包产物**（`dist/assets/index-*.js`），
不是 `.ts` 源码。按源码文件名 grep 永远是 0 —— 无论里面有没有那个功能。
**这个检查对「有」和「没有」都返回 0，等于什么都没验。**

正确做法：解出 `dist/assets/index-*.js` 再 `grep -F` 特征串：
```bash
grep -c -F "v1/tools/ocr" dist/assets/index-*.js
grep -c -F "按页收费" dist/assets/index-*.js
```

### 2. 用「隔离目录有没有出现」验「安装是否装到了隔离目录」

静默安装实验失败后，我看隔离目录没被创建，就判断「装失败了」。
实际上安装器装到了**默认安装目录**，把用户的桌面版覆盖了。

**判据应该是「默认安装目录有没有被改」**（时间戳 + MD5），
而不是「隔离目录有没有出现」——前者是硬证据，后者只能证明「没装到那儿」。

### 2. 同一个改动在两个地方各提交一次 → 历史分叉

README 在本地提交一次、又在临时 worktree 里提交一次，
内容相同但父提交不同。下次推送会重复或冲突。
已用 `git rebase --onto` 捋成一条直线。

### 3. `git rebase --onto A B` 的语义是「把 B **之后**的提交接到 A 上」

我写成 `--onto c90e08a 93e0811`，而 93e0811 之后没有提交 ——
OCR 提交被排除在外，**文件从工作区消失**。靠事先建的备份分支找回。

**动历史前先 `git branch backup-xxx`。**

### 4. 推送要用 schannel，不是 openssl

交接文档记的是 `-c http.sslBackend=openssl`，这台机器现在要 **schannel**。
openssl 报 `TLS connect error: unexpected eof`。
`curl -x http://127.0.0.1:7897` 能通不代表 `git` 能通 —— 两者 TLS 栈不同。

完整命令：
```bash
git -c http.proxy=http://127.0.0.1:7897 \
    -c http.sslBackend=schannel \
    -c http.version=HTTP/1.1 push origin <commit>:main
```

### 5. 构建安装包不能用 `npx electron-builder`

`package.json` 写着 `target: nsis`，但 `build/installer.nsi` 的注释说明：
electron-builder 的 nsis 是**两步编译**（编安装器 → 释放卸载器 → 编第二次），
第 2 步在这台机器上稳定失败（`Install data: 0 / 8 bytes`）。

要用 makensis 直接编：
```bash
cd build
"$LOCALAPPDATA/electron-builder/Cache/nsis-3.0.4.1/makensis.exe" \
  -V2 -INPUTCHARSET UTF8 \
  -DSOURCE_DIR="<win-unpacked 绝对路径>" -DVERSION=0.2.0 installer.nsi
```

### 6. vite build 在 C 盘用户目录会随机失败

报 `[vite:esbuild-transpile] remove ...: Access is denied.`
同一份代码在 `E:\openleaner`（TMP 指 E 盘）能成功，在 `C:\Users\ASUS\ol-build`
（TMP 指 C 盘）稳定失败。原因未完全查明（怀疑 Defender 按大小扫描占住临时文件）。

**绕法：把 `TMP`/`TEMP` 指到 E 盘**。

### 7. 在 worktree 里联接 node_modules，删 worktree 前必须先拆

```bash
# 先拆联接（不加 /S，否则会递归删掉主仓库的依赖）
cmd //c "rmdir <worktree>\node_modules"
git worktree remove --force <worktree>
```
Windows 的 junction 用 `rm -rf` 删会连带删目标。
