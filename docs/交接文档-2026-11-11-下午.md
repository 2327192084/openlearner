## 三、备注功能的设计（供下一任理解，别推翻）

### 为什么备注不新开存储分区

备注与高亮在结构上**完全同构**：都是「某页某处的字符区间 + 一段用户文字」。
所以复用 `TextMark`，只加一个 `kind: 'note'`。不新增分区、不改迁移。

### 「不与批注冲突」的解法（用户原话要求）

三种修饰各有姿态，一眼分得清：

| | 视觉 | 读作 |
|---|---|---|
| 定位高亮 | 黄色**底色** + 极淡描边 | 我跳到这儿了 |
| 批注·下划线 | 琥珀色**实线** | 我要记住这句 |
| 备注 | 蓝灰**虚线** + 行末小圆点 + 极淡底 | 我在这儿写了想法 |

**用户后来又要求**：「除了小点，可以再加一个下划线，好分辨具体位置」→ 已加虚线。
再后来说「批注不需要下划线，已经有颜色显示了」→ 已去掉定位高亮的 `inset` 下划线。

### 整页备注与划选备注怎么分

`isWholePageNote()`：`kind === 'note'` 且 `start === 0` 且覆盖整段（容差 2 字）。
整页备注显示在正文下方页脚，**不画进正文**（否则整段变虚线，看不出重点）。

## 四、⚠️ 硬约束（违反会立刻出问题）

### 1. 迁移必须三件套，且 types.ts 里是四处

| 改动位置 | 改什么 |

| `indexeddb-storage.ts` / `model.ts` | `DB_VERSION` / `LIBRARY_SCHEMA_VERSION` |

`export type StoreName` 这一行最容易漏 —— 11-10 删掉它导致 `StoreRecordMap` 整层塌成 unknown，
tsc 一次报 30 多个不相关文件的错。**改完先看 tsc。**

**数字错了 tsc 抓不到**，必须在 `.tmp` 副本库上跑真实升级验证。

### 2. CSS 层级陷阱（已踩六次以上）

`base.css` 有**不在任何 @layer 内**的 `button` / `input` / `select` / `textarea` 规则。
级联「层级先于特异性」。

> **原生控件（button/input/select/textarea）的样式一律写层外，
> 一条都不能留层内，包括 `appearance: none`。**

### 3. CSS 类名写错不会报错，只会静默不生效

今天靠 `check-css-vars.cjs` 抓出 14 处会让整条声明失效的硬错误。
**改这类「看着像设计问题」的地方之前，先确认类名真的对得上。**

### 4. fetch 不能丢 this

```js
// ❌ Illegal invocation（单测抓不到，假函数不挑 this）
this.fetchImpl = fetch;
// ✅
this.fetchImpl = (url, init) => globalThis.fetch(url, init);
```

### 5. 大文件里不要插代码

`App.tsx`（1900+）、`BookPage.tsx`（800+）、`SettingsPage.tsx`（1440+）、
`ReaderPage.tsx`（1460+）、`GeneratePage.tsx`（CRLF 混用）。

**新增 UI 一律独立文件，宿主里只插一行引用或一个 prop。** 今天的 `EmptyCard` /
`LibraryLocationRow` / `MineruSetupPanel` / `MarkdownBodyMarked` 都这么做。

⚠️ **但注意**：我用 `sed -i` 按行号删旧代码时，**两次把文件搞坏**
（删错范围、文件被截断到 1189 行）。大文件改结构时：
1. 先 `cp` 到 `.tmp` 备份
2. 删完立刻 `wc -l` 看行数是否合理
3. 立刻 `npx tsc -b`，不要等到最后

## 六、工作流：只更新桌面，不出安装包（用户明确要求）

用户原话：「以后只有我在让生成安装程序的时候再生成，其他时候只是要你更新桌面上软件的版本。」

### 平时改完代码

```bash
cd /e/openleaner

# 1. 构建（分开跑，看输出）
TMP=E:/openleaner/.tmp/estmp TEMP=E:/openleaner/.tmp/estmp npx vite build
ls -la dist/assets/index-*.js          # ← 必须确认时间变了

# 2. 打包到 release/win-unpacked
npx electron-builder --dir

# 3. 更新桌面安装位置
node scripts/update-desktop.cjs
```

`update-desktop.cjs` 会：检查目标存在 → 备份旧 asar → 复制 → 校验大小 → 报告。
它**绝不碰数据目录**（数据在 `%APPDATA%\OpenLeaner`，与安装目录分开）。

### 只有用户明确要求时才生成安装程序

```bash
cd /e/openleaner/build
"$LOCALAPPDATA/electron-builder/Cache/nsis-3.0.4.1/makensis.exe" \
  -V2 -INPUTCHARSET UTF8 \
  -DSOURCE_DIR="E:\\openleaner\\release\\win-unpacked" \
  -DVERSION=0.2.0 installer.nsi
```

**为什么手写 NSIS 脚本而不是用 electron-builder 的 nsis 目标**：
那个目标是两步编译（先生成临时安装器、再运行它释放卸载器），
在这台机器上第二步稳定失败（进程退出码 null），产物是个 189KB 的空壳
（`Install data: 0 / 8 bytes`）。`build/installer.nsi` 注释里有完整说明。

## 十二、给下一个模型的话

1. **「我的脚本全过了」不等于「用户看到的是对的」。**
   今天验证备注时脚本 16 项全过，截图才发现按钮状态与我以为的不同。

2. **说「已发布」之前，必须核实三处的字节或时间。**
   今天因为构建失败而反复说「已更新」，用户问了三遍。

3. **构建命令不要用长链 `&&`。** 前面的失败会被后面的输出掩盖。

4. **大文件用 `sed` 删代码先备份。** 我今天两次把 ReaderPage 搞坏
   （删错范围、截断到 1189 行），都是恢复 git 重来的。

5. **`index.html` 是 vite 的源模板，不是产物。** 它被 `dist/` 覆盖过两次（历史事故）。
   怀疑时 `git checkout -- index.html`。

6. **`.tmp` 里的 exe 跑不起来不是包的问题**，是那条 DENY ACL。复制到用户目录再跑。

7. **改存储三件套后先看 tsc。** 数字错了 tsc 抓不到，但类型塌了会一片红。

8. **不要声称「稳定」。** 提问式复习的 AI 判定、标注偏移的修复，都只验证了有限场景。
