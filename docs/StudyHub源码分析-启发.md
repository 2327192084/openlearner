# StudyHub 源码分析：能给 OpenLeaner 什么启发

> 分析对象：[EricWang1358/dsh-web-studyhub](https://github.com/EricWang1358/dsh-web-studyhub) v4.4.4（MIT）
> 分析时间：2026-11-07
> 方法：只读源码与 README，未运行、未安装。规模约 3860 个文件，
> 其中 `lib/` 400+ 模块、`ui/` 30 个功能目录、`tests/` 1473 个测试文件。

---

## 一、先说结论：三个最值得抄的东西

| # | 概念 | StudyHub 怎么做的 | OpenLeaner 现状 |
| --- | --- | --- | --- |
| 1 | **一个「下一步」** | 固定优先级状态机，纯本地算，不调模型 | 有学习流，但是「五步进度展示」，不是「现在该干嘛」 |
| 2 | **覆盖度** | 每段正文有没有题，三种状态（有题/计划了但没出成/从没计划） | **完全没有**。不知道哪一章还没题 |
| 3 | **FSRS-6** | 完整移植 ts-fsrs 5.4.2，21 个权重 | 简化版艾宾浩斯阶梯 |

这三个是**能力缺口**，不是皮肤差异。其余（音频转写、思维导图、案例分析卷）要么依赖外部引擎，要么是长尾功能。

## 二、「一个下一步」：`ui/study-map/next-step.js`

### 它解决什么

打开软件第一眼最想知道的是「我现在做什么」。StudyHub 把这件事做成了一个
**固定优先级的状态机**，第一个成立的状态胜出：

```
model        没有可用的 AI 模型
sources      没有任何自己的资料        ┐ 这三条只在新用户
questions    有资料但还没出过题        ┘ 阶段出现（第一次出题后消失）
due          今天有题到期
resume       没到期但有做了一半的一轮（接着做）
new-source   两周内导入、还没出题的资料
wrong        有错题没复习（待巩固）
exam         一周内有考试，且那门课有复习全书
learn        今天这一轮还有要学的新题/薄弱题
done         没别的了
```

### 三个关键设计决定（源码注释里明说的）

1. **初始三态只在「还没有自己的题组」时出现**。有了自己的题组之后，
   「没有资料」不该打断一个已经在学习的人。
2. **「今天到期」指的是到期的题，不是整轮**。薄弱题走 `wrong` 态，
   只有薄弱/未学题的一轮走 `learn` 态 —— 所以永远不会在下面还有题要学时说「没事了」。
3. **全部从本地快照算**，不调模型、不查 `daily.plan.get`。
   `nextStepFacts()` 的入参就是快照，纯函数，可测。

### 给 OpenLeaner 的启发

我们的「学习流」是**按资料展示五步进度**，回答的是「这份资料走到哪」。
StudyHub 回答的是「**跨所有资料，现在最该做哪一件**」。

两者不冲突，但后者是首屏该有的东西。可以加一张「下一步」卡：

```
if 没配模型          → 去设置
if 没有任何资料      → 去导入
if 有两周内导入未出题 → 去出题
if 今天到期 > 0      → 开始做题（今日题组）
if 有错题            → 错题巩固
else                 → 自由练习 / 没事了
```

需要注意的坑（StudyHub 已经替我们踩过）：
**「没事了」这句话不能说太早** —— 如果还有新题没学，要显示「今天还有 N 道新题可以学」。

## 三、覆盖度：`lib/coverage.js`

### 这是 OpenLeaner 最大的能力缺口

概念：把一份资料的正文切成**叶子段落**（PDF 页 / Markdown 标题 / 转录分段 / 固定窗口），
每一段有三种状态：

| 状态 | 含义 |
| --- | --- |
| `covered` | 至少有一道题的出处落在这段里 |
| `planned-failed` | 计划要出但没出成（带失败原因码） |
| `never-planned` | 从来没计划过 |

产出指标：`covered / plannedFailed / neverPlanned / leaves`，
以及 `percentLeaves`（按段）、`percentChars`（按字符）、`perTenK`（每万字几道题）。

### 为什么这个设计好

1. **它回答「我出题出全了吗」**。OpenLeaner 现在只能看到「这个题组有 8 道题」，
   完全不知道这 8 道题覆盖了资料的百分之几 —— 可能全集中在第一章。
2. **三种状态而不是两种**。「没题」有两种原因：计划了但生成失败、
   压根没计划到。混在一起用户没法判断该重跑还是该补计划。
3. **一个函数，所有界面共用**。源码注释强调：后端、草稿页、任务控制台、
   阅读器大纲**读同一个 `coverageOf()`**，所以每个屏幕上的数字是同一个数字。
   这正好对应 OpenLeaner 踩过的「概览说已学 10 张但列表只有 3 张」。
4. **纯函数**，不碰 I/O，浏览器里也能跑。

### 给 OpenLeaner 的启发

我们已经有 `sourceSegments`（每页/每章的正文）和 `Question.anchors`（题目出处）。
**数据是齐的，只差一个聚合函数**。可以做：

```ts
coverageOf(sourceId) → {
  sections: [{ page, chars, state: 'covered' | 'never-planned' }],
  covered, total, percentLeaves
}
```

在「知识骨架」页或「复习全书」页显示：
「这份资料 36 页，有题的是 12 页（33%）；第 13–24 页从没出过题」。

这比现在的「95 条知识点」有用得多 —— 后者不告诉你覆盖得全不全。

## 四、FSRS-6：`lib/sm2.js`（文件名是旧的，内容已换成 FSRS）

### 和 OpenLeaner 的差距

| | OpenLeaner | StudyHub |
| --- | --- | --- |
| 算法 | 艾宾浩斯阶梯（1/2/4/7/15/30…） | FSRS-6，21 个权重 |
| 个性化 | ease 微调（0.85–1.15） | 稳定性 + 难度两个记忆状态，每次作答都更新 |
| 提前复习 | 不区分 | 「提前复习学到的比按时复习少」—— 按真实间隔算 |

### 最值得抄的一个细节

> 「days are counted on the learner's local calendar (ts-fsrs counts UTC days,
> so in Beijing 07:50 and 08:10 would be two days)」

**StudyHub 特意偏离了 ts-fsrs 的 UTC 计数，改用学习者本地日历。**
理由：北京时间 07:50 和 08:10 跨了 UTC 日期，但用户觉得是「同一天」。

OpenLeaner 的 `todayUtc()` 正是 UTC 计数。这是一个**已知的、被上游明确修正过的**设计缺陷。
如果哪天要改，这是有依据的改法。

### 还有两个小心思

1. **重点题的复习频率加成**：`FOCUS_RETENTION_BOOST = 0.04`，
   把目标记忆率从 0.90 提到 0.94，「约 2 倍复习频率」，
   但**不改 FSRS 的稳定性和难度**。这样重点题的安排更密，但算法本身没被污染。
2. **旧的 SM-2 数据懒迁移**：下次作答时才把 interval 转成初始稳定性、
   ease 转成初始难度；在那之前按原样读。**不做批量迁移**。

### 不建议现在就换

理由：FSRS-6 的 21 个权重需要大量历史数据才有意义（StudyHub 也是移植的 ts-fsrs 默认值）。
OpenLeaner 目前 24 道题的规模，换算法的收益不明显，而风险是「所有现有进度都要重算」。
**但 UTC vs 本地日历这一条，值得单独修。**

## 五、掌握度：`lib/mastery.js`

五档：`new / weak / learning / familiar / mastered`，权重 0 / 0.15 / 0.45 / 0.75 / 1。

判定规则（`cardLevel`）：

```js
lastGrade < 3          → weak        // 答错了
lastGrade === 5        → mastered    // 自评「轻松掌握」= 用户自己的判断，直接采信
interval >= 21天 && 连续答对 >= 2  → mastered
interval >= 6天        → familiar
else                   → learning
```

### 两个设计决定值得抄

1. **「已掌握」要求间隔 ≥ 21 天且连续答对 ≥ 2 次**。
   理由写在注释里：「没有任何调度器设置能靠一次作答就让人『已掌握』」。
   这是在防止「点一次就会了」的假象。
2. **上限自适应**：如果用户把 `maximum_interval` 设得比 21 天低，
   「已掌握」的线也**跟着降下来**（`line()` 函数）。
   这样「已掌握」在**任何设置下含义一致**。

### OpenLeaner 可以立刻用的

我们的 `masteryLabel()` 是：

```js
if (m >= 0.85) return '很熟';
if (m >= 0.6) return '熟练';
if (m >= 0.35) return '有点印象';
```

这是**纯粹的数值分档**，没有「连续答对」这个维度。
加一条「至少连续答对 2 次才算很熟」，能避免「蒙对一次就显示很熟」。

## 六、出题「补题」机制：`lib/shortfall.js`

### 概念

出题计划要覆盖 N 段，实际出了 M 段。差多少？该干什么？

```
questionsKept / questionsGoal / questionsMissing   题数差
sectionsCovered / sectionsUncovered / sectionsUnderQuota   段数差
roundsLeft / nextRoundSections                     下一轮能补多少
action: resume | continue | topup | model-settings  唯一的主操作
secondary                                          次操作（最多一个）
```

### 关键设计

> 「the ONE primary action」（唯一的主操作）

无论界面在哪（首页横幅、待发布行、任务控制台、草稿页），
都读同一个 `shortfallOf()`，所以**同一件事只有一种说法、一个按钮**。

这一点 OpenLeaner 在「我的题组」上踩过反例：
同一个题组，发布按钮和撤回按钮的措辞不统一，用户会以为是两件事。

### 给 OpenLeaner 的启发

我们的出题是「一次生成，出多少算多少」，没有「补题」概念。
如果做了覆盖度，自然就能有：

「这份资料还有 24 页没题 —— [为没覆盖的部分补题]」

这个按钮比现在的「重新出一组」精确得多，也不会浪费已经出好的题。

## 七、其他值得注意的工程实践

| 做法 | 位置 | 说明 |
| --- | --- | --- |
| 纯函数 + 单一真源 | `lib/coverage.js`、`lib/shortfall.js`、`lib/mastery.js` | 每个概念一个函数，所有界面共用，注释里反复强调「一个事实一个数字」 |
| 本地日历而非 UTC | `lib/sm2.js` | 见上文，明确偏离上游库的行为并写了理由 |
| 懒迁移 | `lib/sm2.js` | 旧数据不批量转换，下次写入时顺手转 |
| 快照冻结 + WeakMap 缓存 | `lib/mastery.js` | 同一个数组被问五次，只算一次 |
| 失败原因分类 | `lib/generation-failure.js` | `credential` / `quota` 等，让 UI 能给出**可操作**的提示 |
| 段落切分统一 | `lib/sections.js`（421 行） | PDF 页 / 标题 / 转录分段 / 固定窗口统一成一种结构 |

## 八、明确不建议抄的

| 项 | 原因 |
| --- | --- |
| 音频转写 / 课堂实录 | 要接外部转写服务（硅基流动 SenseVoice / Gemini / Groq），OpenLeaner 没这个依赖，也不是核心价值 |
| 思维导图（Archify） | 依赖第三方开源工具，且是「锦上添花」 |
| 案例分析卷 / 口头面试 | 需要大量出题提示词工程，收益集中在少数场景 |
| 21 个 FSRS 权重的调参 UI | 用户不懂；StudyHub 自己也只暴露 `request_retention` 和 `maximum_interval` 两个 |
| 整个 `lib/` 的 400 个模块架构 | 那是给 DSH 插件生态设计的，OpenLeaner 单体应用抄了只会变重 |

## 九、如果要动手，建议的顺序

按「价值 ÷ 风险」排：

1. **一个「下一步」卡**（价值高、风险零）
   - 纯前端，从现有数据推导，不碰存储
   - 放在学习库首页顶部
   - 注意：「没事了」这句话的前置条件要写全

2. **UTC → 本地日历**（价值中、风险低但影响所有已有进度）
   - 改 `todayUtc()` 为本地日历
   - 需要迁移测试 + 备份
   - 影响：所有 `dueAt` 的语义

3. **覆盖度**（价值高、风险低）
   - 纯聚合函数，数据已齐（`sourceSegments` + `Question.anchors`）
   - 先在「复习全书」或「知识骨架」显示「这份资料 36 页，12 页有题」

4. **掌握度加「连续答对」维度**（价值中、风险低）
   - 改 `masteryLabel()` 的判定
   - 不影响调度，只影响显示

5. **补题机制**（价值高、但依赖 3）
   - 需要覆盖度先做出来

**不建议做**：FSRS-6 全量替换。当前 24 道题的规模，收益不足以覆盖「所有进度重算」的风险。

## 十、一句话总结

StudyHub 最值得学的不是功能清单，而是**三个「一个事实一个数字」的纯函数**：
`nextStep()` 回答「现在做什么」、`coverageOf()` 回答「出题出全了吗」、
`cardLevel()` 回答「这道题学到什么程度」。

它们的共同点：**只读现有数据、不调模型、所有界面共用同一个函数**。
OpenLeaner 现在缺的正是这三层「聚合视图」——数据都在，只是没有一处把它算成一句话。
