## 二、最重要的是三件事

### 1. 「复习功能」被反复返工三次，根因是我只接了表面

用户的反馈一次比一次具体：

1. 「开始复习和开始做题两个按钮功能一样，都是跳转到做题界面」
2. 「复习功能还是不行，点击开始复习后就直接跳到做题界面了」

第一次我以为改接线就行（直跳今日队列），第二次改成进「自测」，
第三次调研后才明白：**复习与做题的差别不在「做不做题」，而在三件事**：

- 只做**今天到期**的，不给自由挑
- 有**固定批次与结束点**，不是无限刷
- **先自己回想，再看答案**，然后自评四档并**写进间隔**

调研来源（写进了注释）：Anki 的四档自评与「先回想后翻面」、
Ebbinghaus 明确把「自由翻看」与「正式复习」分成两个功能（前者不影响间隔）、
StudyHub 的 `ui/Review.jsx` + `DailyRecap.jsx` 会话结构。

**最后一次改动才真正改变了交互**：`prompt` 阶段连选项都不显示，
`grade()` 在 `prompt` 阶段调用直接返回原状态（不许盲评）。

### 2. 一个「删了功能 ≠ 删了数据」的凭据事故（已避免）

用户要求移除墨墨生词本。删 6 个文件很直接，但查库后发现：
**用户库里那条 settings 记录物理上还存着一个真实 token**。

而且它是 **UTF-16LE** 存的 —— 第一次用普通 `grep` 扫 IndexedDB 只搜到键名、
搜不到值，差点判定「没有残留」。

只把字段从类型里删掉不解决问题：`getSettings` 用 `...rest` 展开会把它
带进内存，随后 `exportBackup` 会写进备份文件。也就是说
「删了功能」不等于「凭据不再外泄」。补了三道防线：

1. `init()` → `purgeRetiredCredentials()`：启动时真删并回写库
2. `getSettings()`：清洗返回值，挡住 init 之前的时间窗
3. `sanitizeSettingsForExport` 保留（旧备份导入再导出的路径仍需剔除）

**验证**：在真实库副本上跑真实 Electron，启动后 `hasToken=false`；
新增 5 条单测，并做反向验证 —— 回退清理逻辑后 2 条核心用例立刻变红。

### 3. 定位精度分级：不再假装「每道题都能圈到句子」

用户对照 StudyHub 提出「错题的知识点可以精准定位回原文」。
查数据后发现真实情况：**两条出题来源的定位能力根本不同**。

| 来源 | 锚点精度 | 能否精确定位 |
|---|---|---|
| 从知识库出题 | 一句话（`charStart/charEnd`） | 能 |
| 从原文出题 | **整段**（`charStart=0`，`charEnd`=整段长） | 不能 |

而界面此前对两者承诺同一句话。实测用户库 10 道题：全部没有 `segmentId`，
`anchors` 跨度 681~1454 字符。

改动（用户拍板的 A+B 方案）：
- `SourceLocation` 加 `segmentId` + `quote`（沿用 W3C 双选择器思路）
- 新增 `anchor-precision.ts`：`exact / block / none` 三档，界面说不同的话
- 迁移 v16→v17 + `init()` 回填：`sourceId+page` 恰好对应一段才填，
  **多段留空不猜**（挑第一条正是要修的 bug）
- 修 `knowledgePointId` 被写成段落 id 的断链 bug（实测 10 道题 0 命中）

## 四、我自己踩的坑（都记进了注释）

### 1. 选区监听挂在错误的生命周期上

第一版把 `mouseup` 监听挂在 `bodyRef` 上、依赖写 `[]`。effect 首次执行时
还在 loading，`bodyRef.current` 是 `null` 直接 return —— 正文渲染后
监听器**再也没绑上**。表现是「选中了文字，加标记按钮仍是灰的」。
端到端脚本抓到的。改成 document 级 `selectionchange`。

### 2. 答案归一化把括号吃掉了

第一版左右括号各自独立剥离，`(信号)` → `信号`，而 `(a)(b)` 会变成 `a)(b`。
改成只剥**成对**引号，且**不剥圆括号** —— `f(x)`、`(n+1)` 里括号是正文。

### 3. 问答的空答案被判成「错」

`if (!input) return false` 在 essay 判断之前，用户还没写就看到「答错了」。
把 `essay → null` 提到判空之前。

### 4. `setOpen` 改受控后不接受 updater

原来写 `setOpen(prev => ...)`，改成受控包装后是普通函数，tsc 报错。
改成直接算新 Set。

### 5. 验证脚本两次误判

- 用 `innerText === '开始复习'` 全等匹配，实际按钮是「开始复习\n→」，全 FAIL
- 截图脚本漏传 `--data`，启了个空库，显示「资料 0」与冒烟测试的「资料 2」对不上
  —— 这正是交接文档里「同一屏的数字要对得上」

### 6. 测试环境没有 jsdom

`paint-marks.test.ts` 第一版要测 DOM，但项目 vitest 跑 node 环境、没装 jsdom。
为这个模块装依赖不划算，改成只测**决策层**（该不该跳过、注册名对不对、无 API 时降级），
绘制本身靠真实 Electron 截图验。

## 八、给下一个人的话

1. **「测试全绿不代表界面正确」这轮验了 5 次**（见第三节表格）。
   改界面必须 CDP 截图；改数据流必须查 IndexedDB。**量几何**也很关键
   ——「右侧空一大块」是量出 1128px vs 700px 才定位的。

2. **删功能要先查数据**。删类型不等于删数据；IndexedDB 里的字符串
   可能是 UTF-16LE，普通 grep 扫不到。

3. **同一个功能有多个入口时要全部改**。「开始复习」漏了首页那个，
   用户点了三次才发现。改完 grep 一遍确认没有残留的旧调用。

4. **验证脚本自己也会错**。这轮两次误判（全等匹配、漏传参数）。
   写长脚本用 write 落盘，别用 heredoc。

5. **CSS 冲突可能是跨目录的**。v1 的 `sources.css` 已完全孤立，
   但它的规则仍在构建产物里、仍在运行时生效。用 CDP 的
   `getMatchedStylesForNode` 能看到真正命中的规则。

6. **移动端/窄屏要自己加 media query**。错题页概览改成三栏卡片后，
   窄屏会挤 —— 补了 560px 以下的单栏规则。
