## 3. 五条必须记住的技术结论

### 3.1 Obsidian Spaced Repetition 插件的真实行为（跑过真代码，别信博客）

取证方式：下载 Release 的已发布 `main.js`（sha256 `e2af1a3477ad54bf063ee8787a465661cf6725d88394e9f2f15e78e0bc29993b`，
与 Release API digest 逐字节一致），按 `// src/xxx.ts` 分节注释切片拼成 harness，
真跑插件自己的 `parse()` / `CardFrontBackUtil.expand()`。产物在 `.tmp/sr-verify/`。

九条（1.9.0 → 1.15.4 三个版本一致）：

1. 纯 callout 里没有 `==…==` / 分隔符 → **0 张卡**。callout 内写 `> ?` 也是 0 张（多行分隔符是**整行 trim 全等**比较，`parser.ts:178`，`"> ?"` ≠ `"?"`）。
2. callout 某行含 `==…==` → **1 张 Cloze 卡**，整段 callout 合成一张，`> ` 前缀无害。
3. 一个 callout 内 N 个 `==…==` → **展开成 N 张**独立卡。
4. 裸 `??` 一行 → 自动生成反向卡（`question-type.ts:76-92`）。
5. 标签行会被**吸进卡片正面** → 标签行与第一张卡之间必须**真空行**。
6. 卡之间用 `>` 分隔 → 两张并成一张，**且后一张答案漏进前一张正面**。
7. 行内 `::` 是**子串**匹配（`std::cout 输出 :: 答案` 会把正面截断）。
8. 整行 trim 等于 `?`/`??` 就是分隔符。
9. Anki `{{c1:…}}` **不支持**，且会被 `::` 静默劈成垃圾卡。

**`> [!answer]-` 折叠是 Obsidian 原生的**（obsidian-help Callouts.md:53-65），插件不解析它，实测无害。

**本机没装这个插件**（`.obsidian/plugins/` 只有 `nutstore-sync`，`community-plugins.json` = `[]`），
所以导出的 .md 现在**只是普通笔记**——界面文案必须这么如实说，不许写成"导出即可复习"。

### 3.2 导出器的两个真 bug（都是"跑真解析器"才发现的）

- `bodies` 用 `section.join('\n')` 单换行拼卡 → **导出 5 张，插件只认 1 个 question**（整节粘连、答案互相泄露）。改 `cardBodies.join('\n\n')`。
- 一张卡内出现两个 `==…==`（正面自带挖空 + 又包答案）→ **裂成 2 张**。加 `frontHasCloze` 防护。

### 3.3 文件夹为什么不新开表 / 为什么不往 `Flashcard` 加字段

存 `settings.flashcardFolders`（照 `ResourceService` 的 `SETTINGS_KEY` + `normalize*` 模式）。三条理由：

1. 一次 `saveSettings` 天然原子；
2. 新开表要动**迁移四件套**（`STORES` / `BACKUP_STORES` / `StoreRecordMap` / `DB_VERSION`），漏一个就在写第一条记录时抛 `NotFoundError`；
3. `sanitizeSettingsForExport` 是**整体展开**的（只 delete 凭据），新字段自动进备份。

不往 `Flashcard` 加字段的理由：删文件夹要遍历全库改卡，中途失败会留半截；备份导入两表顺序不确定。

### 3.4 单卡删除与批量删除**刻意不对称**

- 单卡 `remove(id)`：**不进回收站**（闪卡是"临时记一下就删"的便签式内容），靠界面二次确认；
- 批量 `removeMany(ids)`：**进回收站**，30 天可还原（误伤面积大）。

`src/core/flashcards.ts` 头注释里写明了这个理由。**改这里之前先读那段注释。**

### 3.5 改归属时**不动 `sourceId2`**

`sourceId2` 是"这张卡原来从哪张错题/知识点抄来的"线索。跟着改会出现「标成知识点、点进去却指向一道错题」。

## 4. 验证怎么做（这是本仓库最贵的一课）

### 4.1 断言全绿 ≠ 交付。截图要真看

第二批 38 条 CDP 全绿之后，我看截图 `10-trash.png` 发现文字写「还原时一并恢复 10 条关联内容」
而删的是 11 张。查 `src/core/trash.ts:145` 确认 `attachments: entries.slice(1)` —— 1 主 + 10 关联 = 11，
**不是 bug**。但原断言只验「有没有一条 kind=闪卡 的记录」，如果 `removeMany` 只把第一张塞进回收站、
其余直接删，断言照样全绿。于是补了第 38 条：`total = 1 + attachments` 必须 `=== before`。

> **规律：「有记录」和「记录完整」是两件事。凡批量操作写一条汇总记录的地方，都要验条数。**

### 4.2 0 = 0 的假绿（第二批最贵的教训）

首跑 27/28，三条 ★ 关系断言「通过」了，实际数值是 `sel=0 groupSize=0`、`export=0 sel=0`、`assignedN=0 sel=0`。
根因：脚本用 `document.querySelector(".fcx__ghead")` 取**第一个**组头，而按文件夹分组时排最前的
是刚建的**空文件夹**（计数 0）。两边都是 0，等式成立，一条都没验到。

> **规律：关系断言必须显式断言"两边都非零"。** 现在每条 ★ 断言都带 `sel > 0 && groupSize > 0` 之类的前置。

### 4.3 改坏了却没变红 —— 先怀疑破坏方式，再怀疑断言

CDP 反向验证 B（`groupPickState` 恒 `'all'`）第一次改坏后**没红**。原因：我改的是
`if (groupIds.length >= 0) return 'all'`，但原代码后面已有 `if (hit === 0) return 'none'` 兜住了，**行为没变**。
改成 `return 'all'` 才真正变语义、才红。
D 组（回收站）同理：`document.body.textContent.includes("闪卡")` 恒为真（导航栏有「闪卡管理」），
所以"断言通过"根本没在验任何东西。改成按 `.trash-item__kind` 精确匹配 `=== "闪卡"`。

> **规律：①破坏点必须让语义真的变；②断言里别用 `body.textContent.includes` 这种全页包含匹配。**

### 4.4 破坏点必须保持 import 仍被引用

否则 `noUnusedLocals` 让 `tsc` 失败 → 打包中止 → CDP 跑的是**旧好包** → 假红/假绿。

## 5. 五个坑（会浪费你至少半小时的）

1. **`vite-node` 在本仓库会挂起**（跑 `.tmp/xxx.ts` 超 180s 无输出）。要跑临时脚本，用 vitest 驱动临时 `.test.ts`，跑完删掉。
2. **`edit` 工具 + `old_string` 带尾换行会吞掉下一行**。本会话我犯过 3 次。改完一定 `sed -n` 复核或跑 tsc。
3. **`clickByText` 是"剥数字后全等"**，打不到「导入 2 张」这种按钮（剥完还剩「张」）。用 `clickContains`。
4. **直接 `el.value = x` 不进 React state**（React 重写了 setter）。必须用原型原生 setter + 派发 `input` 事件。
5. **chip 文本是「验收2」无空格**（CSS gap 撑开）。`/\s(\d+)$/` 永远匹配不到，要 `/(\d+)$/`。
