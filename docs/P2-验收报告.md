## 三、本轮发现并修复的缺陷

### 缺陷 1：中途停止永远无效（架构级）

- **现象**：点「停止」后 `run.status` 永远是 `completed`，进度条早已 100%。
- **危害**：计划书 P2 明确要求「生成过程显示进度，可中途停止，已完成的部分保留」。
  这条完全失效，但界面看起来有停止按钮，属于「看起来能用其实没用」。
- **根因**：所有定位与落库都写在 `organize()` **返回之后**的循环里。
  用户点停止时后端已经把全部条目跑完，信号到达时无事可做。
- **修复**：把定位 + 落库 + 推进度全部移进 `onDraft` 回调，并规定
  `organize()` 必须逐条 `await onDraft()`。这样停止信号能在两条之间被观察到。
- **契约化**：这条约定写进了 `backend-types.ts` 的接口注释里，
  因为它是「实现者必须遵守」的东西，不写下来下一个人一定重犯。

### 缺陷 2：扫描件会静默生成 0 条

- **现象**：扫描件的段存在但文本为空，`generate()` 只检查 `segments.length`，
  于是顺利通过、产出 0 条、显示「完成」。
- **危害**：用户会以为功能坏了却看不出原因。计划书要求「导入失败给明确原因」，
  这里连失败都不算，是**静默的假成功**。
- **修复**：增加「有没有实质文字」检查，抛错并说明「这份资料没有文字层（扫描件），
  可以先换一份电子版，或等 P6 的看图识别功能」。

### 缺陷 3：定位器漏掉 PDF 折行场景

- **现象**：引用「线性结构与非线性结构」匹配不到原文的「线性结构\n与非线性结构」。
- **根因**：空白归一化时把 `\n` 折成空格，而引用里没有空格，仍对不上。
- **修复**：改为**剔除**空白而非折叠。中文本来不用空格分词，剔除后两边一致。
- **连带**：坐标映射要重做 —— 剔除会改变字符数，必须边扫描边记
  「归一化字符 → 原文下标」，命中后再映射回去，否则高亮会错位。

### 缺陷 4：P0 验收断言过期

- **现象**：P2 实现知识点页后，P0 的「占位页显示待接入」变红。
- **辨析**：这是**断言过期**，不是功能回归。两者都表现为红灯，但处理方式相反 ——
  前者该改断言，后者该改代码。混淆这两件事很危险。
- **修复**：改为自动查找「当前仍为 planned 的页面」来验证，而不是写死 `/knowledge`。

## 四、反向验证：证明关键断言不是空转

自己写的断言自己信不过。本轮做了这些破坏性验证：

| 破坏内容 | 期望 | 实际 |
|---|---|---|
| 所有落库移到 organize() 返回后 | 「中途停止」FAIL | 确实 FAIL（状态的 completed / stopped 不符） |
| 扫描件只检查段数 | 「扫描件报错」FAIL | 确实 FAIL（静默返回 0 条） |
| 空白折叠而非剔除 | 「跨行引用能命中」FAIL | 确实 FAIL |
| 假后端只跑 0 条 | 「定位失败不携带位置」**仍然 PASS** | 正是这个假通过促成了第二个脚本 |

最后一行是重点：**「N 项全过」这个数字本身没有意义**，
有意义的是每一项都能在功能坏掉时变红。为此专门加了 `verify-p2-unlocated.cjs`。

## 五、如实说明的限制

- **P2 阶段没有真实 AI 调用**。`MockBackend` 是唯一可用后端，
  设置页里配置的 API 后端显示为「暂不可用，P5 接入」。**不假装能调。**
- **假后端摘的是原文整句**，所以它产出的知识点质量并不代表真实模型的水平。
  它只证明「链路通、定位准」，不证明「整理得好」。
- **认知层级是猜的**（按关键词）。真实模型给的也只是建议值，
  校对界面可改，这是设计上就承认的不确定。
- **只处理单份资料**。跨资料整合未做。
- **定位取第一处命中**。同一句话在教材出现多次时，不会让用户选。

## 六、给 P3 的交接

P3 要「从知识点出题」，有几件事已经就位：

**已就位**
1. `KnowledgePoint` 带 `cognitiveLevel`（识记/理解/应用/分析），可直接映射题目难度。
2. 知识点的 `anchors` 是精确字符偏移，题目可以**继承**这个锚点 ——
   这意味着「题目的出处」不需要重新定位，直接复用知识点的位置。
3. `anchorStatus` 机制可以照搬：题目若无法确认出处，同样标 `unlocated` 等人处理。
4. `OrganizeBackend` 抽象可以直接复用，出题只是换一个 prompt。

**要注意**
1. **出题的出处应当是「知识点 → 原文」的传递，而不是让模型再说一次引用**。
   模型对同一段话的引用两次可能不一致，直接继承知识点的 anchors 更可靠。
2. **发布前逐题复校验**（计划书 P3 第 2 条）。建议校验项：
   `anchors` 非空且切片能还原、`answer` 非空、`explanation` 非空。
3. **草稿与已发布要分开**。计划书要求「先落草稿，人工检查后才发布」，
   `Deck.status` 已有 `'draft' | 'published'`，但题目层面也需要状态
   （草稿里删题不该影响已发布的题）。
