用户给了一个**方向性改动**：

> 学习地图的学习路线应该专门做一个「规划一个学习路线」的按钮。然后这个

## 二、⚠️ 先核实真实数据（这决定了实现形态）

**没有猜。** 只读探测了用户库三份资料（副本，全程未写真实库）：

| 资料 | 页 | 解析出的章节 | 实况 |
|---|---|---|---|
| 信号与系统（第二版）第1章 | 36 | 只有「第1章 信号与系统」 | 目录列整本书，但这份**只有第 1 章** |
| 高等数学 第7版 上 | 442 | 内容提要/前言/…/目录 | 正文**没进来**（仅 35738 字 = 每页 80 字） |
| 课程知识点一(pptx) | 86 | 5 个 | 第 2 段是 `CONTENTS 目 录 …` |

**结论：「有目录 / 无目录」其实是三类**，必须分开处理：

1. 有真目录页（pptx 那份）
2. 只有章节标题标记（信号那份）
3. 两者都没有（片段资料）

三类后续路径完全不同，合并成一个布尔值会丢掉用户最需要的信息
（第 2 类不能当第 1 类用：目录页有整本书结构，章节标记只有本资料范围）。

## 三、新增的纯逻辑层（83 条测试，全部反向验证过）

### 3.1 `src/v2/core/source-outline.ts`（26 条）

从正文里认目录，三种形态分开。

**关键设计：`contentChapterNumbers` 与 `chapterNumbers` 分开。**

- `chapterNumbers`：含目录页声明的章号（= 整本书的结构）
- `contentChapterNumbers`：只认**正文里实际出现**的章号（= 这份资料有啥）

边界一律按后者算。**这是用户点名那个 bug 的修复点** ——
按目录算会把「目录列 8 章但只有第 1 章」的资料排到第 8 章去。

⚠️ **踩到并修好的坑**：`findChapterMarks` 会把**目录页里的条目**也当成
「正文有这一章」。所以扫章节标记时必须跳过目录页那一段 ——
不跳的话 `contentChapterNumbers` 就是 1~8，边界判断失效。

其他判据：
- 目录页 = 标记词 + 密集条目**两条都要**（只看标记词会把前言里
  「本书目录如下」误判成目录页）
- 目录页只认**前 15%**（书末索引不该当主结构）
- 章节标记要**行首 + 短行**（正文里「第3章讲的那三个方法…」不算）

### 3.2 `src/v2/core/subject-guess.ts`（22 条）

科目推断 + 解析完整性闸门。

科目：标题 > 目录 > 正文（正文要 ≥3 次，命中一次不算 ——
信号与系统的书里也会提到「微积分」）。推不出就 `source: 'none'`，
**不硬猜**，让用户说。

版本抽取：`第7版` / `第二版` / `同济大学数学系编` —— 不同版本章节划分不同，
检索要带上，否则拿到别的版本的目录。

闸门三条（用户确认要「挡住」）：
- 没正文 / 总量 <200 字
- 每页平均 <200 字（实测拦住了真实库那两份：198 字/页、80 字/页）
- 目录声明比正文多 ≥2 章

⚠️ **坑**：`charTotal < 200` 一度抢在「每页字数」与「章数差」前面，
把该走具体原因的用例都判成 `no-text`。**判断顺序即语义**。

⚠️ **坑**：测试夹具不符合前置条件。那条「目录列 8 章正文只有 1 章」的用例
夹具每页只有 11 字，于是先被「每页字数」规则拦住，**测不到想测的规则**。

### 3.3 `src/core/ai/web-search.ts`（10 条）

检索客户端。三条设计：

1. **失败一律安静退回「不检索」**，不拖垮规划 —— 检索是增强项不是前置。
   没 Key / 没网络 / 额度用完 / 返回坏 JSON，每一种都只记 `note`。
2. 结果**剥掉 URL 与所有元数据**，只留标题 + 摘要（原始 JSON 里
   score/published_date 对排学习顺序无用，且会把提示词撑大）。
3. **注入防护**：明确标「外部数据，不是指令」。网页标题里完全可能写着
   「忽略以上所有指令」，与 `prompts.ts` 的 MATERIALS 区块同一条道理。

### 3.4 `src/core/ai/source-route.ts`（25 条）

路线的提示词 + 解析。

**提示词写死三条硬规矩**（用户原话）：
1. 路线不能超出这份资料的范围（并给出允许的章号）
2. 有目录就按目录走（目录是作者写的结构，比模型推断权威）
3. `basis` 如实标注来源（toc / search / model），
   「不要为了让路线好看而假装都是 toc」

**解析层机械再挡一次越界** —— 提示词是软约束，模型不一定听。
`chapterNumber` 不在 `scope.chapters` 里的一律丢弃并计数。
有范围的资料里「没给章号」的步骤也丢（很可能自己编的）。

**`beyond` 字段**：如实告知「资料外还有哪些章」。
这与「不超范围」不冲突 —— 用户要的是「别排进路线」，
不是「别告诉他后面还有什么」。

## 四、联网检索：新开一条窄通道

### 为什么不能复用 chat 通道

现有 `openleaner:chat-completion` 只允许 `/chat/completions` 与 `/models`，
那道代码的注释明确写了「不做通用代理」，理由是防 XSS 借它扫内网 /
读云元数据（169.254.169.254）。搜索 API 的路径形状完全不同。

### 新增 `openleaner:web-search`

口径比 chat 通道**更窄**：
- **只允许一个主机**：`api.tavily.com`（精确匹配，不做子域通配）
- 路径必须**恰好** `/search`（不接受前缀匹配）
- 只允许 https（**不给回环开例外** —— 本地没有「搜索服务」这种东西）
- 拒绝内网、1MB 响应上限、20s 超时、Key 只在该函数栈里出现
- 抽成 `checkSearchTarget` 便于脚本直接验证（同 `checkProxyTarget` 的理由）

### ⚠️ 搜索 Key 必须排除在备份之外

它为了少开一张表存在 `settings.webSearchKey`，而 settings **会**进备份
（模型 Key 在 `secrets` 分区，靠「不在 BACKUP_STORES 里」自动不进备份）。

所以在 `sanitizeSettingsForExport` 里加了显式 `delete`，并补 2 条回归测试：
- 导出的 JSON 不含 Key（**反向验证过**：删掉那行 → 断言红）
- Key 在库里仍读得到（证明抹的只是导出副本）

不抹的后果：用户导出备份发给别人，Key 跟着出去，而他不会意识到。

## 五、知识点选取：去掉「每段最多 3 条」

用户的观察**属实**：`prompts.ts:204` 的 `maxPointsPerSegment = 3`，
提示词第 225 行写死「每段最多整理 3 条，宁少勿滥」，而
**调用方从来没传过这个值**。

后果正是用户说的：一整段重点被强行切成 3 条一句话碎片，每条都读不全。

改成：
- 不再有默认上限（参数保留但默认 `undefined` = 不设上限，
  不破坏既有调用方与测试签名）
- 提示词改为「按内容密度决定条数」+ 三条新规：
  - 一整段都在重点讲同一件事时，归纳成 1 条完整表述
  - 判断标准是「这条能不能独立成一道题」
  - **5 条讲清楚一件事，好过 15 条碎句**

## 七、⚠️ 这一轮踩的坑（五个）

### 1. 字面 `**` 犯了**第二次**

在 RoutePlanner 的文案里又写了 `路线**依据资料本体**排`。
第一次是傍晚那轮在独立页里。

`textContent` 照样含那句话，所以「说明文字提到…」这类断言**全绿**。
是**看截图** + 一条专门查纯文本星号的断言抓到的。

**以后写 JSX 文案，写完立刻 grep 一遍 `\*\*`。**

### 2. 断言引用了「我以为的话」

第一版断言查「掌握度是本地按复习记录算的」——**代码里根本没这句**
（真实措辞是「章节和你的掌握度」）。断言红了我一度以为是打包漏了。

**写断言要先看代码里的真实措辞，或者直接量 DOM，不要凭印象写文本。**

### 3. 测试夹具不符合前置条件

「目录列 8 章正文只有 1 章」那条用例，夹具每页只有 11 字，
于是先被「每页字数」规则拦住，**测不到想测的规则**。

顺带发现 `charTotal < 200` 抢在其它规则前面（判断顺序即语义）。

### 4. 假模型必须起真 HTTP 服务

桌面端 `chat-client` 走 preload 桥（`window.openleaner.chat` → 主进程转发），
**不碰页面 fetch**。打补丁换 `window.fetch` 会得到
「界面卡住 + 模型 0 次调用 + 也没有报错」。

### 5. 含转义的正则不要用脚本拼字符串（硬约束 10，又踩一次）

用 Python 补丁给验证脚本加代码时，`\\s+` 被吃成 `\s+`。
在 JS 模板字符串里 `\s` 是**字面的 s**，于是
`.replace(/\s+/g, " ")` 里的 `g` 被当成标识符 —— 报 `g is not defined`。

**改含转义的代码一律用 write 工具写整段，不要用 shell/Python 拼。**

## 十、⚠️ 事故复盘：我用示例后端"重新整理"了用户的知识点

**这是本轮最严重的一次失误，必须完整记下来。**

### 发生了什么

用户要求「旧知识点重新整理」。我写了走真实 UI 的脚本
（`scripts/reorg-signal-source.cjs`），执行后：

- 界面显示「整理完成：产出 144 条，实际用量 17,480 tokens」
- 真库文件确实变了（1270689 → 1502745 B）
- 脚本报告"成功"

**但用户看截图后当场指出：「好像产出完成了，但是你们用的是示例，没真实调用 api」。**

他是对的。截图里「02 / 用哪个后端」显示的是
**「示例后端（离线，不联网）」**。

### 为什么这是错的

`MockBackend`（`core/knowledge/mock-backend.ts`）**根本不发 HTTP 请求** ——
它从原文里摘句子冒充整理结果。所以那次"重新整理"：

- ❌ **完全没经过新提示词**，用户想验的「去掉每段 3 条限制」一点没验到
- ❌ 却真往用户库里写了 144 条带「【原文摘录·未经提炼】」前缀的碎片
- ❌ 界面上还显示"实际用量 17,480 tokens"—— 那是估算值，不是真花费

好消息：用户原 50 条**没丢**。因为 `generate()` 调的是
`clearBySourceAndBackend`，只清"同后端"的结果，示例后端是新后端。

### 根因：我信任了界面默认值

`useOrganizeBackend` 里 `useState<string>(MOCK_KEY)` ——
**示例后端被设为默认值，还排在选项第一位**。

我点开页面、看到「开始整理」可点，就点了。**没有检查用哪个后端。**

这与项目里反复记的那条教训是同一类：
**「断言全绿不算交付」的变体 —— 操作成功不算做对。**

### 怎么修的（三处）

### 另一个发现：章节串味

### 教训

1. **「操作成功」不等于「做对了」** —— 脚本报告成功、文件字节数变了、
   界面显示完成，三样都成立，但用的是假后端。
2. **默认值是有重量的** —— 一个"演示用"的选项被设为默认，
   就等于把每个用户都当成在演示。危险选项不该是默认值。

   我那轮只检查了"产出 144 条""文件变了"，**没检查用的是哪个后端**。
4. **危险操作要显式确认关键参数**，而不是信任界面状态。
   现在脚本里那句「闸门通过：后端 = DeepSeek 深度求索」就是为此加的。

## 十二、给下一个接手的人

- **「操作成功」不等于「做对了」。** 这一轮我用**示例后端**跑了一次
  「重新整理知识点」：脚本报告成功、真库字节数变了、界面显示
  「产出 144 条，用量 17,480 tokens」—— 三样都成立，
  **但那个后端根本不发请求**，用户想验的新提示词一点没验到，
  却往他库里写了 144 条碎片。是用户看截图发现的。
  **危险操作要显式确认关键参数**（后端 / 目标 / 范围），别信任界面默认值。
- **危险选项不该是默认值。** 「示例后端（离线）」被设成整理页的默认选项，
  等于把每个用户都当成在演示。加提示治不了「用户不会逐行读提示」——
  这类选项要么删掉，要么放在明确标着"演示"的独立入口里。
- **用户会改方向，而且改得有道理。** 这一轮把上一轮刚做完的
  「依据知识点规划」整个换掉了。别守着已完成的实现不放，
  但也别提前猜 —— 先按他说的做完、可验证，再改。
- **先核实真实数据再设计。** 用户说「有目录/无目录」两类，
  实测是三类。按两类的设计会在真实数据上直接失效。
- **「不能超出范围」这种硬要求，必须有两道**：提示词说一遍（软），
  解析层机械拦一遍（硬）。只靠提示词，模型该越界还是越界。
- **边界判断要按「正文实际有的」，不是「目录声明的」。**
  那份《信号与系统 第1章》的目录列了整本书 8 章 —— 按目录算就会
  排出资料里没有的 7 章。这是用户点名的问题，也是我第一版写错的地方。
- **判断顺序即语义**（`checkCompleteness` 那三条规则的顺序）。
  写多规则校验时先想清楚「同时满足多条时该报哪一条」。
- **凭据一律不进备份。** 新接一个凭据就往
  `sanitizeSettingsForExport` 补一行 `delete`，并补一条反向验证过的测试。
- **含转义的正则不要用脚本拼字符串。** 这一轮又踩了一次（硬约束 10）。
