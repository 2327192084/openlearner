### 文件分工

| 文件 | 职责 |
|---|---|
| `src/core/ai/plan-order.ts` | 提示词 + 解析校验（**纯逻辑**，40 条测试） |
| `src/core/ai/chapter-backfill.ts` | 补章节的提示词 + 解析 + 预览（30 条测试） |
| `src/v2/core/plan-inputs.ts` | 数据装配：知识点 + 复习记录 → 排序输入 |
| `src/v2/core/study-plan-store.ts` | 路线的规范化与进度计算（20 条测试） |
| `src/v2/ui/RouteMap.tsx` | 横板爬塔组件 |
| `src/v2/ui/RoutePreviewDialog.tsx` | 「勾完才存」的确认对话框 |
| `src/v2/ui/route-map.css` | 横板样式 |
| `src/v2/ui/route-preview.css` | 补章节 + 对话框样式 |
| `src/v2/ui/MapPage.tsx` | 承接整合（新增 route prop + RouteStarter） |

### 横板为什么这么画

- **横板而不是竖版**：学习路线是**一条有先后的一维路径**。竖版跟上面的章节表
  抢垂直空间，读「第几步」时视线要上下跳。横板左→右正好对应「往前走」。
- **`overflow-x: auto` 而不是压缩节点**：用户库 105 条知识点，压缩会挤成竖线。
  路线长就横着滚，节点保持 132px 可读宽度（与「地图比屏幕宽」的隐喻一致）。
- **三种状态视觉分明**：已走过（绿边 + 压暗）/ 当前（accent 边框 + 「你在这里」徽标）/
  未到达（opacity .72）。
- **借了杀戮尖塔什么、没借什么**：
  借「节点是路径上的关卡」「走没走过一眼看出」「当前高亮」；
  **没借**随机生成（我们的路径是 AI 排的、有理由）、战斗/血量/卡牌
  （学习不需要假装成游戏）。

### 数据流

```
用户点「让 AI 排一条学习路线」
  → App.studyPlanOrder（读后端凭据 + 发请求）
  → buildPlanPrompt（105 条压成紧凑清单，实测 7410 字符）
  → parsePlanOrder（整轮拒绝残缺 / 单条丢弃越界 / 难度非法置 null）
  → App.planDraft（**不落库**）
  → RoutePreviewDialog（按块分组、默认全勾、每块可整块切换）
  → 用户确认 → planToSteps → settings.studyPlan
  → MapPage 横板渲染
```

### 三个已确认的设计（用户 2026-11-21 拍板）

| 问题 | 用户选择 |
|---|---|
| ① 逐条排还是先归块 | **先归成 5–8 块，块内再排** |
| ② 章节缺失要不要先补 | **先调 AI 补上章节，再排序** |
| ③ 要不要确认后生效 | **AI 给、我勾，勾完才存** |

`suggestBlockRange()` 按条数给不同块数（<6 → 2–3 块，<20 → 3–5，否则 5–8）——
知识点只有 4 条时逼模型分 5 块，它只能拆条或编块名。

## 三、与 LogiNote / StudyHub 的差异（调研结论已落实）

子代理这一轮拉到了 **LogiNote 完整源码树**（22.7MB tar.gz）和 StudyHub 关键文件，
拿到几条**校正上一轮结论**的事实。落实进代码的是这些：

### 3.1 理由字段必须留（与 LogiNote 刻意相反）

LogiNote 的规划提示词 JSON schema 里**没有 reason 字段**，它把理由外置到
「个性化决策」的 `instruction + （依据：reason）`。我们两样都留：`reason` + `basis`。

**理由**：交接文档 9.3 的判断成立 —— 用户看不懂为什么这么排，就不会照做。
**理由就是产品价值。**

### 3.2 难度由模型给、掌握度由本地算（LogiNote 只是「防过」）

LogiNote 找到三处原句（子代理在 `planPersonalization.ts:204` / `planCoreScope.ts:6` /
`reviewPrompt.ts:8`）：
> 在"…"相关任务开始前安排简短诊断，**不把已有笔记等同于已经掌握**。
> **未知掌握情况不能假定已经掌握。**

我们的做法比它更强：**两个字段物理分开**。
`PlanPointInput` 里 `mastery` / `wrongCount` / `daysSinceReview` 全部本地算，
模型只读；`difficulty` 模型给。提示词写死：

> 难度由你判断，掌握度不是你的事
> 学生没练过的点，可能其实很容易；练得很熟的点，也可能是全书最难的。

### 3.3 残缺 JSON 整轮拒绝（照 LogiNote）

`planGenerationResponse.ts` 的文件头注释就是策略声明：
> Never repair missing brackets, extract a partial child, or choose among two values.

它的解析器还明确拒绝「找到第二个完整 JSON 值」（`if (++count > 1) return undefined`）。
我们的 `extractCompleteJsonObject` 也自己扫括号深度（跳过字符串内部），深度没归零直接失败。

**⚠️ 重要校正**：子代理实测发现这条**不是 LogiNote 全仓库铁律** ——
`NoteEditor.tsx:468-477` 的学习任务提取**会主动补闭合括号**。
所以引用这条时要说「plan-generation 主流程」，别当通用约束。

### 3.4 一条**没**采纳但值得知道的机制

StudyHub 的 `basis` 自证核验（`tree.js:71-78`）：模型声明排序依据后，
服务端用库里**实际有无**的 syllabus / 编号 / 日期去剔除虚假依据
（「模型声称按 syllabus 排，但库里根本没 syllabus → 该依据被删掉」）。

这个思路很好（理由可核验、不耗输出 token），但我们的 `basis` 是自由文本、
没法机器核验。**如果以后要做「理由可信度」，这是现成的方向。**

## 四、⚠️ 这一轮踩的坑（五个，都写进了断言）

### 1. CSS 写了但从未 import —— 横板渲染成一堆小方块

`route-map.css` 我写完、`check:css-vars` 也过了（那个脚本只查变量有没有定义，
**不查文件有没有被引用**），但**从来没 import**。

现象：横板渲染成三个 `inline-block` 小方块堆在左上角。
而「有横板」「节点 x 递增」两条断言**全绿** —— 因为节点的 x 确实递增
（只是堆在垂直方向上挤成一列根本看不出）。

诊断方式：量 computed style，`trackDisplay` 是 `block` 而不是 `flex`、
`nodeWidths` 是 260/224/137px 而不是我写的 132px。

**教训**：`check:css-vars` 通过 ≠ CSS 生效。查 `.css` 有没有被 import，
或直接 `grep -c "类名前缀" dist/assets/*.css`。

### 2. 断言写得够宽 = 没在验（又一次）

「你在这里」徽标不能压住节点文字 —— 第一版判据是 `overlap <= 0`（不重叠）。
反向验证：把节点加高去掉，间隙从 11px 变成 **3px**，还是「不重叠」，**断言照样绿**。
但截图看 3px 时徽标几乎贴在文字下沿，糊成一团。

改成要求 **≥8px 呼吸空间**，反向验证才红。

### 3. 假模型打补丁完全无效（桌面端走 preload 桥）

第一版验证脚本想用 `window.fetch = ...` 拦截请求。**一次都没被调用**。

根因：`chat-client.ts` 用的是 `resolveChatFetch(readChatBridge())` ——
桌面端走 preload 暴露的 `window.openleaner.chat`（主进程转发），
**根本不碰页面的 fetch**。

现象很有迷惑性：点了按钮、界面卡在「正在让 AI 排…」、假模型 0 次调用、
**也没有任何报错**（主进程真的去连了不存在的地址，超时前一直挂着）。

正确做法（照 `verify-mastery-evidence-ui.cjs`）：**起本地 HTTP 假模型**，
把 `backends` 指向它。这样走完整生产链路，只换模型那一端。

### 4. CDP 密集轮询会把自己压超时

地图页一屏 105 条知识点的章节树 + 横板，主线程本来就紧。
原来每 300ms 一次 `Runtime.evaluate`，把 CDP 队列压满 → **CDP 自己超时**，
而功能其实早就好了。

改成「睡 1.2 秒查一次」。同类问题在别处也可能出现：**页面越重，轮询要越稀**。

### 5. 界面文案里的字面 `**`

JSX 里写 `所以结果**先给你看、你勾了才存**` —— 那两个星号**原样显示**给用户。

`textContent` 里照样含「勾了才存」，所以「说明文字提到勾了才存」这条断言**绿**。
是**看截图**才发现的（交接文档记过五次同类）。

现在专门有一条断言查页面纯文本里的 `**` 数量 == 0。

### teammate 靠截图抓到两个断言抓不到的问题

**① 一行里三处说同一件事**：`[今天] [考期] 今天 · 2026-11-21`。
改成纯文字小标；徽标已说「今天」，右侧截止日不再重复前缀 ——
但**前缀只对考期行去掉**，普通待办今天到期仍保留（另加回归断言守住）。

**② 首页倒计时行对比度不合格，而 `check-contrast.cjs` 抓不到。**
那一行画在**米黄纸张卡**上（`.paper` #ece4d6），而 accent 系列是照深色画布调的：
`--accent-text` 在纸上只有 **2.47:1**。
工具抓不到是因为它跑的时候首页没有考期，**这一行根本不渲染**。
改成 `color-mix(in srgb, var(--accent) 75%, var(--paper-ink))` → 实测 5.57:1。

**这个模式值得记**：「检查工具在元素不存在时静默通过」
（空数组也满足「不达标数 == 0」）。teammate 现在两条对比度断言都强制要求
「量到的条数 ≥ N」并逐条打印实测 ratio。

## 六、⚠️ 顺带修掉一个既有 bug：恢复备份会丢 settings 字段

### 结论（用实验证实，不是读代码猜）

`importBackup` 恢复 settings 是**逐字段白名单**（locale / questionLanguage /
onboarded / gradingRules）。白名单外的字段**恢复备份后静默丢失**。

实测（导出→导入往返）：
```
homeWidgets        → undefined   （应为 [{id:'w_1',...}]）
dailyQuoteEndpoint → undefined   （应为 'https://example.com/quote'）
```
而备份文件里**确实有**这两个字段（`JSON.stringify(backup)` 搜得到内容）。

### 讽刺的地方

那段代码**下面的注释早就写对了结论**：
> 这里原来是「逐字段白名单」，漏一个新字段的后果是：用户恢复备份后
> 自定义评分悄悄退回默认，而备份文件里明明存着 ——
> 属于「数据在、但没生效」的那类最难发现的问题。

结论对，但当时只补了 `gradingRules` 一个字段、**白名单本身没拆掉**。
后来加的 `homeWidgets` / `dailyQuoteEndpoint` 又掉进同一个坑。

### 修法

`DEFAULT_SETTINGS` 打底 + **整体展开**备份的 settings + 关键字段归一化，
展开前先 `sanitizeSettingsForExport`（旧备份里的凭据字段不会被带回来）。

4 条回归测试，**反向验证做过**（退回白名单 → 2 条红）。

### 为什么这一轮必须修

「学习路线」存在 `settings.studyPlan`。不修这个 bug，用户换机器恢复备份后
**路线会静默消失**。详见 `docs/修复-恢复备份丢settings字段.md`。

## 十、给下一个接手的人

- **用户会改方向，而且改得对。** 我做了完整的独立页面（45/45 验证），
  用户一句话就推翻成「整合进地图 + 横板爬塔」。别守着已完成的实现不放 ——
  但也别提前猜他会改：先按他说的做完、可验证，再改。
- **`check:css-vars` 通过 ≠ CSS 生效。** 它只查变量有没有定义，
  不查文件有没有被 import。这一轮横板渲染成方块就是因为这个。
- **「不重叠」不等于「看得清」。** 间隙 3px 时断言绿、截图糊。
  写视觉断言时先问：这个数值下**看起来**是对的吗？
- **桌面端的 AI 请求不经过页面 fetch。** 走 preload 桥（`window.openleaner.chat`）。
  想假造模型就起真 HTTP 服务 —— 打补丁换 fetch 会得到「界面卡住 + 0 调用 + 无报错」。
- **页面越重，CDP 轮询要越稀。** 105 条知识点的页面每 300ms evaluate 一次会把队列压满。
- **`electron:pack` 会「又」生成 52M 的 `openleaner-data`。** 打包前清一次、
  打包后**必须再清一次**，然后才替换三件套。否则安装目录里多一个 52M 历史目录，
  而 `ensureUserDataDir` 第 4 候选会优先选它（11-13 那次「已删除但是假的」根因）。
- **验桌面版不能只 grep asar 里的源码文件名。** 硬约束 5 记过：asar 里装的是
  dist 产物，按 `.ts` 文件名 grep 永远是 0，对「有」和「没有」都返回 0。
  这一轮的做法是：解出 asar 里最大的那个 `index-*.js`（用 `ls -S` 找，不是
  `ls | head -1` —— 我第一次就挑错了 24KB 那个次要 chunk），再 `grep -F` 特征串；
  真正的交付判据还是**启动安装版走真实 UI 截图**。
- **断言别引「我以为的话」。** 这轮写验证时凭印象断言页面上有
  「掌握度是本地按复习记录算的」，而代码里根本没这句 —— 断言红了我还以为是
  打包漏了。写断言要**先看代码里的真实措辞**，或者直接量 DOM 而不是猜文本。
- **`file://` 下 `fetch('./package.json')` 会被 CORS 拦。** 想验 asar 完整性，
  用「React 挂载 + 导航渲染 + preload 桥在」这类页面内证据，别 fetch 本地文件。
- **共享文件要双向确认。** 这一轮我和 teammate 同时改 `src/core/model.ts`
  （他加 `Todo.isExam`、我加 `AppSettings.studyPlan`），相距 250 行没冲突，
  但两边都 `git diff` 对过一遍才敢提交。
