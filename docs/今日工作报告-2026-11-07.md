### 1. 删除按钮找不到 —— 是旧包，不是 bug

用户报告「上一个模型做的删除资料按钮我没找到」。

**排查结论**：桌面快捷方式 `OpenLeaner.lnk` 指向 `E:\openleaner\release\win-unpacked\`，
而删除按钮是 22:03 才提交的（`384746d`），那个包是 19:14 构建的旧版本。

**实证**（不是猜）：

| 检查项 | 快捷方式启动的包 | 工作区最新 dist |
|---|---|---|
| 包内 JS | `index-Vi-jKbpI.js` | `index-CKknWSgz.js` |
| `source-item__delete` | **0 次** | 1 次 |
| 资料行结构 | 只有 `source-row` 一个按钮 | 两个兄弟按钮 |

顺带发现一个更要紧的问题：那个包用的是**独立的空库**
（`release/win-unpacked/openleaner-data/`，3.8MB，只有一条后端配置），
用户真正的 92MB 资料库在桌面包目录里。原因是 `electron/main.cjs`
的 userData 查找顺序：`%APPDATA%\OpenLeaner` 存在且可写时优先于安装目录旁的
`openleaner-data`，两个包各自只认自己目录旁的数据。

**处理**：按用户选定的方案 A，把新构建同步进桌面那个包（用交接文档的离线
手工组装，不跑 electron-builder）。两处 asar 一致，验证 10/10 + 28/28。

### 3. 阅读器：让「可点回原文」真的能点

**为什么必须做**：知识点上写着「可点回原文 · 第 N 页」，但**点不动**。
`anchors` 里存着 `{sourceId, page, charStart, charEnd}`，全库却没有任何
一处拿它去定位正文 —— 等于对用户撒了个谎，比不写这个徽章更糟。

**新增 `src/v2/ui/ReaderPage.tsx`**：

- 只认**页内偏移**（相对 `SourceSegment.text`），不用全文偏移
- 定位三级降级，且如实告诉用户是哪一级：
  `offset 直接命中` / `靠引文搜回来` / `只找到页码`
- 找不到就明说，仍显示那一页正文，**不硬套一个假位置**
- 高亮用 `<mark>`，语义化且不改变文本（复制出来还是原文）
- 无 anchors 时退化成纯阅读器：可翻段、可在本资料内搜索
- 扫描件说「没有文字层，不是文件坏了」，不推卸给用户

**配套**：资料行点击改成打开原文；「整理」提成独立按钮；知识点的
「可点回原文」变成可点按钮，点了带 anchor 跳阅读器。

**验证 `verify-v2-reader.cjs` → 25/25**：
用 `large-50p.pdf`（真 50 页 / 50 段）测跨页定位，逐字符校验
高亮内容 === 原文切片。**对部署后的桌面包内 dist 复跑一遍**。

**截图复核修掉两个真问题**：
1. 章节标题与正文首行重复（解析器把每页第一行当 chapter，正文又以它开头）
2. 高亮 25% 透明在深色底上几乎看不见 → 提到 45% + 下划线 + 外扩描边

### 4. 扫描件 OCR：接入本机 MinerU

**调研阶段**（用户拍板前的依据，全部带来源链接）：

| 引擎 | 代码许可 | Windows 原生 | OCR 引擎 | 结论 |
|---|---|---|---|---|
| Docling | MIT | ✅ | RapidOCR | 备选 |
| **MinerU** | Apache-2.0 + 附加条款 | ⚠️ | 自带模型 | **用户选定** |
| OCRmyPDF | MPL-2.0 | ✅ | **只有 Tesseract** | **建议去掉** |
| Marker | Apache-2.0 / 限商用权重 | ⚠️ | Surya VLM | 权重限制商用 |

**关键发现**：OCRmyPDF 的 `--ocr-engine` 只接受 `tesseract` 或 `none` ——
它内部就是 tesseract，用户否决 tesseract 的理由对它原样成立，
**选它等于没换引擎**。据此建议去掉，用户采纳。

**实现**：

```
src/core/mineru/
  convert.ts      middle_json → 按页正文（纯函数，18 条单测）
  runner.ts       环境适配：桌面走 IPC / 浏览器如实说用不了
  write-back.ts   转成 segments 写回 sourceSegments
electron/mineru.cjs   探测 + 校验 + spawn + 进度解析（纯 Node 可单测）
electron/main.cjs     新增 IPC + 原文件路径登记
src/v2/ui/ConvertPanel.tsx  整理页的转换入口
```

**三条不能让步的设计**：

1. **页码严格 1:1**。`page_idx` 从 0 开始要 +1；空页保留占位，
   **绝不跳过** —— 跳过会让后面所有页错位一格，用户拿「第 12 页」
   去看原书第 12 页会发现对不上。
2. **表格/公式块不进纯文本**。MinerU 给的是 HTML，塞进去会让全文搜索
   和字符锚点一起失效。测试钉住了这条（第一版实现确实漏了，测试抓到）。
3. **不可用就明说**。浏览器里跑不了就不摆按钮，直接说「这个功能需要桌面版」。

## 三、踩到并修掉的坑（留给下一个模型）

| 坑 | 现象 | 原因 |
|---|---|---|
| **MINERU_HOME 不传** | `[WinError 5] 拒绝访问 …models\.locks\…lock` | mineru-kit 退回 `~/.mineru`，那里可能空或不可写。**看起来像 PDF 坏了**，实际是模型目录用错。现从 exePath 推导 `<root>/home` 并显式传入 |
| `app.getPath('temp')` 建目录 | `EPERM: operation not permitted, mkdir` | 受管机器对系统 Temp 有额外限制。改用 `userData/mineru-jobs`（启动时已验证可写） |
| `mineru` vs `mineru-kit` | `mineru parse` 报「Local mineru server is not running」 | 前者需常驻 server，后者纯 CLI。用 `mineru-kit` |
| tqdm 进度单位 | 正则匹配不到下载进度 | 单位是 `418M` 不是 `418MB`，B 必须可选 |
| `mineru-kit` 默认 tier = standard | 首次偷偷下载 1.2GB VLM 权重 | standard = 小模型 + VLM。basic 只用 ONNX（819MB），但**空格断词不如 standard 准** |
| PDF 章节标题重复 | 渲染两次 | 解析器把每页第一行当 chapter，正文又以它开头 |
