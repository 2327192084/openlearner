## 一、最重要的三件事

### 1. MinerU 图片 locator 会失效（本轮验成了事实）

上一份交接文档留了一个没验的风险。本轮用对照实验查清了：

1. 复制 MinerU home 到 `.tmp` 副本（遇到 ACL 保护，`icacls` 收紧后才起得来）
2. 基线：取 `page:1/block:7` → 成功，7117 字节，416×216 电路图
3. **删掉副本里的 `doclib/parsed/87`**（该文档解析缓存），原 PDF 仍在
4. 重启服务再读同一 locator → `Error: Requested parsed content is not cached.`

源码佐证：`mineru/doclib/services/content_read_svc.py` 的 `_render_image_response`
先找页、取不到抛 `page_not_cached`；`_render_source_image_asset` 还要靠原文件路径按 bbox 裁图。

**结论：必须在转换时立刻取图，不能留到用户点开时。**

### 2. 上一份文档第七节说错了一处

它说「图片 locator 被当普通文本存在 `sourceSegments.text` 里，阅读器会渲染成坏链接」。
**查真实库后确认这是错的**：`markdown.ts` 有一条正则把图片行整行丢掉，
`sourceSegments.text` 里 0 个 `![`、0 个 `doc:`。

所以 B 的第一步不是「抽出来」，而是「现在根本没存，要新加提取」。

### 3. 我学会了看视频（别再误判「看不了」）

用户给 B 站链接时，我最初说「看不了」——**那是错的**。两条路都不需要下载整个视频：

```js
// 元数据
https://api.bilibili.com/x/web-interface/view?bvid=<BV号>
// → data.duration / aid / cid

// 快照雪碧图（10×10 网格，一帧 480×270，覆盖全片）
https://api.bilibili.com/x/player/videoshot?aid=<aid>&cid=<cid>&index=1
// → data.image[0]（一张 4800×2700 的 jpg），PIL 切 100 帧
```

163 KB、几秒拿到 100 帧，逐个 `read_image` 看即可。
备选：`yt-dlp` + `ffmpeg` 抽关键帧（[claude-video](https://github.com/bradautomates/claude-video) 的做法）。
**纯画面无语音的录屏最适合这条路**，转写音频毫无意义。

### 关键实现要点

**图片不入 `seg.text`**（这条最重要）：知识点靠 `charStart/charEnd` 字符偏移定位，
库里 95 个已按当前 text 算好。插一个字符就整体平移，高亮集体错位且**难以察觉**。
所以 text 字节不动，图片单独存 `sourceImages`，用 `charOffset` 记位置，渲染时插回。

**回收站不用软删除**：软删除要求每个读取路径都加 `if (!deleted)`，漏一处就静默复活数据。
项目里已有「`answerRecords` 分区是空的却一直留着」这种遗留。

**大二进制不进回收站**（原始 PDF、插图）：几十 MB 且都能重新生成，
但如实记进 `skipped`，列表里明说「还原后需要重新导入」。

**出题现在写 `generationRuns`**：原来不写，导致任务页拿不到 token
（真实数据里 11-08 那组花了 51861 token，记在 `usageRecords` 但关联不上）。

### 2. CSS 层级陷阱（已踩六次以上）

`base.css` 有**不在任何 `@layer` 内**的 `button { font: inherit; color: inherit }`
与 `input/select/textarea` 同名规则。级联「层级先于特异性」。

> **原生控件（button/input/select/textarea）的样式一律写层外，一条都不能留层内。**
> 包括 `appearance: none`。

本轮新增了 `trash-page.css` / `practice-queue.css` / `maimemo-*.css` /
`home-widgets-editor.css`，里面的原生控件全在层外。

### 3. fetch 不能丢了 this（本轮踩的新坑）

```js
// ❌ 错：this 变成类实例，浏览器抛 Illegal invocation
this.fetchImpl = fetch;
await this.fetchImpl(url, opts);

// ✅ 对
this.fetchImpl = (url, init) => globalThis.fetch(url, init);
```

**这个 bug 单测抓不到**——测试注入的假 fetch 是普通函数，不挑 `this`。
要用「严格模式下的普通函数」当替身才测得出（见 `maimemo.test.ts` 最后一条）。

### 4. `GeneratePage.tsx` / `SettingsPage.tsx` 已经很大

- `GeneratePage.tsx`：CRLF/LF 混用，按行号批量替换会错位
- `SettingsPage.tsx`：1400+ 行

**新增 UI 一律独立文件，宿主里只插一行引用。** 本轮三个新面板都是这么做的。

### 5. 改界面必须截图，改数据流必须查 IndexedDB

本轮 **6 个问题是看截图才发现的**（测试全绿）：

- 熟练度百分比用错了分母（答对 1 题却没百分比）

### 6. 验证脚本自己也会错

本轮被 `shell heredoc → node -e → JS 模板字符串` 三层转义吃掉反斜杠**三次**，

## 五、已知问题（接手后优先看）

### 1. 墨墨生词本「导入成功」这条链路没验通过

`395fc6f` 修掉了 `fetch` 的 `Illegal invocation`（那是真 bug，用户报的），
但**没有真 token**，所以「读取词本 → 导入词条」成功的那一步没跑过。

已知事实（实测）：
- 基地址 `https://open.maimemo.com/open/api/v1/` 可用
- 不带 token 返回 **401** + `{"errors":[{"code":"common_unauthorized",...}],"success":false}`
- 导入是**整段替换 content**，不是追加（社区实现 EudicSyncToMaiMemo 可参考）

**接手后要做的**：拿真 token 跑通一次，确认 `notepads/{id}` 的 body 形状对不对。
如果不对，改 `maimemo.ts` 的 `importWords`。

### 2. 划词浮层没在真实内容上验过

用户资料全是中文（信号与系统），没有英文可划。
`extractWords` 有 12 个单测，但「界面上真的浮出来了」没看到。
**要验的话先导入一份英文资料。**

### 3. 墨墨 token 存在 `settings` 里，靠导出时剔除

`library.ts` 的 `sanitizeSettingsForExport` 会删掉它，有 5 个测试
（其中一个端到端，回退验证过会红）。

**但这不是最稳的做法**。注释里写了：以后接更多第三方凭据应统一挪进
`secrets` 分区，一次迁移解决，而不是一个字段一个字段补剔除逻辑。

### 4. 每日一句联网默认关闭

`settings.dailyQuoteEndpoint` 为空 → 纯本地。要启用就填一个返回 JSON 的地址。

## 六、调研过的三个方向（结论写下来，避免下一个人重查）

34 个接口（云词本 / 词汇查询 / 学习数据 / 记忆卡）。频率限制 20 次/10 秒。

落地为 `pages.ts` 里知识骨架的 `purpose` 措辞（功能一个字节没动）。

DSH **Web GUI** 的主题插件，我们是独立 Electron 应用，没有它的插件系统。

顺带确认：我们只有深浅两套主题（`tokens.css`）。
加主题要重验每个配色的 WCAG AA 对比度，不是复制粘贴，暂不做。
